# 달의 위상 — NOTES

## (a) 답하는 질문

"햇빛은 언제나 달의 절반을 비추는데, 왜 우리 눈에는 가는 초승달부터 둥근 보름달까지 모양이 바뀌어 보이는가?"
글을 읽다 흔히 "지구 그림자가 가려서"라고 오해하며 멈추는 곳이다.

동사: **지구를 향한 반쪽이 돌아가며, 햇빛 받는 반쪽과의 겹침이 달라진다.**

## (b) 동사를 화면에서 일어나게 한 방법

- 왼쪽 칸(북쪽 위에서 내려다본 지구와 달): 달의 밝은 반쪽은 궤도 어디서든 늘 오른쪽(태양 쪽)이다.
  반면 강조색 호(지구를 향한 반쪽)는 달이 돌면서 함께 돌아간다. 호 안쪽에 밝은 부분이 얼마나 들어오는지가
  "겹침"이며, 이것이 자동 진행으로 0 → 절반 → 전부 → 절반 → 0 으로 바뀐다.
- 오른쪽 칸(지구에서 올려다본 달): 같은 순간 지구를 향한 반구를 화소마다 계산해(표면 법선과 태양 방향의 내적)
  원판에 그린다. 원판을 두른 강조색 원이 왼쪽 칸 강조색 호와 같은 대상이라, "호 안에 든 밝은 부분" 이 곧
  "원판에 보이는 밝은 모양" 임이 두 칸에서 동시에 일어난다.
- 궤도 위 반투명 달 여덟 개가 모두 오른쪽이 밝아, "햇빛 받는 반쪽은 그대로" 를 멈춘 그림으로 받쳐 준다.

## (c) 화면 구성 결정

- **두 칸**: 겹침은 위에서 봐야 보이고, 모양은 지구에서 봐야 보인다. 둘 중 하나만으로는 주장이 닫히지 않는다.
  칸 이름 두 줄은 시점이 다르다는 것을 알려야 하므로 두었다.
- **강조색(주황)은 "지구를 향한 반쪽" 한 가지 뜻에만** 쓴다. 두 칸의 강조색이 같은 대상이다.
  햇빛 받는 표면은 두 칸 모두 같은 밝은 색, 그늘 표면은 같은 어두운 색.
- **햇빛은 흐르는 평행 줄무늬 장**으로 그렸다. 화살표 하나보다 "모든 곳에 같은 방향으로 온다" 가 드러난다.
  방향 문구 하나는 태양이 화면 밖에 있어 필요했다.
- **캡션**: 앞문장은 고정, 뒷문장만 밝은 면적 비율 (1 − cos θ)/2 로 세 경우 중 고른다 (0.03 미만 / 0.97 초과 / 그 사이).
  "커지는 중/줄어드는 중" 은 끌기로 거꾸로 돌리면 어긋나므로 쓰지 않았다. 위상 이름도 경계가 모호해 쓰지 않았다.
- **조작**: 왼쪽 달을 끌어 자리를 옮길 수 있다. 독자가 "이 자리면 어떻게 보이지?" 를 직접 해 보게 하려는 것이며,
  누르지 않아도 한 바퀴(16초) 안에 주장이 끝난다. `PieceKit.frozen` 이면 무시한다.
- **두지 않은 것**: 그리드·축·범례·재생 버튼·제목·툴팁, 지구 그림자(월식은 다른 질문이고 궤도 기울기 없이는
  오해를 낳음), 실제 크기·거리 비율, 밝기 비율 숫자, 달의 자전 무늬.

## (d) 이 그림이 성립하려면 필요했던 것

- 다시 짜기 아까웠던 것
  - 광원·시선·위쪽 벡터를 받아 구의 명암 경계를 그리는 원판 렌더 (금성 위상·행성에도 그대로 쓸 것)
  - 같은 장면을 두 시점으로 나란히 두고 같은 대상을 같은 색으로 잇는 칸 구성
  - 방향 하나로 정해지는 균일한 흐름 장(평행광) 무늬
  - 자동 진행 시각에 위상 차이를 더하는 끌기 조작과 frozen 처리
  - 연속값 구간으로 캡션 문장을 고르는 슬롯
- 누가 강제하면 안 되는 것
  - 남쪽·북쪽 어느 쪽에서 보는지, 궤도 방향 — 글의 독자(북반구) 에 맞춰 조각이 정해야 한다
  - 실제 비율을 버리는 결정 — 이 질문에서는 비율보다 방향이 중요해서 버렸지만, 다른 질문에서는 반대다
  - 명암 경계의 부드러움 정도 — 여기서는 경계가 또렷해야 겹침이 읽힌다
