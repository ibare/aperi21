# color-addition — 빛의 합성

## (a) 답하는 질문

빨간 빛과 초록 빛을 겹쳐 비추면 왜 노랑이 되고, 세 빛을 모두 겹치면 왜 흰색이 되는가?
(물감은 섞을수록 어두워지는데 빛은 무슨 일이 일어나는가)

답의 동사: **더해진다.**

## (b) 동사를 화면에서 어떻게 일어나게 했는가

- 검은 스크린 위에 빨강·초록·파랑 원판 빛을 가산 합성으로 그린다. 겹친 곳의 색은 실제로 채널이 더해진 값이다
  (빨강+초록 = 노랑, 셋 = 흰색). 겹치는 자리마다 다른 색이 스크린 위에 그대로 생긴다.
- 스크린 가운데 고리 한 점을 정하고, 빛이 **한 번에 하나씩** 그 자리에 들어오고 나간다
  (빨강 → +초록 → +파랑 → −빨강 → −초록 → −파랑 → +빨강, 15초 주기).
  빛 하나가 들어올 때마다 고리 자리의 색이 바뀌는 것이 곧 "더해진다" 이다.
- 오른쪽에 `빨강 몫 + 초록 몫 + 파랑 몫 = 고리 자리` 네모를 두어, 들어온 빛은 제 색으로 켜지고
  빠진 빛은 검정이 된다. 합 네모는 스크린의 고리 자리와 같은 색이다. 더하기가 수치가 아니라 색으로 일어난다.
- 세 빛이 다 빠지면 고리 자리가 검다 — 더할 것이 없으면 아무것도 없다는 것도 같은 동사의 한 경우다.

## (c) 화면 구성에서 내린 결정과 이유

- **원판 경계를 날카롭게** 했다. 부드럽게 흐리면 고리가 경계에 걸리는 순간 몫이 어중간해지고,
  캡션(8가지 조합 중 하나)과 화면이 어긋난다. 몫을 0/1 로 두면 캡션·몫 네모·스크린이 언제나 일치한다.
- **캡션은 시간표가 아니라 고리 자리의 실제 포함 여부에서 계산한다.** 그래서 손으로 원판이나 고리를 옮겨도 어긋나지 않는다.
- **더하기 기호(+, =)** 는 두었다. 몫 네모 셋과 합 네모의 관계가 곧 주장이라 기호 없이는 네 네모가 나열로만 읽힌다.
  네모 아래 글자(빨강·초록·파랑·고리 자리)도 두었다. 검정으로 꺼진 몫 네모는 색으로 누구인지 알 수 없기 때문이다.
- **고리**는 흰 윤곽선(검은 테 두름)이다. 어떤 빛 색 위에서도 보이도록. 강조색은 쓰지 않았다 — 이 조각의 색은 모두 빛 자신의 색이다.
- 조작: 원판과 고리를 끌 수 있다. 독자가 자홍(빨강+파랑)처럼 자동 진행에 없는 조합을 직접 만들어 볼 수 있게.
  누르는 순간 자동 진행이 멈추고 그 자리에서 이어진다. `PieceKit.frozen` 이면 조작을 무시한다.
- 두지 않은 것: 그리드·축·범례·제목·재생 버튼·밝기 수치·스펙트럼·원추세포 그림.
  모두 주장("겹치면 더해진다")에 보태지 않거나 문단의 몫이다. 이웃 조각 `ray-tracing`(렌즈)과 겹치지 않도록 광선 그림도 두지 않았다.
- 도착 순간(t=0) 이미 초록이 고리 쪽으로 들어오는 중이다.
- 세로 310px — 원판 셋이 비켜난 상태에서도 스크린 안에 들어오는 최소 높이.

## (d) 이 그림이 성립하려면 무엇이 필요했는가

- 다시 짜기 아까웠던 것
  - 상태 순서표 + 구간 길이 + 이징으로 위치를 `t` 의 함수로 만드는 계산
  - 자동 진행 ↔ 손 조작 전환(현재 자동 상태 복사, frozen 처리)
  - 포인터 좌표 ↔ 논리 좌표 변환, dpr 처리
  - 화면 상태 조합 → 캡션 문장 표
  - 가산 합성 그리기 (캔버스 `lighter` 에 묶여 있음)
- 누가 강제하면 안 되는 것
  - 원판 경계를 부드럽게 해야 한다는 "보기 좋은" 기본값 — 여기서는 캡션 일치를 위해 날카로워야 한다
  - 색을 테마 팔레트로 바꾸는 것 — 빛의 색은 순수한 빨강·초록·파랑이어야 합이 노랑·청록·자홍·흰색으로 정확히 나온다.
    테마가 조각 색을 덮으면 주장이 거짓이 된다
  - 배경색 — 스크린은 반드시 검정이어야 한다 (빛이 없음 = 0)
