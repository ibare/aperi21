# 배치 00 — 파일럿 (운동학 2)

배치 방식이 돌아가는지 확인하는 파일럿. 10개 배치로 가기 전에 장치와 절차를 두 조각으로 태운다.

| 조각 | 주장 | 동사 |
|---|---|---|
| `centripetal-acceleration` | 같은 빠르기로 원을 돌아도 속도는 매 순간 방향이 바뀌고, 그 바뀐 만큼(Δv)은 어디서 재도 중심을 향한다 | 중심 쪽으로 꺾인다 |
| `velocity-time-graph` | 속도-시간 그래프 아래 쌓인 넓이는 그 동안 물체가 간 거리와 같다 | 쌓인다 |

## 1. 자유 구현

격리된 에이전트 둘이 병렬로 만들었다. 지시서는 `tasks/piece-lab/_harness/BRIEF.md`.
엔진 이야기는 넣지 않았다.

- 둘 다 계측 약속을 지켰다 — `⚠` 0, 계측 전 시각, 같은 `t` 두 번 촬영 시 바이트 동일
- 두 에이전트 모두 스크린샷을 보고 스스로 고쳤다 (띠 시차 제거 · 이음매 제거)

## 2. 추출 — 엔진이 주는 것 / 못 주는 것

### 구심 가속도

| 화면 요소 | 어휘 | 판정 |
|---|---|---|
| 원 궤도 | `trajectory` (`closed`) | **선언만 있고 미구현** |
| 중심 · 공 | `body` | 있음 |
| 공의 속도 · Δv (이름표) | `vector` (`label`) | 있음 |
| 남겨 둔 속도 · 지난 Δv (옅어짐) | `vector` + 인스턴스 불투명도 | **없음** |
| 짧아지면 줄어드는 화살촉 | `vector` | **수정** |
| 두 줄 캡션 · 페이드 인 | `readout` + 불투명도 | **수정** (여러 줄) |

### 속도-시간 그래프

| 화면 요소 | 어휘 | 판정 |
|---|---|---|
| 축 · 1초 경계 · 말뚝 (1px) · 속도 곡선 (2px) | `trajectory` + 굵기 | **수정** (굵기) |
| 쌓인 넓이 · 떨어지는 기둥 · 펼친 띠 · 길 | `region` | 있음 |
| 지금 속도 점 · 수레 | `body` · `marker` | 있음 |
| 캡션 | `readout` | 있음 |

**기존 어휘로 성립한다.** 새 어휘가 필요 없다는 것도 결과다 — 오늘 올린 `region` 이
그래프 넓이와 길 위 띠를 모두 덮었다.

### 발견한 결함

`trajectory` 가 `style.lineStyle`(dashed/dotted) 과 `closed` 를 **선언만 하고 구현하지
않았다.** `setLineDash` 호출이 없고 경로를 닫지 않으며 굵기가 2로 고정이다.
이미 영향이 있었다 — torricelli 의 동시 출발 점선과 container-shape 의 목표 수면 점선이
실선으로 그려지고 있었다.

## 4. 엔진이 아닌 것 — 결정이 필요한 것

**시간표 헬퍼.** 두 조각이 모두 원했다 — 주기 안의 단계 경계, 구간별 진행도, 이징,
단계 이름으로 캡션을 고르는 것. 렌더 어휘가 아니라 **sim 쪽 연출 계산**이다. sim 이
import 할 수 있는 곳에 두려면 원칙 1 의 허용 목록(schema 타입 · 도메인 plugin 의 순수
계산 함수)을 넓혀야 한다.

파일럿에서는 각 sim 이 `physics.ts` 안에서 단계를 계산한다.

**결정 (2026-09-10) — 선언으로 올린다 (안 B).** 헬퍼 패키지(안 A)는 원칙 1 을 넓혀야
하고, 무엇보다 단계의 길이와 캡션이 여전히 코드에 남아 저작자가 손댈 수 없다.

- `BundleSchema.timeline` — `startAt` 과 단계 목록(`id` · `duration` · `ease` · `caption`).
  늘 순환한다. 엔진이 시각에서 푼 값(`TimelineFrame`)을 `scene` 에 `timeline` 으로 넘긴다.
- `BundleSchema.caption` — 캡션 슬롯 하나. 엔진이 readout 을 만들어 덧붙인다. 이웃 단계가
  같은 문장이면 다시 페이드하지 않는다.
- 시계는 임베드 시간 엔진 + `startAt`. 리셋 · 검사 시각 이동이 그대로 맞는다.
- 두 sim 의 상태가 비었다. 구심 가속도의 비교 각 간격은 `keep` 길이에서, 속도-시간
  그래프의 기둥 비행 시간은 `land` 길이에서 유도한다 — 선언과 물리가 어긋날 수 없다.
- 남은 것: 유체 두 sim 은 캡션을 **상태**(속도 구간 · 물방울 나이)로 고른다. 시간표로
  나눌 수 없어 이번에 옮기지 않았다. 정박값 시퀀스 + 유휴 복귀(`laminar`)도 같은 축이다.

## 5. 자기 신고 중 엔진 일이 아니었던 것

| 신고 | 판정 |
|---|---|
| 벡터 평행 이동 애니메이션 | sim 이 시간에 따라 `from` 을 계산 |
| 주기 번호로 다시 계산하는 결정적 잔상 | sim 의 계산 + `opacity` |
| 두 좌표계 사이 도형 보간 | sim 의 배치 계산. 월드 좌표 하나로 두 칸을 놓는다 |
| 꺾은선 함수와 정확한 적분 | sim 의 물리 |
| 고DPI 캔버스 맞춤 | 엔진 무대가 이미 한다 |

## 6. 장치에서 드러난 것

- **`inspectAt` 이 처음에 동작하지 않았다.** `useBundleRuntime` 이 마운트 때 같은 값의
  새 `paramValues` 객체를 넣어 재초기화 effect 가 한 번 더 돌았다. 평소에도 마운트마다
  상태를 두 번 초기화하던 잠복 버그였다.
- 두 에이전트가 같은 `_report/report.md` 에 덮어쓴다. 10개 병렬에서는 조각별로 나누거나
  합본을 마지막에 다시 돌려야 한다.
- 병렬 이관은 공유 파일(bootstrap loader · 의존 · 카탈로그 연결)에서 충돌한다.
  파일럿은 메인이 미리 배선한다. 10개 배치 전에 이 배선을 생성기로 바꿀지 판단한다.

## 7. 절차 위반 — 확인 지점을 건너뛰었다

이 파일럿은 **확인 지점 ① 선정과 ② 원본 확인을 건너뛰고** 엔진 수정·이관까지 진행했다.
보고서를 만들어 놓고 그 앞에서 멈추지 않았고, 보고서에 sims 비교를 섞었다.

교정 — 확인 지점 ② 의 보고서는 **원본 스크린샷 + 조각별 엔진 대조표(`engine-fit.json`) +
배치 전체의 없는 기능 합계**를 한 장에 담는다. 드리고 멈추며, 확인 전에는 엔진 수정도 이관도
하지 않는다. 절차 SSOT 는 `tasks/piece-lab/_harness/PROCESS.md`.

이 파일럿의 엔진 수정(§3)과 두 sims 는 확인 없이 만든 것이라 **미커밋 상태로 두고** 원본 확인
결과에 따라 유지하거나 되돌린다. `trajectory` 점선·닫힌 경로 결함은 원본과 무관하게 원래 있던
버그라 수정 자체는 유효하다.
