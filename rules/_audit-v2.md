## 미해소 (2건, 둘 다 Medium)

### 위반 5 — C4 · 두 id 공간이 겹친다

**코드 수정으로 닫을 수 없다.** v1 에서는 "파일 2개 rename" 으로 봤으나 재조사에서
틀린 것으로 드러났다.

- `schema.id` 는 흘러나온 명명 실수가 아니라 **카탈로그 콘텐츠 명세**(`docs/01-catalog.json`)
  의 id 공간에 속한다. 그쪽은 id 163개가 전부 snake 다 (kebab 0).
- 카탈로그 생성기는 `schema.id` 가 아니라 **디렉터리 leaf** 로 조인하므로 등록 키와
  런타임에서 어긋나 있지는 않다. 겹치는 것은 3개 엔티티뿐이다.

→ **리포 전역 명명 규약 결정이 선행되어야 한다.** 3개만 바꾸면 한 파일에 두 규약이
섞여 지금보다 나빠진다. 상세는 `rules/concerns/C4-reference-identifier.md`.

## 감사 자체에서 배운 것

**v1 의 grep 이 불완전했다.** C1 검사가 `ko ?` 삼항식만 봐서 같은 뜻의 다른 형태를
놓쳤다. 감사의 검색은 **규칙이 금지하는 것**이 아니라 **코드가 실제로 쓰는 형태**를
기준으로 짜야 한다. 같은 뜻을 코드가 두 형태로 쓰고 있으면 둘 다 봐야 한다.

**v1 의 영향 범위 판정도 한 번 틀렸다** (위반 5). 문자열 출현 위치만 세고 그 문자열이
속한 id 공간을 보지 않았다. 다음 감사에서는 "이 식별자가 어느 명명 공간의 일부인가" 를
함께 묻는다.
