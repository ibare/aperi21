# 정지 마찰력

**주장** — 정지 마찰력은 당기는 힘을 따라 똑같이 커지며 버티다가, 버틸 수 있는 한계를
넘는 순간 놓치고 상자가 미끄러진다. 동사: **따라 커지다가 놓친다.**

원본은 엔진 없이 손으로 짠 것이다 (`tasks/piece-lab/static-friction/`).
자유 렌더(`Bundle.renderers`) 없이 선언만으로 성립한다.

## 쓴 어휘

| 원본의 요소 | 어휘 |
| --- | --- |
| 바닥선 | `trajectory` (2점 · `width: 2` · `muted`) |
| 바닥 결(빗금) | `trace` (`shape: 'tick'` · `direction: [-1, -1]` · `width: 1`) |
| 상자 채움 | `body` (`rect` · `outline: 'none'` · `muted` subtle) |
| 상자 테두리 | `body` (`rect` · `fill: 'none'` · `outline: 'role'` · `muted` medium) |
| 한계 점선 | `trajectory` (`lineStyle: 'dashed'` · `width: 1.5` · `accent` · `opacity`) |
| 한계 세로 눈금 | `trajectory` (2점 · `width: 2.5` · `accent` · `opacity`) |
| '버틸 수 있는 한계' 글자 | `readout` (월드 앵커 · `chip: false` · `font: 'text'` · 12 px · `accent`) |
| 마찰력 화살표 | `vector` (`width: 5` · `headSize` 12 px · `secondary`) |
| 당기는 힘 화살표 | `vector` (`width: 5` · `headSize` 12 px · `ink`) |
| 흐려짐 · 다시 나타남 | 각 인스턴스의 `opacity` |
| 당김 → 미끄러짐 → 흐려짐 → 빈 틈 | `BundleSchema.timeline` 단계 다섯 (`appear` 0.4 · `pull` 5.6 · `slide` 3 · `vanish` 0.6 · `rest` 0.4) |
| 도착한 순간 이미 당기는 중 | `BundleSchema.startAt` = 1.5 s (원본 `OFFSET`) |
| 캡션 "버틴다 / 미끄러진다" | `BundleSchema.caption` 슬롯 + 단계마다 `caption` 키 · `fade: 0.4` |

색은 원본대로 세 역할이다 — 당기는 힘 `ink` · 마찰력 `secondary`(파랑) · 한계 `accent`(주황).
정지 → 운동 마찰로 바뀌어도 "바닥이 주는 마찰" 이라는 같은 대상이라 마찰력의 색을 바꾸지 않는다.

상태는 비어 있다. 모든 값이 조각 시계의 함수이고 `physics.readingAt` 이 시간표 프레임에서
계산한다 — 누적 적분이 없어 `step` 은 항등이고 `preroll` 도 쓰지 않는다.

## (a) 원본과 달라진 점과 이유

**1. 시간표를 단계 다섯으로 나눴다 — 값은 원본 식과 같다.**
원본은 `p < RAMP` 분기 하나와 `p < 0.4` · `p > SLIDE_END` 알파 봉투로 갈랐다. 경계 상수를
옮기지 않고 단계로 선언했다. 당기는 힘은 `span(start('appear'), end('pull'))`(원본 `p / RAMP`),
미끄러진 거리는 `at('slide')²`(원본 `½·a·τ²`, `a = 2·250/3²`), 알파는
`at('appear') × (1 − at('vanish'))`(원본 `p/0.4` · `1 − (p−9)/0.6`)로 원본과 같은 값이다.

**2. 캡션이 미끄러지는 순간 0.4 초 페이드 인 한다.** 원본은 캡션 불투명도를 장면 알파에 묶어
주기 첫 0.4 초에 나타나고, 문장이 바뀌는 순간(4.5 s)에는 바로 바꿨다. 슬롯의 `fade` 는 문안이
바뀔 때마다 걸리므로 주기 첫머리를 맞추면 전환 순간에도 0.4 초 페이드가 생긴다. 첫머리를
택했다 — 문턱 순간의 짧은 페이드는 주장을 가리지 않는다.

**3. 캡션이 흐려지지 않고 끊긴다.** 원본은 `vanish` 0.6 초 동안 캡션도 장면과 함께 흐려졌다.
슬롯에는 페이드 아웃이 없어 캡션은 `vanish` 동안 그대로 있다가 `rest` 에서 사라진다(캡션 키 없음).

**4. 상자 색이 회색이다.** 원본은 베이지 채움(`#c9c3b6`) + 한 단 짙은 테두리(`#8d8676`)였다.
색 역할로만 말하므로(C2) `muted` subtle 채움 + `muted` medium 테두리로 옮겼다. 채움과 테두리를
다른 진하기로 두려고 `body` 를 두 겹 선언했다. 테두리 굵기는 테마의 가는 선(1 px, 원본 1.5)이다.

**5. 프레이밍 — 경계는 원본 캔버스 820 × 190 px, 캡션은 그 아래 여백.**
좌표는 원본 100 px = 월드 1, 바닥선이 y = 0 이다(`schema.ts` 「배치」, 숫자는 원본 그대로).
러너가 경계 둘레에 여백 36 px(프레이밍 12 + 기본 24)을 두므로 캡션 줄을 경계에 넣으면 세로가
배율을 묶어 장면이 원본의 77 % 로 작아졌다(첫 대조에서 확인). 캡션 줄을 경계에서 빼고 캔버스
높이를 254 px 로 두어 가로가 배율을 정하게 했다 — 850 px 임베드에서 약 0.95 배. 그래서 원본보다
장면과 캡션 사이가 조금 넓다.

**6. 화살표 모양의 작은 차이.** 엔진 `vector` 는 선끝이 둥글고(원본 butt) 머리 길이가
`headSize × 배율`이라 원본보다 1 px 쯤 작다. 길이 비교(같은 축척 180 px)는 그대로다.

**7. 글꼴.** 캡션과 한계 글자가 테마 본문 글꼴(세리프)로 나온다. 원본은 시스템 산세리프였다.

**화면에 두지 않은 것** — 원본 결정 그대로다. 힘의 수치(N)와 마찰 계수, 운동 마찰 비율 0.7,
수직항력·중력·알짜힘 화살표. 주장은 값이 아니라 두 화살표 길이의 모양이다.

## 어휘 부족

- **캡션 슬롯의 페이드 아웃 · 장면 알파와의 연동이 없다.** `fade` 는 문안이 바뀔 때의 페이드 인
  하나뿐이다. 주기 끝에서 장면과 함께 흐려지는 캡션, 그리고 "첫머리에만 페이드하고 단계
  전환에는 바로 바꾸는" 선택을 선언할 수 없다. 단계마다 캡션 불투명도(또는 페이드 여부)를
  줄 자리가 있으면 원본과 같아진다. (달라진 점 2 · 3)
- **`body` 테두리 굵기를 선언할 수 없다.** 원본 1.5 px 테두리가 테마의 가는 선(1 px)으로 고정된다.
  채움과 테두리를 다른 진하기로 두려면 `body` 를 두 겹 선언해야 했다 — 테두리 색의 강조
  단계를 따로 줄 필드(`outline` 의 emphasis)가 없다. (달라진 점 4)
- **`vector` 선끝 모양을 고를 수 없다.** 둥근 끝이 고정이라 상자 옆면에서 시작하는 힘이
  면에 딱 붙지 않고 반 굵기만큼 면 안쪽으로 파고든다. 작용점이 판정 장치인 힘 화살표에는
  `butt` 가 필요하다. (달라진 점 6)
- **러너 기본 여백(24 px)이 캡션 줄과 겹친다는 것을 경계에서 알 수 없다.** 캡션 슬롯이 그림
  아래에 서는 조각은 경계에 캡션 몫을 넣을지 여백에 맡길지를 여백 크기를 알고 골라야 했다.
  캡션 슬롯의 자리를 프레이밍 여백에 반영하는 계약이 있으면 캔버스 높이를 손으로 맞추지 않아도
  된다. (달라진 점 5)
