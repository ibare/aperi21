# 마찰각 — 이관 NOTES

원본: `tasks/piece-lab/angle-of-friction/` (질문 · 동사 · 화면 결정은 원본 NOTES 가 그대로 유효하다).

동사: **같은 각에서 함께 미끄러진다.**

## 쓴 어휘

| 원본 요소 | 어휘 |
|---|---|
| 바닥 · 받침대 | `trajectory` |
| 각도 호 · 숫자 | `sector`(fillOpacity 0 · rimWidth) + `readout` |
| 미끄러진 각 눈금 | `trace`(tick · 방사 direction) |
| 나무판 · 상자 | `body` rect · orientation — 채움 한 겹 + 테두리 한 겹(`fill: 'none'` · `outline: 'role'`) |
| 아래 끝 턱 · 경첩 | `body` rect · circle(`glow: false`) |
| 미끄러진 각 기록 | `readout` — 줄마다 글 하나 + 강조색 값 하나 |
| 상자 수 조작기 | `slider`(range [2,5] · step 1 · digits 0) + `heldPath` |
| 회차 박자 · 캡션 | `timeline`(tilt · slide · vanish · lowered · appear) + `caption`(`cases: stopped` · `vars: n, angle`) |
| 겹침 순서 | `drawOrder: 'scene'` — 원본의 그리는 순서 그대로 |

역할 분담 — 판의 기울기와 상자 투명도는 시각의 함수라 scene 이 `params.timeline` 에서
읽는다. 상자의 적분(정지→운동 마찰, 턱 · 앞 상자에 닿으면 멈춤), 회차 기록, 더미 수의
교체는 누적이라 `step` 이 쌓는다. 원본은 주기 첫머리(판이 이미 12°)에서 열리므로
`startAt` · `preroll` 을 두지 않았다.

## (a) 원본과 달라진 점과 이유

1. **상자 색.** 원본은 나무색(황갈) 채움 + 갈색 테두리였다. 색 역할에 나무색이 없고,
   가장 가까운 `accent`(호박색)는 "미끄러지기 시작한 각" 하나에만 쓰기로 한 강조색이라
   빌리면 강조색이 두 뜻이 된다. 주 대상 역할 `primary`(옅은 채움 + 짙은 테두리)로 옮겼다.
   두 상자는 여전히 같은 색이다.
2. **슬라이더 자리.** 원본은 캡션 아래 캔버스 밖에 있었다. 엔진의 조작기는 그림 위에
   얹히므로, 판이 가장 높이 서도(26.6°) 비어 있는 왼쪽 위에 둔다(`at: top-left`).
   값 옆의 "개" 단위는 붙이지 않았다 — 아래 「어휘 부족」 2.
3. **배율.** 원본 860 × 290 px 를 고정 경계로 두고 캔버스 340 px 에 담는다. 러너 여백과
   캡션 한 줄 때문에 그림이 원본보다 조금 작다(대조 스크린샷 기준 약 0.9 배). 배치 · 비율은 같다.
4. **각도 호 · 판 테두리 굵기.** 호는 `rimWidth` 1.2 로 원본과 같지만 판 · 상자 테두리는
   `body` 가 굵기를 받지 않아 테마의 선 굵기다(원본 1.5).
5. **`PieceKit.frozen` 무시 규칙**은 옮기지 않았다 — 엔진에 그 개념이 없다. 슬라이더 조작
   규칙(기울이는 중이면 바로, 아니면 다음 회차부터; 누르기만 하고 값을 바꾸지 않으면 자동
   순서를 끊지 않음)은 원본과 같다.

대조 — `probeTimes` 1.5 · 4.4 · 6.5 · 13.5 초 네 시각 모두 원본과 같은 장면이다
(18.0° 기울이는 중 / 26.6° 미끄러지는 중 · 기록 한 줄 / 멈춘 뒤 과거형 캡션 / 5개 더미 회차 · 기록 두 줄).
모의 실행으로 회차 경계를 확인했다 — 미끄러짐 시작 3.65 초, 두 상자 멈춤 5.28 초,
다음 더미 교체 8.42 초, 자동 순서 3 → 5 → 2 → 4.

## (b) 어휘 부족

1. **`step` 은 `TimelineFrame` 을 받지 못한다.** 상자를 미끄러지는 단계에서만 적분하고,
   `tilt` 가 끝나는 걸음에 기록을 남기고, `appear` 에서 더미를 갈아 끼우려면 지금 단계를
   알아야 한다. 상태에 제 시계(`clock`)를 두고 선언된 `schema.timeline.phases` 를 다시 읽어
   단계를 계산했다(`physics.ts` 의 `phaseAt`). 엔진 시계와 같은 `dt` 로 쌓이니 어긋나지
   않지만, 같은 규칙을 조각이 한 벌 더 갖고 있다. `inclined-plane` 과 같은 우회다.
2. **`slider.unit` 이 `LocalizedText` 가 아니다.** 원본 값 표시는 "3개" 였다. "개" 는
   언어마다 달라지는 낱말이라 문자열 단위로 박을 수 없어 뺐다.
3. **회차 결과를 한 줄씩 쌓는 기록 목록**이 어휘에 없다. `readout` 을 줄마다 둘씩(글 · 강조색 값)
   손으로 늘어놓았다. 줄 간격 · 최근 N 줄 · 값 열 정렬을 조각이 다시 짠다.
4. **빗면(경첩) 좌표 틀**이 없다. 판 위 자리(s, h) → 월드 변환과 판에 수직으로 쌓는 더미를
   `onBoard` 로 손으로 옮겼다. 빗면 조각마다 되풀이된다.
5. **`body` 테두리 굵기**를 선언할 수 없다 (위 (a) 4).
6. **나무색 같은 재질색 역할**이 없다 (위 (a) 1). 강조색과 겹치지 않는 따뜻한 물체색이 필요했다.
