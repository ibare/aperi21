# 수평잡기 — sim 노트

원본: `tasks/piece-lab/balance-scale/` (자유 구현). 원본의 결정과 근거는 그쪽 `NOTES.md`.
이 파일은 sim 으로 옮긴 뒤 **달라진 것**과 **어휘 부족**을 적는다.

옮기면서 쓴 어휘 — `trajectory`(수평 기준선 점선 · 저울대 굵은 선) · `region`(받침대
삼각 기둥 · 바닥판) · `body`(받침점 구멍 circle · 추 블록 rect + orientation) ·
`trace`(거리 눈금 tick, 방향 = 저울대 법선) · `luminance`(옅은 회색 · 청회색 · 구멍) ·
`BundleSchema.timeline`(거리 대본 9단계) · `BundleSchema.caption`(단계 캡션 + `cases`) ·
`drawOrder: 'scene'` · `point-drag`(가벼운 추 끌기). **자유 렌더(`Bundle.renderers`)는 쓰지 않았다.**

대조: `pnpm -s piece:report --sims=… balance-scale` 의 t = 0.5 · 3 · 8 · 12 · 16.5 다섯 시각에서
기울기 · 추 자리 · 캡션 문장이 원본과 같다.

## (a) 원본과 달라진 것

### 1. 저울대 각은 `step`, 거리 대본은 `timeline`

각은 토크 · 복원 토크 · 감쇠로 적분하는 **누적 상태**라 `step` 이 쌓는다 (원본의 반암시
오일러 그대로). 가벼운 추 거리는 **시각의 함수**라 시간표 단계(1.5 / 3.5 / 4 / 1.5 / 2 / 1.5 /
3 / 2.5 / 0.5 초, 이징 `smooth`)로 선언했다. 단계마다의 거리(2 → 4 → 5 → 4 → 2 칸)는 스테이지
상수 `armNear` · `armLevel` · `armOver` 를 `physics.PHASE_ARMS` 가 단계 id 로 가리킨다.

그런데 적분에는 매 걸음의 거리가 필요하고 `step` 은 시간표 프레임을 받지 못한다. 그래서
상태에 `clock` 을 두고 `physics.phaseAt` 이 **선언의 단계 목록을 직접 읽어** 거리를 구한다.
단계 경계 상수는 두지 않았다. 시간표에 `timeScale` · `startAt` 이 없으므로 이 시계는 실시간
루프와 검사 시각(`inspectAt`) 양쪽에서 엔진 시계와 같은 걸음으로 흐른다.

### 2. `preroll` · `startAt` 을 쓰지 않았다

원본은 시계를 0 에서 열고, 초기 각을 **2칸일 때의 평형각**(약 −14°)으로 두어 "도착한 순간
이미 기울어 있다" 를 만들었다. 시계를 앞당긴 것이 아니므로 둘 다 두지 않고, 평형각을
스테이지 상수에서 계산해 `initialState` 에 둔다. `preroll` 을 걸면 상태 시계만 앞서 엔진
시계와 어긋난다.

### 3. 캡션 — 단계 + `cases`

각으로 갈리지 않는 문장(가까이 · 바깥으로 · 조금 더 · 너무 멀리 · 되돌리자 · 가까이 당기자)은
단계의 `caption` 이다. 각으로 갈리는 것은 상태 boolean 으로 고른다 — `levelReached`(수평 단계
·되돌림 단계에서 1.5° 안), 끌어 본 뒤의 `manualLevel`(1° 안) · `manualHeavy` · `manualLight`.
수평 단계의 기본 문장은 원본의 `settling`, 되돌림 단계는 `back` 이다. 원본 `captionText` 의
`if` 순서를 `cases` 순서로 옮겼다.

### 4. 끌기 — 손잡이가 보인다

원본은 커서 모양만 바뀌고 손잡이가 없었다. `point-drag` 는 손잡이를 그리므로 가벼운 추
가운데에 테두리 고리(`handle: 'ring'`)가 늘 보인다. 잡는 판정도 원본은 "저울대 방향으로 블록
한 변 안(높이 무관)" 이었고 여기서는 추 가운데 반경 34 px 원이다. 잡고 있는 동안 고리는
포인터를 따라가고, 블록은 그 자리를 저울대 위로 투영한 거리(0.5 ~ 5 칸)에 놓인다.
한 번 끌면 대본이 멈추는 것은 원본 그대로다(`manual`). `PieceKit.frozen` 무시는 엔진의 검사
시각이 시계를 멈추는 것으로 갈음된다.

### 6. 캡션 자리 · 캔버스

원본 캡션은 캔버스 **아래 DOM 문단**이었다. 슬롯은 캔버스 안에 그리므로 캔버스를 300 → 330 px
로 늘리고 원본 문단의 가운데 높이(받침점 아래 175 px)에 월드 앵커로 두었다.

## (b) 어휘 부족

- **`step` 이 시간표 프레임을 받지 못한다.** 누적 적분이 시간표 단계의 값(가벼운 추 거리)을
  매 걸음 필요로 하는데 받을 길이 없어, 상태에 시계를 따로 두고 선언의 단계 목록을 조각이
  직접 해석했다(`physics.phaseAt` — 엔진 `evaluateTimeline` 과 같은 일, 이징 곡선도 복제).
  단계에 `timeScale` 이 생기거나 `startAt` · `restart` 가 끼면 두 시계가 조용히 어긋난다.
- **단계에 값을 실을 자리가 없다.** 단계마다 "거리가 어디서 어디로" 를 선언할 수 없어
  단계 id → 스테이지 상수 이름 표(`PHASE_ARMS`)가 코드에 남았다. 저작자가 단계를 추가하면
  이 표도 고쳐야 한다.
- **`point-drag` 손잡이를 숨길 수 없고, 잡는 판정 모양을 고를 수 없다.** 물체 자체가 손잡이인
  그림(블록을 잡는다)에 고리가 덧그려진다. 판정도 원뿐이라 "저울대 방향 거리만" 같은 띠
  판정을 선언할 수 없다.
- **`point-drag` 의 제약이 움직이는 몸체를 따라가지 못한다.** `snapTo` 는 고정 점 목록이라
  도는 저울대 위로 붙일 수 없어, 투영을 `step` 이 한다. 그래서 끄는 동안 손잡이(포인터 자리)와
  블록이 따로 논다.
- **캡션 조건이 각(값)으로 갈린다.** 1.5° · 1° 문턱은 `cases` 가 식을 받지 않으므로 physics 가
  boolean 으로 세어 둔다 — 규약대로지만, 문턱 값 자체는 저작자가 선언에서 고칠 수 없다(스키마
  상수).
- **청회색 역할이 없다.** 무채도 강조색도 아닌 "주 대상의 차분한 색" 을 옮길 자리가 없어
  `secondary` 를 옅게 얹었다(위 5).
