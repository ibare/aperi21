# stress-strain-curve — 이관 NOTES

원본: `tasks/piece-lab/stress-strain-curve/` (자유 구현, 캔버스 직접 그리기).
이관본은 **자유 렌더 없이** 표준 어휘 넷으로 선언한다 — `body` · `trajectory` · `vector` · `readout`.

| 원본 묶음 | 어휘 |
|---|---|
| 벽 | `body` rect (10 × 100, `ink`) + 빗금 `trajectory` ×6 (width 1, `muted` medium) |
| 처음 길이 표시 | `trajectory` dashed (width 1) + `readout` (world, 칩 없음, `text` 14px) |
| 막대 · 손잡이 | `body` rect ×2 (`secondary` strong) — 두께 26 / √(1 + 0.12 e) |
| 당기는 힘 화살표 | `vector` (width 2.5 · headSize 12 · `ink`) — 길이 3 px 아래면 두지 않는다 |
| 남은 늘어남 (막대) | `trajectory` 괄호 4점 (width 3, `accent`) + `readout` (`accent`) |
| 곡선 축 | `trajectory` 꺾인 선 (width 1.2) + `readout` ×3 ('응력' · '변형률' · '0') |
| 지나온 곡선 | `trajectory` (width 2.5, `ink`) |
| 남은 늘어남 (곡선) | `trajectory` 선분 (width 5, `accent`) |
| 지금 상태 점 | `body` circle (반지름 6.5, glow 끔, 막대와 같은 `secondary`) |
| 캡션 | `caption` 슬롯 — 월드 앵커 (원본 자리 20, 280), 왼쪽 16px `ink` |

월드는 **원본 캔버스 1px = 1** 이고 y 만 위로 뒤집었다. 곡선 판은 `graph` 카드가 아니라 막대와 같은
월드에 긋는다. 고정 경계는 860 × 300 한 장 그대로, 겹침은 원본이 그린 순서(`drawOrder: 'scene'`).

시간표 — 원본의 한 바퀴 17 s 를 12 단계로 선언했다(`schema.ts`). `startAt: 0.8` 은 원본의 시작 어긋남.
장면 흐려짐(`fade` · `enter`)과 남은 늘어남의 나타남은 단계 진행도와 `span` 으로 읽는다.

## (a) 원본과 달라진 점과 이유

1. **상태를 쌓지 않는다.** 원본은 남은 변형률과 자취 점 목록을 매 프레임 쌓았다. 한 바퀴 안에서
   당김은 늘 한 방향이고 놓기는 힘을 곧게 줄이므로, 쌓인 값이 시각의 닫힌 함수다 — 당긴 변형률이
   남은 변형률을 정하고, 자취는 탄성 직선 · 뼈대곡선 · 하중 제거 직선의 이음이다(`physics.ts`
   `materialAt`). 원본 누적 모형을 1/600 s 걸음으로 한 바퀴 돌려 견준 결과 변형률 · 응력 · 남은
   변형률 · 두 투명도의 최대 차이가 2 × 10⁻⁶ 이었다. 자취의 곡선 구간은 프레임마다가 아니라
   변형률 0.04 간격으로 잇는다(모양 같음).
2. **두 번째 당김의 캡션 전환을 시각으로 옮겼다.** 원본은 변형률로 문장을 골랐다(`e <= 0.5`).
   당김이 smoothstep 으로 정해져 있어 그 순간은 당김 시작 뒤 0.98 s 하나로 정해진다. 그 시각에서
   `pull-elastic` / `pull-plastic` 으로 갈라 캡션을 시간표가 고른다. 경계는 `schema.ts` 가 모형
   상수에서 역산한다(`ELASTIC_PULL_DURATION`). 위 대조에서 캡션이 어긋난 걸음은 경계 한 걸음뿐이다.
3. **한 동작을 두 단계에 걸쳐 이징한다.** 멀리 당김(위 2 로 가름)과 멀리 놓기(끝 0.2 s 에 남은
   늘어남이 나타나기 시작 — 원본 12.0 s)는 두 단계로 나뉘므로, 이징은 합친 구간에
   `span(…, 'smooth')` 으로 건다. 단계마다 이징하면 가른 자리에서 멈칫한다.
4. **색은 역할색으로.** 막대 · 점 `secondary`(원본의 탁한 청회색보다 밝은 파랑), 강조 `accent`
   (원본 주홍 → 호박색), 먹 `ink`, 흐린먹 `muted` medium — 원본처럼 선과 글자가 한 색이다.
5. 처음 길이 점선 무늬는 원본 4/4 px 대신 `trajectory` 의 6/5 px 이다. 괄호 모서리와 선 끝은
   둥글다(원본은 각지고 잘린 끝) — 남은 선분이 원점 왼쪽으로 2.5 px 삐져나온다.
6. 캡션 글자는 캔버스 폭이 좁으면 readout 이 줄인다(원본은 고정 16px).

## (b) 어휘 부족

1. **선 끝 · 이음 모양을 고를 수 없다.** `trajectory` 는 `lineCap: round` · `lineJoin: round` 고정이다.
   축 위 남은 늘어남 선분은 **원점에서 정확히 시작해야** "원점부터 여기까지" 로 읽히는데, 굵기 5 의
   둥근 끝이 원점 왼쪽으로 나간다. 괄호의 각진 모서리도 낼 수 없다.
2. **실선 치수 괄호가 없다.** `dimension` 은 점선 + 끝점 원이라 "두 자리 사이의 길이 차" 를 강조색
   실선 괄호(다리 달린 ㄷ자)로 그을 수 없다. `trajectory` 4점 + `readout` 으로 근사했다. 원본
   engineWish 도 꼽았다.
3. **묶음 투명도가 없다.** 주기 끝의 흐려짐 → 새 막대 전환은 막대 · 손잡이 · 힘 · 괄호 · 자취 · 선분 ·
   점 일곱 인스턴스에 같은 `opacity` 를 하나씩 곱해 넣었다. "이 무리를 함께 흐린다" 를 선언할 자리가
   없다.
4. **여러 단계에 걸친 이징을 선언할 자리가 없다.** 캡션 때문에 한 동작을 두 단계로 가르면 단계
   이징(`ease`)을 쓸 수 없어 scene 이 `span` 으로 구간 끝을 다시 짚는다(위 (a) 3).
5. **값으로 캡션을 고르는 일을 시각으로 역산했다.** 캡션 `cases` 는 state 경로를 보지만 이 조각은
   state 가 비어 있고, `step` 은 TimelineFrame 을 받지 못해 "지금 변형률이 꺾인 곳을 넘었는가" 를
   상태에 적을 수 없다(알려진 부족). 그래서 경계를 모형에서 역산해 단계로 갈랐다 — 저작자가
   `pull-elastic` 길이를 따로 고치면 캡션과 곡선이 어긋난다.
6. 점선 무늬 간격을 선언할 수 없다(4/4 px 대신 6/5 px). 짧은 화살표의 머리는 길이 35% 로 제한된다
   (`newtons-second-law` (b) 1 과 같다) — 힘이 작은 순간 머리가 작아진다.

## 화면에 두지 않은 것 (원본 판단 유지)

- 응력 · 변형률의 숫자 값, 눈금 · 격자 — 주장은 "원점으로 돌아오는가" 라는 모양의 문제다.
- 항복점 · 극한강도 · 파단 · 넥킹 이름과 구간 — 한 주장을 넘는다.
- 조작기 — 작은 당김 / 큰 당김의 자동 대조로 주장이 끝난다.
