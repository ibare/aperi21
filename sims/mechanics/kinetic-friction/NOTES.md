# 운동 마찰력

**주장** — 미끄러지는 동안의 마찰은 빠르기와 상관없이 같은 크기라서, 빠른 상자와 느린 상자가
같은 만큼씩 느려진다. 동사: **같은 만큼씩 느려진다.**

원본은 엔진 없이 손으로 짠 것이다 (`tasks/piece-lab/kinetic-friction/`).
자유 렌더(`Bundle.renderers`) 없이 선언만으로 성립한다.

## 쓴 어휘

| 원본의 요소 | 어휘 |
| --- | --- |
| 두 줄 바닥선 | `trajectory` (2점 · `width: 2` · `ink` medium) |
| 줄 이름(빠르게 출발 / 느리게 출발) | `readout` (월드 앵커 · `chip: false` · `font: 'text'` · 13 px · `muted`) |
| 자리 눈금(1 초마다) | `trace` (`shape: 'tick'` · 세로 · 12 px · `width: 2` · `age` 없음 — 지워지지 않는다) |
| 상자 채움 | `body` (`rect` · `outline: 'none'` · `muted` subtle · `opacity: 0.3`) |
| 상자 테두리 | `body` (`rect` · `fill: 'none'` · `outline: 'role'` · `muted` strong) |
| 속도 화살표 | `vector` (`width: 2.5` · `headSize` 8 px · `ink`) |
| 마찰 화살표 | `vector` (`width: 3` · `headSize` 8 px · `accent` — 강조색은 이것 하나) |
| '속도' · '마찰' 글자 | `readout` (월드 앵커 · 12 px · 원본 기준선 자리) |
| 둘 다 미끄러짐 → 느린 상자 멈춤 → 둘 다 멈춤 | `BundleSchema.timeline` 단계 셋 (`sliding` 3 · `fastOnly` 3 · `stopped` 2.5) |
| 도착한 순간 이미 미끄러지는 중 | `BundleSchema.startAt` = 0.5 s (원본 `OFFSET`) |
| 캡션 세 문장 | `BundleSchema.caption` 슬롯 (월드 앵커 · 왼쪽 정렬 · 15 px) + 단계마다 `caption` 키 |

상태는 비어 있다. 원본도 `laneAt(tc)` 닫힌 식이라 누적 적분이 없다 — `step` 은 항등이고
`preroll` 은 쓰지 않는다. 지난 눈금도 쌓지 않고 `tickPositions(tc)` 로 매 프레임 다시 계산한다.
물리 상수(감속도 0.4 · 처음 빠르기 2.4 / 1.2 · 눈금 1 s)는 스테이지 `constants` 에 둔다.

## (a) 원본과 달라진 점과 이유

**1. 캡션 전환을 단계 경계로 옮겼다 — 경계는 멈추는 시각에서 계산한다.**
원본은 매 프레임 `state.lanes[].stopped` 를 보고 문장을 골랐다. 이 조각은 모든 것이 시각의
함수라 "느린 상자가 멈춤" 은 `tc ≥ v0/감속도 = 3 s`, "둘 다 멈춤" 은 `tc ≥ 6 s` 로 정해진다.
그래서 단계 길이를 `schema.ts` 에서 같은 상수로 계산했다(`V0_SLOW / DECEL` 등). 멈춤 판정과 단계
경계가 같은 식에서 나와 부동소수점까지 일치한다(`1.2/0.4 = 2.9999999999999996` 을 양쪽이 같게 쓴다).
**어느 시각에서도 캡션이 화면과 어긋나지 않는다** — 경계 직전은 두 화살표가 아직 보이고, 경계부터
멈춘 상자의 화살표가 사라진다. 캡션 전환에 페이드는 없다(원본과 같다).

**2. 상자 색이 조금 다르다.** 원본은 거의 흰 회색 채움(`#e9ecef`) + 짙은 회색 테두리(`#495057`, 2 px)다.
색 역할로만 말하므로(C2) `muted` subtle 채움을 `opacity: 0.3` 으로 더 옅게 하고, 테두리는 두 번째
`body` 로 `muted` strong 을 그었다. 테두리 굵기는 테마의 가는 선(1 px)이다. 첫 대조에서 opacity
없이 subtle 만 쓰면 채움이 짙은 회색으로 나와 원본과 달랐다.

**3. 강조색 · 바닥 색이 테마 색이다.** 마찰 화살표는 원본 주황(`#e8590c`) 대신 `accent`(황갈색),
바닥선은 원본 `#343a40` 대신 `ink` medium, 눈금은 `muted` medium 이다. "강조색은 마찰 하나" 라는
원본 결정은 그대로다.

**4. 아주 짧은 속도 화살표의 머리가 작다.** 원본은 머리 길이를 `min(8, 길이)` 로 잘라, 멈추기 직전의
8 px 짜리 화살표가 머리 삼각형만으로 남는다. 엔진 `vector` 는 머리를 길이의 35 % 로 자르므로 같은
순간에 짧은 막대처럼 보인다(t = 2 의 느린 줄). 줄어드는 길이는 같다.

**5. 프레이밍 — 경계는 원본 캔버스 860 × 268 px 전체(캡션 줄 포함), 캔버스 높이 316 px.**
좌표는 원본 100 px = 1 m = 월드 1, 캔버스 아래 끝이 y = 0 이다(`schema.ts` 「배치」, 숫자는 원본
그대로). 처음 300 px 로 두었더니 세로가 배율을 묶어 장면이 원본의 약 0.85 배였다. 316 px 로 올려
가로가 배율을 정하게 했다(약 0.9 배).

**6. 글꼴.** 줄 이름 · 화살 글자 · 캡션이 테마 본문 글꼴로 나온다. 원본은 시스템 산세리프였다.
대조 스크린샷에서 캡션의 몇 글자(「멈췄」 「씩」 등)가 다른 굵기로 섞여 보인다 — 글꼴 대체의
문제로 보이며 이 조각의 선언과는 무관하다(미확인).

**화면에 두지 않은 것** — 원본 결정 그대로다. 속도 · 마찰력 · 거리의 수치, 마찰 계수와 질량,
멈춘 뒤의 정지 마찰, 속도-시간 그래프. 주장은 "같은 크기" · "같은 만큼" 이라는 비교라 화살표 길이와
눈금 간격으로만 보인다.

## 어휘 부족

- **`vector` 머리의 짧은 화살표 규칙을 고를 수 없다.** 머리가 길이의 35 % 로 잘려, 줄어들다
  사라지는 화살표의 마지막 순간이 원본(머리 삼각형만 남음)과 다르다. 속도가 0 으로 줄어드는 것이
  주장의 일부인 조각에서는 "머리는 온전히, 축만 줄인다" 를 선언할 자리가 있으면 원본과 같아진다.
  (달라진 점 4)
- **`body` 테두리 굵기 · 테두리 진하기를 선언할 수 없다.** 원본 2 px 테두리가 1 px 로 고정되고,
  채움과 테두리를 다른 진하기로 두려면 `body` 를 두 겹 선언해야 했다. (달라진 점 2 · static-friction 과 같은 부족)
- **readout 을 글자 기준선에 맞출 수 없다.** 월드 앵커는 글 가운데에 놓으므로, 원본의 기준선 좌표를
  옮기려고 글자 크기의 1/3 만큼 올리는 근사를 썼다(`BASELINE_TO_MIDDLE`). 글꼴마다 실제 가운데가
  달라 1~2 px 어긋날 수 있다.
- **단계 길이를 물리 상수에서 계산한 것은 선언이 아니라 코드다.** 캡션 전환이 "멈춤" 이라는 상태에
  묶여 있는데, `caption.cases` 는 state 경로를 보고 `step` 은 시간표 프레임을 받지 못해(알려진 부족)
  시각의 함수인 멈춤을 state 에 적을 수 없다. 그래서 단계 경계를 멈추는 시각과 같은 식으로 계산했다.
  저작자가 단계 길이만 바꾸면 캡션이 멈춤과 어긋난다 — 단계 경계가 물리량의 함수라는 것을 선언할
  자리가 없다. (달라진 점 1)
