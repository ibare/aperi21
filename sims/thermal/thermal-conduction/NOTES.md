# 열전도 — sim 노트

원본: `tasks/piece-lab/thermal-conduction/` (자유 구현). 원본의 결정과 근거는 그쪽 `NOTES.md`.
이 파일은 sim 으로 옮긴 뒤 **달라진 것**과 **어휘 부족**을 적는다.

## 쓴 어휘

| 원본이 손으로 그린 것 | 선언 |
| --- | --- |
| 막대 몸체(채움 + 테두리) | `body` (`rect`) |
| 나뭇결 · 금속결 가로선 3줄 | `trajectory` (`width: 1`) |
| 격자 한 칸마다 세로 띠를 알파로 덧칠 | `region` 여럿 + `fillOpacity` |
| 60 ℃ 앞머리 선 · 쐐기 | `trajectory` + `body` (`custom`) |
| 밀랍 구슬 — 붙은 것 · 떨어지는 것 · 쌓인 것 | `body` (`circle` / `custom`) |
| 버너 불꽃 두 겹 · 주둥이 | `body` (`custom`) × 2 + `opacity`, `body` (`rect`) |
| 재질 이름표 | `readout` |
| 캡션 한 줄 | `BundleSchema.caption` 슬롯 + `cases` |
| 초기조건 프리롤(손으로 감던 것) | `BundleSchema.preroll` |
| 겹침 순서 | `BundleSchema.drawOrder: 'scene'` |

자유 렌더(`Bundle.renderers`)를 쓰지 않는다. `trace` · `constraint` · `particleSystem` ·
`luminance` · `heldPath` 는 이 조각이 쓸 자리가 없어 선언하지 않았다 — 조작기가 없고,
바닥에 쌓인 구슬은 지워지지 않아야 하지만 **자국이 아니라 물건**이라 `body` 로 둔다
(문턱을 넘으면 촉발되는 플래그 · 낙하 적분 · 착지 정지가 전부 `step` 의 상태다).

## 물리가 원본과 같은지

`step` 만 고정 걸음 1/60 로 굴려 재 봤다. 원본이 NOTES 에 적은 값과 **전부 일치한다.**

| | 이관본 | 원본 |
| --- | --- | --- |
| 쇠 낙하(도착 이후, 초) | 0.40 · 1.28 · 2.43 · 3.78 · 5.18 · 6.32 · 7.02 · 7.25 | 같음 |
| 나무 낙하 | 9.38 | 9.38 |
| 앞머리 t=0 | 쇠 3.7 cm · 나무 0.4 cm | 같음 |
| 앞머리 t=1.5 / 4 | 쇠 6.3 / 9.2 · 나무 0.7 / 1.0 | 같음 |
| t=7.5 | 쇠 바닥 9 + 낙하 중 1, 나무 0 | 같음 |

간격이 0.88 → 1.15 → 1.35 → 1.40 으로 벌어지다 마지막 셋이 도로 몰리는 것(단열된 끝에서
열이 쌓인다)도 그대로 나온다.

## 원본과 달라진 것

1. **캡션이 수치를 말하지 못한다.** 원본은 온도 배열에서 문자열을 직접 만들었다 —
   "3분 9초 — 쇠에서는 60 ℃ 가 9.2 cm 까지 번졌고, 나무에서는 1.0 cm 에 머문다".
   `CaptionSlotDef` 에는 `vars` 가 없어서 값을 끼울 수 없다. 지금은 상태로 고르는 두
   문장(`cases`)이다 — 쇠가 끝까지 도달했는가로 갈린다. **이 조각에서 가장 크게 잃은
   것이고**, 아래 「어휘 부족」 1번이다.
2. **두 막대의 몸체 색이 같다.** 원본은 회색(#9aa0a6)과 나무색(#c69b6d)으로 재질을
   구분했다. `colorRole` 은 의미 역할이라 물질 색을 말할 수 없고, 나무색에 가장 가까운
   `accent` 는 이 조각에서 **뜨거움 한 가지 뜻으로 예약**돼 있다 (S-piece: 강조색은 한
   가지 뜻에만). 그래서 둘 다 `muted`(옅게)로 두고 재질은 결 선과 이름표가 말한다.
   두 막대가 같아 보이는 것이 "조건은 같고 재질만 다르다" 를 오히려 강하게 만든다고
   봤지만, 원본의 결정과는 다른 쪽이다.
3. **밀랍 구슬이 크림색이 아니다.** 팔레트에 밀랍색이 없어 `muted`(짙게)로 둔다. 막대와
   같은 역할(물건)이되 짙어서 낙하 사건이 눈에 띈다.
4. **바닥에 쌓인 구슬에 테두리가 없다.** 납작한 타원은 `body` `custom` 인데 그 외형은
   채움만 하고 윤곽선을 긋지 않는다. 붙어 있는·떨어지는 구슬(`circle`)에는 테두리가
   있어서 셋의 결이 조금 다르다.
5. **서브스텝을 안정조건에서 뽑는다.** 원본은 12 를 손으로 계산해 박았다. 지금은
   `α·dt/dx² ≤ 0.45` 를 지키는 최소 수를 구하고, **가장 빠른 막대(쇠)가 정한 수를 두
   막대가 함께 쓴다** — 막대마다 따로 잡으면 적분기가 둘이 되어 "같은 코드로 돌았다" 는
   이 조각의 산출물이 깨진다. 1/60 걸음에서 12 가 나와 원본과 같은 값이다.
6. **프리롤 횟수.** 원본 NOTES 는 "advance 를 540번" 이라고 적었지만 실제 코드는
   `round(30 / 40 / (1/60))` = **45 프레임**이다. `schema.preroll` 은 화면 시간이라
   `30 / 40 = 0.75` 초로 선언했고 러너가 같은 45 걸음을 굴린다.
7. **바탕이 흰색이 아니다.** 원본은 `#ffffff` 를 직접 칠했다. 엔진에서는 테마 배경이다.
8. **화면 비율이 고정이 아니다.** 원본은 860 × 276 캔버스 한 장이었다. 여기서는
   `boundsHint` 가 그 배치를 월드로 옮긴 고정 경계를 주고(100 px = 월드 1), 카메라가
   임베드 폭에 맞춘다. 굵기·글자 크기는 화면 px 라 배율을 따라가지 않으므로 좁은
   임베드에서는 원본보다 조금 굵게 보인다.
9. **도착 순간 쇠막대 구슬 하나가 아직 공중에 있다.** 원본 스크린샷(t=0)은 바닥에
   납작한 구슬 **둘**을 보이는데, 이관본은 하나가 바닥이고 하나가 떨어지는 중이다.
   원본은 프리롤 루프를 돈 **뒤에** 이미 떨어진 구슬을 바닥으로 내려놓는 줄을 따로
   두었다 — `if (released) { y = FLOOR; vy = 0 }`. `schema.preroll` 은 `step` 을 굴리기만
   하므로, 프리롤이 끝나기 직전(낙하에 걸리는 0.34 초 안)에 촉발된 구슬은 공중에 남는다.
   0.2 초쯤 뒤 바닥에 닿고 그 뒤로는 원본과 같다. 아래 「어휘 부족」 4번이다.

## 화면에 없는 것 (원본의 결정을 그대로 지킨다)

축과 눈금자 · 온도 범례와 컬러바 · 재생 버튼 · 조작기 전부 · 막대 위 온도 수치.
특히 **범례와 컬러바를 두지 않는다** — 색은 "얼마나 뜨거운가" 를 재라고 있는 것이 아니라
"어디까지 왔는가" 를 보라고 있고, 정확한 문턱 하나(60 ℃)는 구슬이 말한다. 구슬이 15 mm
마다 박혀 있어 그 자체가 자이므로 눈금도 긋지 않는다.

## 어휘 부족

1. **`CaptionSlotDef` 에 `vars` 가 없다.** 캡션이 상태에서 나온 수를 말할 수 없다.
   `Readout` 에는 `vars` 가 있는데 캡션 슬롯에는 없어서, 값이 들어가는 캡션을 쓰려면
   슬롯을 버리고 `readout` 을 따로 놓는 수밖에 없다 — 그건 캡션이 둘이 되는 길이다.
   이 조각의 원본 캡션은 "지난 시간 + 두 막대의 앞머리 거리" 였고, 그 값이 화면의 앞머리
   선과 **같은 배열에서 나온다는 것**이 원본이 지킨 보증이었다. 지금은 그 보증을 말로만
   한다.
2. **`body` 의 `custom` 외형에 윤곽선이 없다.** 채움만 한다. 옅은 색 물체를 `custom` 으로
   그리면 배경에 묻힌다 — 이 조각은 쌓인 구슬을 짙게 칠해 피했지만, 원본처럼 "옅은 채움 +
   가는 테두리" 인 물체는 `circle` 말고는 낼 수 없다.
3. **`colorRole` 로 재질을 말할 수 없다.** 역할은 의미(주 대상 · 강조 · 배경)로 갈려
   있어서 "이것은 쇠고 저것은 나무다" 를 색으로 구분하려면 뜻이 다른 역할을 빌려 써야
   한다. 빌리는 순간 강조색이 두 가지 뜻을 갖는다.
4. **`preroll` 은 굴리기만 하고 가라앉히지 않는다.** "도착한 순간 이미 진행 중" 에는
   "그때까지 끝난 일은 끝나 있다" 가 딸려 온다 — 원본이 프리롤 뒤에 구슬을 바닥으로
   내려놓은 것이 그것이다. 지금은 프리롤이 끝나는 순간의 **과도 상태가 그대로 첫
   화면**이 되어, 막 촉발된 구슬이 공중에 뜬 채로 독자를 맞는다. 조각이 손으로 고치려면
   `initialState` 가 아니라 프리롤 **뒤**에 끼어들 자리가 필요한데 그 자리가 없다.
   (위 「원본과 달라진 것」 9번.)
5. **장(field)을 칠하는 일이 인스턴스 240개가 된다.** 격자 한 칸이 `region` 하나라
   막대 둘에 240개를 매 프레임 선언한다. `scalarField` 같은 기성품을 원하는 것이 **아니다**
   — 그런 것이 컬러바를 달고 오면 이 조각은 망가진다. 다만 "같은 모양을 배열로 여럿"
   이라는 꼴은 `trace.marks` 처럼 한 인스턴스가 목록을 받는 쪽이 선언에 가깝다.

## 대조 한계

`apps/catalog/src/data/catalog.json` 에 `thermal-conduction` 주제가 없어서
(`thermal-conduction` 이라는 다른 id 의 주제만 있고 `simId` 가 비어 있다)
`pnpm piece:report --sims` 가 정식 sims 스크린샷을 찍지 못한다 — `simIdOf` 가 주제를
못 찾으면 조용히 건너뛴다. 카탈로그 연결은 이 작업의 범위 밖이라(공유 파일) 손대지 않았다.
그래서 **화면 대조는 수치로만 했다** (위 「물리가 원본과 같은지」).
