# statistical-fluctuation — 요동

자유 구현 원본이 없다. 엔진 어휘로 곧바로 지었다.
쓴 어휘: `trajectory`(닫힌 사각 · 파선 · 점선 · 이력 곡선 · 선 모양 토막) · `particleSystem` · `trace`(dot) · `readout`(vars)
+ `timeline` · 캡션 슬롯(`vars`). 자유 렌더 없음, 조작기 없음.

## (a) 답하는 질문과 동사

**질문** — 고르게 섞인 기체도 흔들리는가, 얼마나 흔들리는가.

**동사** — *(적으면) 널뛴다 / (많으면) 붙어 있다.*

입자 10 · 100 · 1000 개가 든 상자 셋이 왼쪽에 세로로 쌓여 있고, 입자는 처음부터 상자 전체에 고르게 퍼져
움직인다. 오른쪽 **한 축** 그래프가 상자마다 가운데 점선 왼쪽에 든 몫을 시간에 따라 긋는다 — N = 10 곡선(실선)은
50% 선 위아래로 10% ~ 80% 까지 계단처럼 널뛰고, N = 100(파선)은 그보다 좁게, N = 1000(점선)은 50% 선에 거의
붙어 있다. 「흔들림이 입자 수에 따라 줄어든다」 는 수가 아니라 **같은 축 위 세 곡선의 폭 차이**로 보인다.

- 입자는 벽에서만 튄다. 자리는 처음 자리 · 속도와 시각의 닫힌 식이라 `step` 에 쌓지 않는다.
- 곡선은 매 프레임 `draw` 시작부터 지금까지 0.1 초 간격으로 왼쪽 몫을 다시 센다 — 같은 시각은 같은 곡선이다.
- 주기 끝에서 곡선 · 입자가 흐려지고(`fade`) 다음 주기에 새로 자란다.

## (b) 화면 구성의 결정 — 두지 않은 것 포함

- **상자 기둥 + 그래프를 가로로.** 상자만 보면 1000 개 상자가 「고르다」 까지만 보이고 흔들림의 크기는 시간을
  모아야 보인다. 그래프 100% 높이가 쌓은 상자 셋의 높이와 같아 그림 전체가 한 덩이로 읽힌다.
- **곡선 셋을 한 축에.** 칸을 셋으로 나누면 눈이 세 칸의 폭을 따로 재야 한다. 한 축이면 50% 선 둘레의 폭이
  바로 견줘진다 (투입 문구).
- **곡선은 색이 아니라 선 모양으로 가른다** — 실선 · 파선 · 점선, 모두 먹색 (S-piece). 가장 크게 뛰는 N = 10 이
  실선이라 뛰는 모양이 끊기지 않고, 거의 평평한 N = 1000 이 점선이다. 점선은 50% 선 위에서 묻혀 굵기를 2.4 px 로 올렸다.
- **곡선 머리 N 표식 앞에 그 곡선의 선 모양 토막을 둔다.** 1차 촬영에서 머리 셋이 50% 둘레에 몰리면 표식을 세로로
  벌려도 어느 것이 어느 곡선인지 읽히지 않았다. 토막은 떨어진 범례가 아니라 곡선 머리에 붙는 표식의 일부다.
- **% 는 축 눈금(0 · 50 · 100%)에만.** 지금 값 글자는 띄우지 않는다 — 머리 점의 높이가 그 값이다 (투입 문구).
  1/√N · 표준편차 · 확률은 두지 않는다. 문단의 몫이다.
- **입자 점 크기가 상자마다 다르다**(3 · 2 · 1.1 px). 같은 크기면 N = 1000 상자가 한 덩이로 메워져 움직임이 안 보인다.
  크기는 물리량이 아니고 색은 셋 모두 같은 `primary` 다.
- **강조색은 곡선 머리 점(지금 몫) 한 뜻에만.**
- **퍼짐(칸막이 걷기)은 하지 않는다** — 이웃 `second-law-of-thermodynamics` 의 몫이다. 이 조각의 입자는 처음부터 고르다.
- **입자끼리 부딪히지 않는다.** 주장(흔들림의 크기가 N 에 달렸다)은 충돌 없이도 서고, 닫힌 식이면 시각만으로 같은 화면이다.
- **조작기 없음.** 입자 수를 끌게 하면 캡션의 참 보장이 시드 하나로 되지 않는다. 입자 수 셋은 스테이지 상수라
  저작자가 바꿀 수 있다.
- **캡션 참 보장** — 시드 2 · 척도 0.5 에서 `compare`(주기 4.4 ~ 13.4 초) 동안 N = 10 몫은 10% ~ 80%, N = 1000 몫은
  47.6% ~ 51.3% 다(모의 확인, 시드 1~12 를 견줘 골랐다). 결과가 시드로 고정이라 모든 주기에서 「N = 10 곡선은 크게 널뛰고,
  N = 1000 곡선은 거의 붙어 있다」 가 참이다. 시드를 바꾸면 촬영으로 다시 본다(schema 주석).
- `startAt: 2.4` — 도착한 순간 입자가 움직이고 곡선이 2 초쯤 자라 있다. 쌓는 상태가 없어 `preroll` 은 쓰지 않는다.
- 그래프 자리(`GRAPH`) · 경계(`SCENE_BOUNDS`) · 상자 틈(`BOX_GAP`)은 기본 상자 크기(1.2 × 0.62)에 맞춘 고정값이다.
  저작자가 상자를 키우면 그래프와 겹친다 — 원칙 6 에 따라 경계를 상수로 계산하지 않았다.

## (c) 어휘 부족

**주장 부족 없음.** 근사한 곳은 모두 모양의 문제다.

| 장부 | 이 조각에서 |
| --- | --- |
| G203 | 월드에 놓이는 x–y 선 그래프가 없다 — 축 · 50% 선 · 곡선 셋 · 지금 점을 `trajectory` · `trace` 로 조립하고 좌표 사상을 scene 이 한다 |
| G131 | 흐르는 이력 곡선이 없어 매 프레임 표본(곡선마다 최대 130 점 × 입자 1110 개 세기)을 scene 이 다시 계산한다 |
| G47 | 축 어휘가 없다 — % 눈금 셋과 축 이름을 `readout` 으로 손수 붙였다 |
| G111 | 선 끝 이름표 자리 규칙이 없다 — 머리 셋이 몰릴 때 N 표식이 겹쳐 scene 이 세로로 벌리는 배치(`spreadLabels`)를 한다 |
| G133 | 캡션 `{a}` · `{c}` 와 이름표 `{n}` 을 스테이지 상수에서 끼우려고 `initialState` 가 입자 수 글자를 state 에 둔다 |
| G24 | 캡션 슬롯 자리가 프레이밍 여백에 잡히지 않아 `SCENE_BOUNDS` 아래(−0.62)를 손으로 비웠다 |

## (d) 주장이 화면에서 서는가

`pnpm -s piece:report --sims=http://localhost:5173/aperi21/ statistical-fluctuation` 촬영본을 라이트 · 다크 모두 직접 열어
확인했다 (2026-09-19). `?t=` 는 `startAt`(2.4) 에서부터 흐른 시간이다.

| t(초) | 라이트 · 다크 |
| --- | --- |
| 0.5 | 상자 셋에 입자가 고르게 퍼져 움직이고, 곡선 셋이 2 초쯤 자라 있다. 실선은 이미 30% 아래로 내려갔다가 돌아왔다. 캡션 「입자 10개 · 100개 · 1000개」 |
| 3 | 견주기 캡션. 실선이 20% 와 80% 를 찍었고, 파선은 40~60%, 점선은 50% 선을 따라 평평하다 |
| 7 | 곡선이 가로 절반을 넘었다. 실선은 10% 까지 내려갔고 지금 70% 위, 점선은 50% 선에 붙어 있다 |
| 10.5 | 곡선 셋이 가로축 끝 가까이까지 쌓였다. 폭이 실선 > 파선 > 점선으로 뚜렷이 줄어든다. 머리 셋이 50% 에 몰렸어도 토막으로 가려진다 |

- **다크** — 상자 · 곡선 · 표식이 밝은 먹색으로 뒤집히고 입자는 붉은 `primary`, 머리 점은 금빛 강조색으로 남는다.
  점선(2.4 px)이 50% 선과 갈린다.
- **라이트** — 글자 · 표식 겹침, 화면 밖으로 나간 것 없음. `N = 1000` 표식이 50% 선 위에 놓일 때 선이 글자를 지나가지만 읽힌다.
- 1차 촬영에서 고친 것 — 머리 셋이 50% 에 몰리면 N 표식만으로는 어느 곡선인지 모호해 선 모양 토막을 붙였고,
  점선 곡선이 50% 선에 묻혀 굵기를 1.6 → 2.4 px 로 올렸다.
