# 포물선 운동 — 수평·연직의 독립

> 원본: `tasks/piece-lab/projectile-motion/` (자유 구현). 이 패키지는 그것을 엔진 어휘로
> 옮긴 것이다. 자유 렌더(`Bundle.renderers`)를 쓰지 않는다.

## 한 주장

앞으로 얼마나 빨리 던졌든 세 공은 매 순간 같은 높이에 있고 한꺼번에 바닥에 닿는다.
동사는 **나란히 내려와 한꺼번에 닿는다**.

주장은 물체 목록에 없다. 세 공을 꿰는 선이 수평이라는 **관계**가 화면의 주인공이고,
그래서 그 선은 제 몫의 선언(두 점짜리 `trajectory`)으로 나온다.

## 쓴 어휘

| 원본의 요소 | 어휘 |
| --- | --- |
| 지면 | `surface` (`geometry.kind: 'ground'`) |
| 공 셋 | `body` × 3 — `shape: 'circle'` · `fill: 'solid'` · `outline: 'none'` · `glow: false` |
| 지금 높이선 | `trajectory` (2점 · `width: 2` · `accent`) |
| 지나간 높이선(사다리 가로대) | `trajectory` × 스트로브 시각 수 (`width: 1` · `opacity: 0.2`) |
| 잔상 | `trace` (`shape: 'dot'` · `age` 생략 — 늙지 않는다) |
| 착지 파문 | `trace` (`shape: 'ring'` · `arc: [0, π]` · `spreadTo` · `life`) |
| 사이클(낙하 → 머묾) | `BundleSchema.timeline` 두 단계 |
| 도착한 순간 이미 진행 중 | `BundleSchema.startAt: 0.7` |
| 캡션 한 줄 | `BundleSchema.caption` 슬롯 + 단계마다의 `caption` 키 |
| 빠르기 손잡이 | `slider` + `ControllerInstance.heldPath` |
| 겹침 순서 | `BundleSchema.drawOrder: 'scene'` |

`dimension` 을 쓰지 않았다 — 점선 + 끝점 원 + 얇은 선이 고정이라 "꿰는 굵은 선" 이
되지 않는다. 이 그림은 치수를 재는 그림이 아니다.

## 원본과 달라진 점

1. **좌표.** 원본은 화면 픽셀에서 g 를 역산해 썼다(`G = 2(GROUND − R − Y0)/T_FALL²`
   = 109.5 px/s²). 같은 배치를 100 으로 나눈 월드로 옮기고(발사점이 원점, 지면 y = 0)
   화면으로 옮기는 일은 카메라에 맡겼다. `G = 1.095`, 공은 여전히 정확히 2.0 초에
   닿는다. 프레이밍(`boundsHint`)은 원본 캔버스 828 × 282 를 그대로 옮긴 고정 직사각형이라
   가로세로비가 같은 임베드에서는 1 월드 = 100 px 로 원본과 같은 배율이 된다.

2. **손잡이를 만졌을 때.** 원본은 슬라이더 입력마다 `phase` 를 0 으로 되돌리고 잔상을
   비웠다 — 다시 던진다. 시간표를 선언으로 올린 지금 시계는 엔진이 쥐고 있어 조각이
   되돌릴 수 없다(아래 「어휘 부족」). 옮길 수 있는 절반만 옮겼다: **잡고 있는 동안
   사다리의 기록을 비운다**(`heldPath: 'held'` → `scene` 이 읽는다). 공과 지금 높이선은
   계속 날며 새 빠르기에 바로 반응하므로 독자의 시험은 그대로 성립하고, 지나간
   가로대가 새 빠르기로 다시 그려져 있던 적 없는 과거를 주장하는 일은 일어나지 않는다.

3. **지면의 모양.** 원본은 캔버스 좌우 18 px 를 남긴 1.5 px 직선이다. 엔진의
   `surface`/`ground` 는 같은 굵기(`strokeWidth.regular` = 1.5)로 화면 전폭을 긋고
   **아래쪽에 옅은 칠(0.15)을 깐다.** 그 칠은 원본에 없다.

4. **슬라이더가 값을 보여 준다.** 엔진의 슬라이더는 라벨 옆에 항상 숫자를 찍는다.
   원본은 손잡이 값(0~100)을 화면에 두지 않았다 — 이 조각은 "얼마나" 가 아니라
   "같다" 를 말하므로 수치를 전부 뺐었다(`inventory.hidden`).

5. **세로.** 원본은 캡션과 손잡이를 캔버스 **아래** 한 줄에 놓아 282 px 로 끝났다.
   엔진은 둘을 캔버스 안에 그리므로 그 한 줄만큼(54 px)을 높이에 더해 336 으로 뒀다.

6. **색.** 원본의 강조색은 붉은색(#d4483b), 공은 먹색(#2b2b33)이었다. 여기서는 뜻만
   옮긴다 — 높이·동시성은 `accent`, 공과 잔상은 `ink`. 실제 색은 테마가 정한다 (C2).

## 화면에 두지 않은 것

원본의 판단을 그대로 잇는다 — 속도 벡터 분해 화살표, 포물선 곡선, 경과 시간·속도·도달
거리 수치, 그리드·축·눈금, 제목·범례. 이유는 원본 NOTES 「(c) 두지 않은 것」에 있다.
요약하면 셋 다 같은 대상이라 이름이 필요 없고, 읽어야 할 것은 "선이 수평이다" 하나다.

## 어휘 부족

이관에서 어휘에 닿지 않아 근사하거나 포기한 것. 다음 엔진 작업의 입력이다.

1. **조작기가 시간표를 되돌리는 것.** `TimelineDef` 는 시각의 함수라 조각이 주기를
   다시 시작시킬 수 없다. "만지면 다시 던진다" 는 이 조각(과 원본 `engineWish` 의
   사이클 항목)이 요구한 규약인데, 지금은 `heldPath` 로 *기록을 비우는* 것까지만 된다.
   필요한 모양: 선언이 가리키는 상태 경로가 참이 될 때 주기를 0 으로 되돌리는 것
   (`timeline.restartWhen` 같은 자리). 상태로 주기를 도는 쪽(`ramp-energy`)으로 가면
   되돌릴 수는 있으나 시간표 선언을 통째로 포기하게 된다.

2. **값을 감춘 슬라이더.** `slider` 는 언제나 `value.toFixed(2)` 를 찍는다. 값이 물리량이
   아니라 "더 빠르게/느리게" 인 조각은 숫자가 나오는 순간 읽을 것이 둘이 된다.
   필요한 모양: 인스턴스가 값 표시를 끄는 선언(`showValue: false` 같은 자리).

3. **화면 폭에 맞춘 조작기 상한.** 원본은 `vmax = (W − X0 − 42)/(2·T_FALL)` 로 "가장 빠른
   공이 화면 안에 들어오는 최대값" 을 폭에서 계산했다. 고정 프레이밍을 쓰는 지금은
   고정값(1.82)으로 충분하지만, 상한이 배치에서 나오는 요구는 조각마다 되풀이된다.

4. **같은 종류의 인스턴스 여럿.** 수평 속도 배수만 다른 공이 셋인데 `scene` 이 배열을
   돌며 `body` 를 세 번 낸다. 넷으로 늘리는 것은 `MULTIPLIERS` 한 줄이라 원본보다는
   낫지만, 여전히 코드의 배열이지 편집 가능한 선언은 아니다 (원칙 7).

5. **지면의 아래쪽 칠.** `surface`/`ground` 는 선과 칠이 한 벌이라 선만 쓸 수 없다.
   무대로서의 지면만 필요한 조각이 그 칠을 끄지 못한다.
