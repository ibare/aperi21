# 상대 속도 — 이관 노트

원본: `tasks/piece-lab/relative-velocity/`(자유 구현). 이 문서는 **엔진 위로 옮기면서
달라진 것**과 **어휘로 되지 않아 근사한 것**만 적는다. 조각 자체의 논증은 원본
`NOTES.md` 에 있다.

## 쓴 어휘

| 원본이 손으로 그리던 것 | 옮긴 어휘 |
| --- | --- |
| 강물 띠 · 위아래 땅 띠 | `region` ×3 (`opaque` · `outline` 로 물가 경계선) |
| 물거품 150개 | `trace` (`shape: 'tick'`, `direction: [1, 0]`) |
| 자갈 90개 | `particleSystem` (`sizes` 로 알갱이마다 다른 반지름) |
| 선착장 말뚝 | `body` (`shape: 'rect'`) |
| 지나온 길 · 사라지는 자취 | `trajectory` (`width` · `opacity`) |
| 시간 자국 | `trace` (`shape: 'dot'`, 나이 없음 — 늙지 않는다) |
| 배 | `body` (`shape: 'custom'` + `customPath`, `outline: 'background'`) |
| 캡션 한 줄 | `BundleSchema.caption` 슬롯 (`cases` — 값으로 갈린다) |
| 슬라이더 · 자동/수동 인계 | `slider` + `ControllerInstance.heldPath` |
| 2.7 초 미리 돌리기 | `BundleSchema.preroll` |
| 14 초 자동 순회 | `BundleSchema.timeline` (`FRAME_TOUR` 한 표) |

## `plugin-mechanics` 의 순수 계산

원본 「다시 짜기 아까웠던 것」 1·2·3 이 그대로 함수가 되어 들어왔다.

| 원본이 손으로 짠 것 | 쓴 함수 |
| --- | --- |
| `screenPast(xm, ti, t)` — 전단항 `u·(t − tᵢ)` | `eventInFrame` |
| `screenNow(xm)` — `x − Xobs` | `positionInFrame` |
| `Xobs += u*dt` | `advanceObserver` (+ `observerAtRest`) |
| `eachWrapped()` — 세 번 다시 짠 감기 | `tiledPositions` |

**변환이 이름으로 갈려 있는 것이 이 조각에는 특히 중요하다.** 전단항을 빠뜨리면
궤적만 안 기우는데 예외도 안 나고 타입도 통과한다. 이름이 둘이면 그 자리에서
"지금 있는 것인가 지나간 사건인가" 를 고르게 되어 조용히 틀릴 길이 좁아진다.

`ObserverFrame` 이 `at` · `velocity` · `t` 를 한 덩어리로 들고 다니므로 조각의
상태에서 `Xobs` · `u` · `curT` 세 변수가 사라졌고, "`u` 를 바꿨는데 `Xobs` 는 안
바꿨다" 같은 어긋남이 생길 자리가 없다.

## (a) 원본과 달라진 점

1. **조작기가 캔버스 안으로 들어왔다.** 원본은 캔버스 **아래** HTML 한 줄이었다.
   엔진의 조작기는 화면에 얹히므로 오른쪽 아래에 자리를 선언했다(`at`). 자리를
   선언한 조작기는 카메라가 프레이밍을 비우지 않아 그림이 밀리지 않는다.
2. **캡션에서 숫자가 빠졌다.** 원본은 "강물보다 빠른 **1.6 m/s** 로 떠내려가며
   본다" 처럼 값을 문장에 끼웠다. 캡션 슬롯은 `vars` 를 받지 않는다(아래
   「어휘 부족」). 지금 값은 슬라이더가 읽어 준다 — 다만 소수 **두** 자리다.
   원본 옆줄의 힌트("강물은 1.2 m/s")는 조작기 이름표에 접어 넣었다.
3. **물거품의 길이와 진하기가 한 값으로 묶였다.** 원본은 둘을 따로 뽑았다.
   `trace` 가 자국마다 줄 수 있는 것은 `strength` 하나뿐이고 그것이 크기와
   진하기에 함께 걸린다. 진하기 쪽 난수를 살리고 길이 쪽은 버렸다 — 옅은 것이
   짧고 진한 것이 긴 결이 된다.
4. **강물에 세로 그라데이션이 없다.** 원본은 가장자리를 조금 짙게 칠했다.
   `region` 은 한 색으로 채운다.
5. **선착장의 되풀이 주기가 60 m → 12 m 다.** 원본은 말뚝 5개를 60 m 로 감았고,
   60 = 12 × 5 라 **나오는 자리가 한 치도 다르지 않다.** 한 줄로 줄었을 뿐이다.
6. **배 테두리 굵기가 1.6 → 테마의 가는 선(1)이다.** `body` 에 테두리 굵기를
   선언할 자리가 없다. 색은 그대로 바탕색(`outline: 'background'`)이다.
7. **첫 자취 점이 한 프레임 뒤에 찍힌다.** 원본은 프리롤 첫 호출을 `tau = 0` 에서
   했고 엔진 프리롤은 `dt` 를 한 번 전진시킨 뒤 부른다. 0.027 m(≈0.6 px) 차이다.
8. **색이 역할로 바뀌었다.** 배·궤적·자국은 `primary`(테마의 붉은색 — 원본 강조색과
   같은 뜻: *배와 배가 남긴 것*), 물은 `secondary`, 땅·말뚝·자갈·거품은 `muted` 다.
   원본의 흙빛/물빛 그대로는 아니지만 **한 대상이 한 색** 이라는 규칙은 지켜진다.

달라지지 **않은** 것 중 확인해 둘 것 — 물거품·자갈의 흩어진 자리가 원본과 한 알도
다르지 않다. 원본 하네스와 같은 생성기(mulberry32)를 같은 시드(1)로 같은 순서로
뽑는다.

## (b) 어휘 부족

다음 엔진 작업의 입력이다. 순서는 이 조각에서 아쉬웠던 순이다.

1. **`step` 이 시간표를 보지 못한다.** 엔진은 `TimelineFrame` 을 `scene` 에만 준다.
   그런데 이 조각의 관측자 위치는 **적분**이라(`Xobs += u·dt`) 매 프레임 `step` 이
   지금 기준틀 속도를 알아야 하고, 그 값은 시간표가 정한다. 그래서 단계 표
   (`FRAME_TOUR`)를 physics 가 직접 읽고 이징을 다시 짰다 — 경계 상수를 코드에
   옮겨 적지는 않았지만(같은 표가 `schema.timeline` 이다) `smoothstep` 은 두 벌이 됐다.
   **시간표가 상태를 밀어야 하는 조각은 이 조각만이 아닐 것이다.**
2. **시간표를 되감거나 위상을 옮길 수 없다.** 이 조각은 "손을 뗀 자리에서 순회를
   이어 간다" 를 위해 이징의 **역함수**로 위상을 되찾아 시간표를 통째로 민다.
   엔진 시간표는 절대 시각의 함수라 그 일을 할 수 없다. 조작기를 두는 조각마다
   다시 나올 문제다(원본도 그렇게 적었다).
3. **캡션 슬롯이 값을 끼우지 못한다.** `Readout` 에는 `vars` 가 있는데
   `CaptionSlotDef` 에는 없다. `cases` 는 문안 키만 고른다. 그래서 "지금 몇 m/s 로
   보는 중인가" 가 캡션에서 빠졌다. 캡션이 지금 화면의 값을 말해야 하는 조각은
   흔할 것이다.
4. **`trace` 가 자국마다 크기를 못 준다.** `strength` 가 크기와 진하기에 함께 걸린다.
   길이와 진하기가 각각 다른 것을 말하는 자국(물거품 = 물결의 결과 밝기)은 둘을
   따로 줘야 한다. `particleSystem` 은 `sizes` 로 알갱이마다 크기를 주는데 `trace` 만
   없다.
5. **바탕색으로 채우는 것을 말할 길이 없다.** `body.outline: 'background'` 는 **선**
   뿐이다. 배 위의 종이색 칸은 `luminance: 0`(빛의 양 0 = 바탕색)으로 우회했다.
   물거품의 흰색도 같은 성질이라 `luminance: 0.12` 로 바탕 쪽으로 끌어 놓았다.
   `colorRole: 'background'` 하나면 둘 다 우회가 아니게 된다.
6. **띠에 그라데이션이 없다.** `region` 은 한 색이다. 물의 가장자리가 짙어지는
   것처럼 **면 안에서 변하는 것**을 말할 자리가 없다.
7. **`body` 에 선 굵기가 없다.** `trajectory` · `vector` · `trace` · `sector` 에는
   `width` 가 있는데 `body` 만 없다. 테두리가 주장의 일부인 물체(바탕색 테두리를
   두른 배)는 굵기를 고르지 못한다.

## (c) 화면에 두지 않은 것

원본의 판단을 그대로 이어받았다. 속도 화살(등속이라 궤적의 접선과 겹친다) ·
격자와 축("어느 격자가 진짜인가" 가 이 조각의 물음이라 좌표 눈금이 그 물음을
지운다) · 건너는 시간 5.0 초(어느 기준틀에서나 같아 보탤 것이 없다) · 떠내려간
거리 6.0 m(강둑 기준틀에서만 뜻이 있는 값이라 숫자로 쓰면 기준틀과 무관한
사실처럼 읽힌다 — 궤적의 가로 폭이 그 값이다).

`ghost` 는 자취만 남긴다. 원본은 자국도 함께 담아 두었지만 그리지는 않았다.
