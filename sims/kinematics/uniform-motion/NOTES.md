# 등속 운동 — 같은 시간에 같은 간격

원본: `tasks/piece-lab/uniform-motion/` (자유 구현). 이 패키지는 그것을 엔진 어휘로
옮긴 것이다. 자유 렌더 계층(`Bundle.renderers`)을 쓰지 않는다.

동사: **같은 간격으로 찍힌다.**

## 쓴 어휘

| 원본의 것 | 어휘 |
| --- | --- |
| 바닥 (가로선 하나) | `trajectory` — 점 둘, `width` 1.5, `muted`·`subtle` |
| 가는 것 (동그란 물체) | `body` `circle`, `glow: false`, `outline: 'none'` |
| 걸음 막대 (쌓이는 가로 막대) | `body` `rect`, `fill: 'solid'` + `outline: 'none'` |
| 자국 (1초마다의 세로 눈금) | `trace` `shape: 'tick'` + `direction` |
| 방금 찍힌 자국 (강조색) | `trace` 인스턴스 하나 더 — 색은 인스턴스 단위다 |
| 바닥 아래로 퍼지는 반원 파동 | `trace` `shape: 'ring'` + `arc: [-π, 0]` + `spreadTo` + `life` |
| 캡션 한 줄 | `BundleSchema.caption` 슬롯 (`text`) |
| 빠르기 슬라이더 | `slider` + `ControllerInstance.heldPath` |
| 도착한 순간 이미 세 걸음째 | `BundleSchema.preroll: 3.05` |
| 바닥 → 막대 → 자국 → 물체 겹침 | `BundleSchema.drawOrder: 'scene'` |

## 원본과 달라진 점

1. **캔버스 세로 214 → 250.** 원본은 캡션과 조작기 줄을 캔버스 **밖** DOM 에 두었고,
   엔진은 둘을 캔버스 **위**에 얹는다. 그림 자체의 세로 예산(바닥선 위 물체 한 층,
   아래 자국, 그 아래 막대 6줄 = 월드 140)은 원본 그대로다.
2. **세로도 폭을 따라 줄어든다.** 원본은 세로가 px 고정이고 가로만 폭에 비례했다.
   월드로 옮기면 배율 하나가 두 축에 함께 걸린다 — 원본 NOTES (d) 4 가 바라던 쪽이다.
3. **슬라이더가 오른쪽 아래 오버레이.** 원본은 캔버스 아래 왼쪽의 DOM 줄이었다.
   왼쪽 아래는 쌓인 막대와 캡션의 자리라 비워 둔다.
4. **슬라이더에 빠르기 값이 뜬다.** 코어 슬라이더가 언제나 값을 찍는다 (「어휘 부족」 5).
   원본은 숫자를 한 글자도 띄우지 않았다.
5. **색이 역할색으로 옮겨졌다.** 원본의 짙은 청록 = `primary`, 주황 = `accent`,
   바닥선 = `muted`·`subtle`. 물체·자국·막대가 모두 같은 역할색이고 막대만 emphasis 가
   한 단계 옅다 — 원본의 `INK` / `INK_SOFT` 관계를 그대로 옮긴 것이다. 셋은 서로 다른
   무엇이 아니라 같은 한 물체가 남긴 것이다.
6. **빠르기를 잡고 있는 동안 랩이 0 에 머문다.** 원본은 `input` 이벤트마다 `lapT = 0`
   이라 **값이 바뀌는 동안만** 머물렀다. 손잡이를 쥔 채 멈춰 있으면 원본은 랩이 흐르고
   이쪽은 멈춰 있다. 잡혔다는 사실을 러너가 적어 주므로(`heldPath`) 이쪽이 "옛 간격과
   새 간격이 한 줄에 섞이지 않게" 를 더 곧게 지킨다.
7. **`timeline` 을 선언하지 않았다.** 아래 「어휘 부족」 1.

## 어휘 부족

다음 엔진 작업의 입력이다.

1. **되돌릴 수 있는 랩 시계가 없다.** `BundleSchema.timeline` 은 임베드 시계의 순수
   함수라 조각이 되돌릴 방법이 없는데, 이 조각의 랩은 **독자가 되돌린다** — 빠르기를
   잡으면 처음으로 돌아간다. 그래서 시간표를 쓰지 못하고 `state.lapT` 를 쌓았고,
   그 결과 시간표로 선언했을 것들이 `physics.ts` 코드에 남았다.
   - 구간 막대의 시차 출발 — 구간 k 가 k+1 초에 떠나 0.5 초에 걸쳐 내려간다.
     `timeline.span(from, to, ease)` 가 정확히 이 자리를 위한 것이다.
   - 랩 경계의 흐려짐 (0.28 초 밝아짐 · 6.62 초부터 0.38 초 저묾).
   - 이징 `easeOut`(cubic-out). `TimelineEase` 에도 없는 곡선이다.

   S-piece 「시간표는 선언이다」 를 지키지 못한 자리이고, 원본 `inventory.json` 의
   engineWish 1·5 가 가리키던 것과 같다. 필요한 것은 *주기 · 초기 위상 · 경계 페이드 ·
   **무엇을 리셋하는가 는 조각이 정하는** 리셋* 을 묶은 랩 시계다.

2. **`Trace.marks[].strength` 가 크기와 진하기를 한 값에 묶는다.** 원본은 방금 찍힌
   자국을 **길게만** 한다 (16 → 24px). 진하기는 그대로다. `strength` 로 길이를 키우면
   알파가 1 을 넘고, 알파를 맞추면 길이가 줄어든다. 그래서 길이는 인스턴스의 `size` 로
   주고 자국 하나짜리 인스턴스를 따로 냈다. 「크기만」과 「진하기만」이 갈라져야 한다.

3. **`shape: 'tick'` 이 자리를 중심으로 대칭이다.** 원본의 자국은 바닥선 위 3px,
   아래 13(+8)px 로 **한쪽으로 치우친** 획이다. 중심을 아래로 내리고 길이를 늘려 같은
   그림을 만들었지만, 그러면 "바닥선에서 아래로 뻗는다" 는 뜻이 좌표 계산 속에 숨는다.
   기준선에 걸리는 눈금은 흔한 쓰임이라 `anchor: 'start' | 'center'` 같은 갈래가 있으면
   자국의 뿌리를 바닥선에 직접 묶을 수 있다.

4. **`Trace` 의 크기가 화면 px 라 배율을 따라가지 않는다.** 자국 길이와 파동 반지름은
   원본에서 바닥선·물체와 **같은 자**로 잰 값인데, 어휘는 화면 px 다. 컨테이너가
   좁아지면 물체·막대만 줄고 자국은 그대로 남아 비례가 어긋난다.

5. **값을 숨기는 슬라이더가 없다.** 코어 슬라이더는 언제나 `value.toFixed(2)` 를 찍는다.
   이 조각은 숫자를 한 글자도 띄우지 않기로 했고 빠르기의 수치는 주장과 무관하다.
   원본은 양 끝에 「느리게 ↔ 빠르게」 두 이름표를 두었는데 어휘는 이름표가 하나다.

6. **조각 전체를 한 번에 흐리게 하는 자리가 없다.** 랩 경계의 페이드는 그림 전체에
   한 번 걸리는 일인데, 지금은 선언 여섯에 `lap.alpha` 를 각각 곱해 넣는다. 하나를
   빠뜨려도 타입이 통과하고 그 하나만 랩 경계에서 남는다.

## 화면에 두지 않은 것 (S-piece — 화면에 없는 것도 결정이다)

- **속도 값과 이동 거리 값.** 계산은 되지만 두지 않는다. 숫자를 띄우면 「같음」을 눈이
  아니라 숫자로 읽게 되고, 동사가 화면에서 사라진다.
- **경과 시간 표시.** 1초 박자는 자국이 찍히는 반짝임이 말한다. 초시계를 두면 볼 것이
  하나 늘 뿐이다.
- **눈금자·격자.** 같은 길이인지는 쌓인 막대의 오른쪽 끝이 한 줄로 맞는지로 판정된다.
  길이를 재게 하려는 그림이 아니다 (`chrome.grid` 를 켜지 않는다).
- **등속이 아닌 것과의 나란한 대비.** 캡션이 둘이 되고 조각이 둘이 된다. 가속은 가속의
  조각이 할 말이다.
- **`Trace.marks[].direction`.** 자국이 모두 같은 쪽을 보므로 인스턴스의 `direction`
  하나면 된다. 자국마다 방향이 다른 방사 배치가 그 필드의 자리다.
