## (a) 원본과 달라진 점과 이유

**1. 색이 테마의 것이다.** 원본의 `#33302b` · `#ded7c9` · `#c0442f` 는 각각
`ink`·`muted`·`accent` 로 간다 (C2). 뜻은 그대로다 — **붉은색은 "진행 중인 0.5초" 한
뜻에만 쓰고 눈금·바퀴살은 전부 같은 먹색이다.** 옅은 테두리는 `muted`·`subtle` 로도
원본만큼 옅지 않아 `opacity: 0.6` 을 한 번 더 걸었다 (`centripetal-acceleration` 과 같은 처리).

**2. 캡션과 슬라이더가 캔버스 안으로 들어왔다.** 원본은 캔버스 280 px 아래에 `<p>` 와
`<input type=range>` 를 따로 놓았는데 엔진은 셋이 한 캔버스에 얹힌다. 그 두 줄 자리
(약 68 px)를 아래에 비우고 `camera.screenYBias: -16` 으로 바퀴를 올려, 배율이 원본과
같은 **100 px/단위**(반지름 108 px)가 되게 했다. 캔버스 높이 340.

**3. 주기를 네 단계로 쪼갰다.** 원본의 `fadeIn = min(1, tau/0.35)` 이 단계 경계가
아니라 `RUN` 안의 상수였다. `appear 0.35 + record 7.65 + erase 0.7 + blank 0.5 = 9.2`
로 나누면 `RUN = 8.0` 이 `end('record')` 로 읽히고, 불투명도가
`at('appear') × (1 − at('erase'))` 라는 선언의 함수가 된다. 조각에 경계 상수도
`if (u < B1)` 분기도 남지 않는다.

**4. `drawOrder: 'scene'` 을 켰다 — 2026-09-18 에 되돌렸다.** 이유와 해소는 아래 「어휘 부족」 1.

**5. `heldPath` 를 선언하지 않았다.** 이 조각에는 두 값을 미는 자동 진행이 없어 잡는
순간 양보할 것도, 놓은 뒤 돌아갈 값도 없다. 러너가 적어 줘도 읽는 곳이 없으므로 선언만
두면 저작자에게 거짓말이 된다 (S-render, `thermal-conduction` 과 같은 판단).

**6. 상태는 ω₀ · α 둘뿐이다.** 원본이 각도를 적분하지 않고 `θ(τ) = ω₀τ + ½ατ²` 를 매
프레임 다시 푸는 성질을 그대로 지켰다. `step` 은 항등이고 눈금 목록도 상태에 없다 —
그래서 슬라이더를 움직이면 **이미 찍힌 과거 눈금까지** 새 값으로 즉시 다시 서고,
α 를 0 으로 내리는 순간 부채 전체가 고른 간격으로 접힌다.

## (b) 어휘 부족

**1. 정적인 원을 그릴 어휘가 `trajectory` 뿐이다.** 바퀴 테두리는 궤적이 아니라
구조물인데, `surface` 의 `geometry: { kind: 'arc' }` 는 **선언에만 있고 렌더러가
그리지 않는다** (`renderSurface` 는 ground·incline·wall 셋만 처리한다). 그래서 테두리를
`trajectory` 로 놓을 수밖에 없고, 그러면 바퀴살과 같은 층(20)이라 눈금(19) 위를 지난다 —
원본은 테두리를 맨 먼저 그려 눈금이 그 위를 가로지른다. 겹침이 이 그림의 판정 장치라
(`눈금 = 테두리를 가로지르는 시간 기록`) `drawOrder: 'scene'` 으로 넘겼다. 층을 통째로
포기하지 않으려면 **테두리를 구조물 층에 놓을 어휘**(`surface` 의 arc 구현)가 있어야 한다.

> **해소 (2026-09-18)** — 엔진이 `surface` 의 arc 를 구현했다(장부 G138). 테두리를 `surface` 원호로 옮겨
> 구조물 층(10)에 놓았고, 층 순서만으로 겹침 관계가 서서 `drawOrder: 'scene'` 을 되돌렸다.

**2. `Trace.size` 의 단위가 문서와 다르다.** 주석은 "자국 크기(화면 px)" 라고 하는데
`shape: 'tick'` 만은 방향 벡터를 **월드 좌표에 더한 뒤** `toScreen` 하므로 실제 길이가
`size × scale` 이다 (`dot`·`ring` 은 진짜 화면 px). `pendulum-isochronism` 도 이미
`lengthFromPx(10)` 로 우회하고 있다. 여기서는 `0.18`(= 원본 18 px)을 월드로 넘겼다.
셋 중 하나를 골라야 한다 — tick 을 화면 px 로 고치거나, 주석을 고치거나, `sizeWorld` 를
따로 두거나.

**3. `slider` 에 눈금(`step`)도 표시 자릿수도 없다.** 원본은 ω₀ 를 0.01 간격 소수 둘째,
α 를 **0.005 간격 소수 셋째**로 고정 표기했다. 엔진의 슬라이더는 값을 소수 셋째에서
반올림하고 화면에는 `toFixed(2)` 로 찍으므로 **α 의 0.005 간격이 표시에서 뭉갠다**
(0.095 와 0.100 이 둘 다 "0.10"). "내가 무엇을 바꿨는지 알아야 한다" 가 이 조각이
슬라이더에 숫자를 둔 유일한 이유라 이건 뜻이 상하는 자리다.

**4. `sector` 는 원본의 부채꼴을 온전히 대신한다.** 채움 + 테두리 위 호가 한 덩어리로
나오고, 폭 0 일 때 점이 남지 않게 `MIN_SWEEP` 이 이미 들어 있다. `opacity` 가
`fillOpacity` 와 곱해져 원본의 `globalAlpha = op × 0.22` / `op` 가 그대로 재현된다.
모자란 것 없음.

**5. 각을 두 규약 사이에서 한 번 환산한다.** `pointAtClockAngle` 은 시계각을 받는데
`Sector.from`·`to` 는 월드 각(x 축에서 반시계)이라 `π/2 − θ` 를 조각이 쓴다. 부호를
한곳에 모아 두려고 만든 것이 극좌표 함수인데, 부채꼴만 규약이 달라 그 자리가 다시 생겼다.
`sector` 가 시계각을 받는 짝(또는 `clockSector`)이 있으면 조각에서 `π/2` 가 사라진다.
