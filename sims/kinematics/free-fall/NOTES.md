# 자유 낙하 — 이관 노트

원본 `tasks/piece-lab/free-fall/index.html` 을 엔진 어휘로 옮긴 기록이다.
자유 렌더(`Bundle.renderers`)를 쓰지 않았다.

## 쓴 어휘

| 원본의 표식 | 어휘 |
|---|---|
| 무대 | (없음 — 배경은 러너가 칠한다) |
| 땅 | `region` (띠 + 윗변 `outline`) |
| 낙하 사다리 — 가로대 | `trajectory` × 칸 수 |
| 낙하 사다리 — 잔상 원 | `trace` (`shape: 'ring'`) × 2 (기둥마다 하나) |
| 나란함 잣대 | `trajectory` |
| 무거운 공 | `body` (`fill: 'solid'` · `outline: 'none'` · `glow: false`) |
| 가벼운 공 | `body` (`fill: 'none'` · `outline: 'line'`) |
| 무게 딱지 | `readout` (월드 앵커 · `chip: false`) × 2 |
| 착지 울림 | `trace` (`shape: 'ring'` · `arc` · `spreadTo` · `life`) |
| 사이클 | `BundleSchema.timeline` 4단계 |
| 캡션 | `BundleSchema.caption` 슬롯 (`cases` 3) |
| 질량 택1 버튼 | `param-chips` (후보 4) |
| px ↔ m 환산 | `boundsHint` + 카메라 |

이번에 엔진에 들어온 필드를 **원본이 쓰던 자리마다** 실제로 선언했다 —
`Body.fill: 'none'`(가벼운 공) · `Body.outline`(두 공) · `Trace.arc`(착지 울림) ·
`param-chips`(무게 택1) · `CaptionSlotDef.cases`(착지 문안).

`heldPath` 는 두지 않았다. 칩은 잡고 있는 조작기가 아니고, 누르는 동안 양보해야 할
자동 진행도 없다.

## (a) 원본과 달라진 점과 이유

1. **가로 자리가 화면 비율에서 월드 거리로 바뀌었다.** 원본은 `xH = W * 0.34` ·
   `xL = W * 0.66` 으로 캔버스 폭을 따라갔다. 월드에는 화면 폭이 없으므로 원본 무대의
   최대 폭(`#stage { max-width: 860px }`)에서 굳혀 `BALL_X = 0.16 × 860 / PX_PER_M`
   으로 두었다. 좁은 임베드에서 두 공의 간격이 원본만큼 좁아지지 않는다.

2. **땅을 `surface`(`kind: 'ground'`)로 두지 않았다.** 그 어휘는 선 아래를 **뷰포트
   끝까지** muted 15 % 로 덮는다. 원본은 처음에 캔버스 끝까지 칠했다가 *캡션이 땅속에
   묻혀* 10 px 띠로 줄인 조각이다 — 그 수정을 되돌리게 된다. 그래서 띠 두께를 선언할 수
   있는 `region` 으로 옮기고 윗변만 `outline` 으로 굵게 그었다.

3. **조작기가 캔버스 안으로 들어왔고 자리가 위로 올라갔다.** 원본은 캔버스(340 px)
   **아래** DOM 에 버튼 줄을 두었다. 엔진의 조작기는 캔버스 위에 얹히므로 (i) 높이를
   340 → 400 으로 늘려 버튼 줄이 먹던 만큼을 돌려주고, (ii) 자리를 `top-left` 로
   선언했다. 기본 자리(왼쪽 아래)는 캡션 슬롯(아래 가운데)과 같은 높이라 좁은
   임베드에서 겹친다. 두 공은 위에서 출발해 내려오므로 비는 쪽은 위 모서리다.

4. **칩을 눌러도 처음부터 다시 떨어뜨리지 않는다.** 원본은 `restart()` 로 `tau` 를 0 으로
   되감았다. 엔진에는 조각이 제 시계를 되감을 통로가 없다 — `Bundle.step` 이
   `timeline` 을 받지 않고, 시간 엔진을 돌리는 선언도 없다. 대신 **아직 들고 있는
   동안(`tau < HOLD`)에는 고른 무게가 즉시 반영되고, 놓고 나면 이번 낙하의 무게로
   굳는다.** 늦어도 4.3 초 안에 고른 무게로 한 번 온전히 떨어진다. 떨어지는 도중에
   딱지만 갈아 끼우면 "숫자만 바꿔 놓았다" 로 읽혀 주장이 약해진다.

5. **착지 캡션이 문안 셋으로 갈렸다.** 원본은 `mH + '배 무거운 공도…'` 한 줄이다.
   캡션 슬롯에 `vars` 가 없어 후보 수만큼 키를 두고 `cases` 로 골랐다 (아래 「어휘 부족」).

6. **주기 안 시계가 둘이 되었다.** 시간표(`schema.timeline`)와 `state.tau` 가 같은
   상수(`CYCLE` · `HOLD` · `SETTLE` · `APPEAR`)를 본다. `step` 이 `timeline` 을 받지
   않아서 누적 적분을 하는 조각은 주기 안 시각을 상태에 따로 쌓아야 한다
   (`mechanics/inertial-frame` 이 같은 모양). 둘 다 러너가 주는 같은 `dt` 를 더한다.

7. **`drawOrder: 'scene'` 을 켰다.** 층 기본값은 `trace`(19) < `trajectory`(20) 이라
   잔상 원이 가로대 **아래**로 간다. 원본은 칸마다 가로대를 긋고 그 위에 원을 얹어
   칸이 "두 공이 있던 자리" 로 읽히게 했다. 겹침이 판정 장치라 선언 순서를 택했다.

8. **잣대의 둥근 끝 · 띠 윗변의 굵기.** 잣대의 `lineCap: 'round'` 는 `trajectory`
   렌더러가 늘 둥글게 그어 그대로다. 땅 선은 원본 1.5 px 인데 `region.outline` 이
   `strokeWidth.thick`(2) 고정이라 0.5 px 두껍다.

**바뀌지 않은 것** — 질량은 `F = m * g` 에서 들어갔다 `a = F / m` 에서 상쇄된다.
두 줄을 한 줄로 줄이지 않았다. 두 공은 서로의 값을 한 번도 읽지 않고 각자 적분한다.
같은 `dt` 로 돌린 대조에서 착지 시각(1.35 s) · 사다리 칸 수(12) · 멈추는 높이가
원본과 **완전히 같다**.

## (b) 어휘 부족

다음 엔진 작업의 입력이다. 위에서부터 이 조각에 아픈 순서다.

1. **`Body.fill: 'none'` 이 `colorRole` 을 따르지 않는다.** 속을 비우면 남는 것은
   둘레뿐인데, `body.ts` 는 둘레를 `rc.theme.line` 으로만 긋는다
   (`outline === 'line' ? rc.theme.line : …`). 라이트 테마에서 `line` 은 `#D4CEC2`,
   배경은 `#F5F1E8` 이라 **가벼운 공이 바탕에 거의 묻힌다.** 원본은 두 공을 같은
   잉크색으로 그리고 채움만으로 갈랐다 — 색이 갈리는 순간 "대상 구분은 채움과 딱지가
   한다" 는 규율이 깨지고, 묻히는 순간 "두 공이 나란히" 가 한쪽만 보이는 그림이 된다.
   채움이 없을 때 둘레가 `style.colorRole` 을 쓰거나, 둘레 색을 선언할 수 있어야 한다.

2. **둘레 굵기를 선언할 수 없다.** `body` 의 둘레는 `strokeWidth.thin`(1) 고정이다.
   원본의 가벼운 공은 2.5 px 이다. 채운 공과 **같은 무게로 읽혀야** 하는 빈 공은
   가는 실선으로는 서지 않는다. 1번과 같은 자리에서 같이 풀려야 한다.

3. **`Trace.size` · `spreadTo` 가 화면 px 고정이라 월드 크기와 어긋난다.** 잔상 원은
   공과 **같은 크기**여야 "그 공이 있던 자리" 로 읽힌다. 공은 월드(m)이고 잔상 원은
   px 라, 카메라 배율이 원본의 44.2 px/m 에서 벗어나면 둘이 어긋난다. 크기를 월드
   단위로도 줄 수 있어야 한다(착지 울림처럼 **화면 px 가 맞는** 자국도 있으므로
   둘 중 하나를 고르게 하는 쪽이 맞다).

4. **`CaptionSlotDef` 에 `vars` 가 없다.** `Readout` 에는 있는데 캡션 슬롯에는 없어서
   `'{m}배 무거운 공도 바닥에 같이 닿았다'` 한 줄을 후보 수만큼(2 · 10 · 50) 키로
   쪼개고 state 에 boolean 을 셋 두어야 했다(`landedAs2` · `landedAs10` · `landedAs50`).
   후보가 늘면 문안 · boolean · `cases` 세 곳을 함께 고쳐야 한다. `cases` 항목이
   `vars` 를 실을 수 있으면 boolean 하나로 족하다.

5. **땅의 두께를 고를 수 없다.** `surface` 의 `kind: 'ground'` 는 선 아래를 뷰포트
   끝까지 덮는다. 캡션이 그 위에 앉으면 "땅속의 캡션" 이 된다 — 원본이 실제로 겪고
   고친 자리이고, `fluids/pressure-and-container-shape` 도 같은 이유로 `ground` 를
   버렸다. 두 조각이 각자 버렸으므로 `ground` 가 **띠 두께**를 받아야 한다.

6. **조각이 제 시계를 되감을 수 없다.** 조작기를 눌렀을 때 "처음부터 다시" 는 되풀이
   재생하는 조각에 흔한 요구인데, `step` 은 `timeline` 을 못 보고 시간 엔진을 되돌릴
   선언도 없다. 위 (a)4 가 그 때문에 생긴 차이다.

7. **`region.outline` 의 굵기가 `strokeWidth.thick` 고정이다.** 채움과 윤곽의 색·알파는
   `fillOpacity` + `opacity` 로 갈랐는데 굵기는 못 갈랐다.

## (c) 화면에 두지 않은 것

원본의 판단을 그대로 옮겼다. 계산은 되지만 두지 않았다 (S-piece).

- **속도·가속도 숫자** — 두면 독자가 두 숫자의 자릿수를 대조하게 된다. 그것은 눈으로
  보는 일이 아니라 검산이고, 나란함을 잣대에서 빼앗아 표로 옮기는 일이다.
- **경과 시간 시계** — 동시 착지는 울림 두 개가 같이 퍼지는 것으로 이미 보인다.
- **좌표축·눈금·격자** — 높이를 읽을 일이 없다. 사다리 칸이 눈금 구실을 겸한다.
- **떨어뜨리는 높이 5 m 와 배율** — 낙하 시간을 약 1 초로 맞추려고 정한 값이고,
  주장은 높이와 무관하다.
- **공기 저항** — 계산에 넣지 않았다. 같은 크기의 두 공이라는 그림이 그 자리를 대신한다.
- **재생·정지 버튼 · 제목 · 그리드 · 카메라 버튼** — 조각은 스스로 되풀이하고, 제목은
  문단이 이미 달고 있다.

`startAt` 도 두지 않았다. 원본은 주기 첫머리에서 두 공이 **이미 들려 있는** 채로 열고
0.35 초 뒤에 놓는다 — 빈 화면을 기다리는 구간이 없어 시계를 앞당길 이유가 없다.

## (e) "차례로 바꾸기" 를 어떻게 옮겼는가

원본의 조작기는 네 칸이다 — `차례로 바꾸기` / `2 kg` / `10 kg` / `50 kg`. 앞의 하나는
값이 아니라 **값을 고르지 않은 상태**이고, 그때 무게는 떨어뜨릴 때마다 2 → 10 → 50 으로
스스로 돈다.

`param-chips` 는 후보의 값이 `number | string` 이라 네 칸을 그대로 옮겼다 —
`options: [{ value: 'auto' }, { value: 2 }, { value: 10 }, { value: 50 }]` 이 `massChoice`
한 자리를 쓴다. 순환을 별도 조작기(토글)로 빼지 않은 이유는 그것이 **다섯 번째 자리를
만드는 일**이기 때문이다. 원본에서 네 칸은 한 줄의 배타 선택이고, 그 배타성이
"지금 무엇이 정해져 있는가" 를 한눈에 말한다.

무게를 실제로 정하는 것은 `physics.ts` 의 `resolveMass(choice, cyc)` 다.

```ts
if (typeof choice === 'number') return choice;   // 고른 값
return MASSES[cyc % MASSES.length];              // 고르지 않았으면 차례로
```

선언은 후보 넷을 말하고, **무엇이 `auto` 인지 아는 것은 물리**다 (원칙 2).
`cyc` 는 주기가 넘어갈 때만 늘어나므로 순환은 "떨어뜨릴 때마다" 그대로다.
