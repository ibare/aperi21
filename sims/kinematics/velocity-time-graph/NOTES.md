# velocity-time-graph — 이관 NOTES

원본: `tasks/piece-lab/velocity-time-graph/` (자유 구현, 캔버스 직접 그리기).
이관본은 **자유 렌더 없이** 표준 어휘 다섯으로 선언한다 —
`region` · `trajectory` · `marker` · `body` · `readout`.

| 원본 묶음 | 어휘 |
|---|---|
| 그래프 축 | `trajectory` (width 1) + `readout` 둘 ('속도' · '시간') |
| 속도 곡선 | `trajectory` (width 2) |
| 쌓인 넓이 | `region` |
| 1초 경계 | `trajectory` (width 1) × 지나온 초 |
| 지금 속도 점 | `marker` pin (반지름 4px) |
| 길 | `region` (띠) + `trajectory` (바닥선, width 1) |
| 펼친 넓이 | `region` |
| 1초 말뚝 | `trajectory` (width 1) × 지나온 초 |
| 떼어 옮기는 넓이 | `region` — 띠 24개의 윗변을 이은 한 다각형 |
| 물체 | `region` (차체) + `body` point × 2 (바퀴) + `trajectory` (바늘, width 1.5) |
| 캡션 | `readout` 화면 고정 한 줄 |

속도 꺾은선 구간 · 주기 12.4 s · 연출 시간표(FLIGHT 0.8 · HOLD_END 11.8 · FADE 0.6 ·
SUB 24 · STAGGER 0 · 나타남 0.3)는 원본 코드에서 그대로 옮겼다 (`schema.ts`).

## 두 칸, 월드 하나

그래프 칸과 길 칸을 한 월드 좌표에 위아래로 놓는다. **월드 1 = 길 1 m.**

- 그래프 가로 `TIME_X = D / T_END` — 그래프 폭 = 길 폭 (원본도 둘 다 plotW).
- 그래프 세로 `VY = 16 · PX` — 원본의 1 m/s = 16px 를, 원본 캔버스(보고서 폭에서 860px,
  plotW 794px)의 축척 `PX = D / 794` 로 월드로 옮겼다.
- 띠 두께 `BAND_H = TIME_X · VY` — 원본의 `h = pxs·pxv / k` 를 월드로 옮긴 것.
  그래프 1 m(= 1 m/s × 1 s)의 넓이가 길 위 1 m × BAND_H 와 같다. 떨어지는 기둥은 모양만
  바뀌고 칠의 양은 그대로다. 두 축척이 서로에게서 유도되므로 캔버스 폭이 바뀌어도
  약속이 유지된다.
- 그 밖의 배치(축 높이, 말뚝이 띠 위로 7px 솟는 것, 수레 모양)는 원본 px 에 `PX` 를 곱해
  월드로 옮겼다. 선 굵기 · 점 반지름 · 글자 크기는 화면 px 그대로다.

운동 시계를 1.5 s 앞당겨 연 것은 스테이지 상수 `startAt: 1.5` 로 선언하고
`initialState` 가 그 값에서 시작한다.

## (a) 원본과 달라진 점과 이유

1. **파랑이 반투명이다.** 원본은 불투명한 옅은 파랑(#9cc3e6)이다. `region` 은
   `colorRole` + `fillOpacity` 로만 칠해서, 옅은 파랑을 얻으려면 `secondary` 를 0.45 로
   깔아야 한다. 결과는 원본보다 한 톤 짙고 탁한 파랑이다.
   - 그 탓에 **떨어지기 시작한 기둥이 쌓인 넓이와 겹치는 동안 겹친 곳이 더 짙다**
     (t=1.9 에서 가로축 바로 위 띠). 원본은 같은 불투명 색이라 겹침이 보이지 않는다.
   - 같은 이유로 길 띠를 **내려앉은 곳만큼 비워 두었다** (`road-head` · `road-tail`).
     반투명 파랑이 길 위에 겹치면 그래프 속 넓이와 다른 파랑이 되어 "같은 것" 이라는
     말이 흐려진다. 원본은 길 위에 파랑을 덮어 칠했다.
2. **먹색이 회색이다.** 곡선 · 축 · 지금 점 · 수레 · 캡션을 원본은 먹색(#1f2328)으로
   그렸다. `ColorRole` 에 전경(먹) 역할이 없어서 가장 짙은 무채색인 `muted` strong 을 썼다.
   곡선과 안내선(`muted` subtle)의 위계는 굵기(2 / 1)와 세기로 여전히 갈린다.
3. **말뚝과 경계선이 파랑 아래에 깔린다.** 원본은 "펼친 넓이 위에 말뚝을 긋는다" 가
   의도였다. z 층이 타입 단위(`region` 45 > `trajectory` 20)라 선이 면 아래로 간다. 파랑이
   반투명이라 말뚝은 비쳐 보이고, 띠가 말뚝 사이를 채우는 판정은 그대로 된다.
   곡선도 쌓인 넓이의 윗변에서 절반이 파랑에 덮인다.
4. **캡션이 캔버스 안이다.** 원본은 캔버스 밖 figcaption. 조각 규범의 캡션 슬롯은
   화면 고정 `readout` 이라 캔버스 아래 모서리에 붙는다. 경계에 캡션 자리(원본 30px)를
   더 잡았다. 카탈로그처럼 캔버스가 높으면 그림과 캡션 사이가 더 벌어진다.
5. **바퀴가 `body` point 라 반지름이 화면 3px 고정이다.** 차체(`region`)는 월드로 크기가
   정해져 배율을 따라간다. 원본 축척에서는 같고, 크게 확대하면 바퀴만 작아진다.
6. 말뚝의 픽셀 스냅(`Math.round(...) + 0.5`)은 옮기지 않았다 — 좌표 변환은 렌더러의 일이다.

대조 (`pnpm -s piece:report --sims=… velocity-time-graph`): t = 1.9 · 4.9 · 9 에서 기둥
위치 · 띠 끝 · 말뚝 간격 · 수레 · 지금 점이 원본과 축척 비율대로 1px 안쪽으로 맞는다.
**t = 0 은 장치 탓으로 약 0.2 s 어긋난다** — `Embed` 의 `inspectAt` 은 `> 0` 일 때만 시간을
멈추므로 t=0 캡처는 실시간으로 조금 흐른 뒤 찍힌다. 선언상 시작은 τ = 1.5 로, 원본과 같이
첫 기둥이 떨어지는 중이다.

## (b) 어휘 부족

분석 단계의 판정("기존 어휘만으로 성립한다")은 **동사 기준으로는 맞다.** 기둥이 떨어지며
납작해지고 말뚝 사이를 꼭 채우는 일이 화면에서 일어난다. 모자란 것은 표현의 정확도 쪽이다.

1. **불투명한 옅은 칠이 없다.** `region` 은 `colorRole` 의 원색에 알파를 곱해서만 옅어진다.
   "같은 대상 = 같은 색" 을 지키는 조각에서, 같은 색 도형 둘이 겹치면 겹친 곳이 짙어져
   **다른 것처럼 보인다** (쌓인 넓이 × 떨어지는 기둥, 파랑 × 길). 원본은 불투명 옅은 색이라
   겹침이 사라졌다. 필요한 것: 옅은 색조(tint)를 불투명으로 까는 방법, 또는 같은 id 묶음의
   도형을 합집합으로 한 번에 칠하는 방법.
2. **전경(먹) 색 역할이 없다.** `ColorRole` 6개 중 무채색은 `muted` 하나라, 곡선 · 물체 ·
   글자처럼 "먹" 으로 그려야 할 것이 회색이 된다. `theme.foreground` 는 있는데 선언에서 닿을
   길이 없다.
3. **겹침 순서를 선언이 정할 수 없다.** z 가 타입 단위라 "이 선은 이 면 위" 를 말할 수 없다.
   원본에서 말뚝을 띠 위에 긋는 것은 판정 장치였다.
4. **(작음)** `body` 의 크기가 모양에 따라 월드(circle)이거나 화면 고정(point)이라, 월드로
   크기가 정해진 `region` 차체와 바퀴가 배율을 함께 따라가지 못한다. `region` 을 물체의
   외형으로 쓴 것도 근사다 — `body` 에 다각형 외형이 없다 (`custom` 은 선언만 있고 구현이 없다).

## 화면에 없는 것

원본의 결정을 그대로 따른다 — 넓이 · 거리 수치, 가속도(기울기), 눈금 · 격자, 위치-시간
그래프는 두지 않는다. 숫자로 확인시키면 "꼭 맞는다" 가 눈이 아니라 산수가 된다.
