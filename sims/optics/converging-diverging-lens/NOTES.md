# converging-diverging-lens — 볼록 렌즈와 오목 렌즈

자유 구현 원본이 없다. 엔진 어휘로 곧바로 지었다.
쓴 어휘: `region`(렌즈 두 개의 윤곽) · `ray`(줄기, plugin-optics `traceRay` 로 추적) · `trajectory`(광축, 거꾸로 이은 점선 `dashed`) ·
`body` circle(실초점 채운 점 · 허초점 빈 점) · `readout`(렌즈 이름표, 표식 `F`), 선언 `timeline`(`ease: 'smooth'`) · `startAt` ·
`caption` · `drawOrder: 'scene'` · `canvas` · `stages[].constants`.

## (a) 답하는 질문과 동사

**질문** — 나란히 들어온 빛을 볼록 렌즈와 오목 렌즈는 각각 어디로 보내는가.

**주장** — 같은 평행 줄기를 볼록 렌즈는 렌즈 뒤 한 점으로 모으고, 오목 렌즈는 렌즈 앞 한 점에서 나온 것처럼 퍼뜨린다.

**동사** — *볼록 렌즈 뒤에서는 줄기가 한 점에 모이고, 오목 렌즈 뒤에서는 줄기가 벌어지며 거꾸로 이은 점선이 렌즈 앞 한 점에 모인다.*

화면에서 일어나는 방식 —

- 두 렌즈를 위(볼록) · 아래(오목)로 **같은 x** 에 세운다. 같은 높이 · 같은 간격의 평행 줄기 다섯이 두 줄에 똑같이 들어온다.
- `enter` — 줄기 앞머리(화살촉)가 왼쪽에서 두 렌즈로 온다. `bend` — 렌즈를 지나 위 줄기는 축 쪽으로, 아래 줄기는 축 바깥으로 꺾인다.
- `mark-real` · `hold-real` — 위 줄기가 모두 지나는 렌즈 뒤 축 위 점에 채운 점과 `F` 가 뜬다. 줄기는 그 점을 지나 엇갈려 나간다.
- `trace-back` — 아래의 벌어진 줄기 넷을 렌즈에서 앞쪽으로 거꾸로 잇는 점선이 자라 축으로 모여 간다. `mark-virtual` · `hold-virtual` —
  점선이 만난 렌즈 앞 축 위 점에 빈 점과 `F` 가 뜬다. 위 `F` 는 렌즈 뒤, 아래 `F` 는 렌즈 앞 — 같은 x 에 세워 두어 곧바로 견줘진다.
- `drain` — 줄기 꼬리가 오른쪽으로 빠져나가고 점선 · 초점이 옅어진 뒤 주기가 처음부터 다시 선다.
- 꺾이는 방향은 조각이 정하지 않는다. 줄기마다 `traceRay` 를 얇은 렌즈(`lens-convex` / `lens-concave`, `focalLength` = 스테이지 상수)에
  쏘아 얻는다. 두 초점도 추적한 줄기(볼록은 앞으로, 오목은 거꾸로)가 축과 만나는 자리에서 읽는다 — 초점 점과 줄기 교점이 한 계산이다.
- 앞머리 · 꼬리 x, 점선 길이, 초점 짙기는 모두 단계 진행도(`at`)의 합 · 곱이다(`physics.ts`). 단계 경계를 코드 상수로 가르지 않는다.

## (b) 화면 구성의 결정 — 두지 않은 것 포함

- **물체 · 상을 두지 않았다.** 세 광선 결상은 `ray-tracing`, 배율은 `magnification`, 실상 · 허상은 `real-vs-virtual-image` 의 몫이다.
  이 조각은 평행광과 초점만 말한다.
- **위아래로 쌓았다(단계로 바꿔 끼우지 않았다).** 한 줄에서 렌즈를 바꿔 끼우면 두 초점이 한 화면에 같이 서지 않는다. 같은 x 에
  세운 두 렌즈에서 `F` 가 렌즈 뒤 · 앞으로 갈리는 것이 주장의 한가운데다. 대신 세로가 든다(`canvas.height` 460).
- **렌즈는 `region` 으로 그렸다.** plugin `opticalElement` 의 `lens-concave` 는 가운데가 두꺼운 볼록 모양으로 그려진다 — 렌더러의 두
  이차 곡선이 볼록 렌즈와 같은 도형을 만든다(아래 (c) 새 부족). 두 렌즈의 모양 차이가 주장의 절반이라 쓸 수 없다. 렌즈 요소는 선언만
  만들어 `traceRay` 에 넘기고 화면에 올리지 않는다. (이 결함은 장부 G224 로 올라가 2026-09-19 에 엔진에서 고쳤다 — 이 조각은
  `region` 그림을 그대로 둔다.)
- **두 줄의 줄기를 색으로 가르지 않는다.** `ray` 는 plugin 강조색 하나(빛 한 가지 뜻)다. 거꾸로 이은 줄기도 같은 줄기의 연장이라 같은
  강조색이고, 실제 빛이 아니라는 것은 **점선**으로 가른다. 실초점 · 허초점은 같은 표식 `F` 에 **채운 점 / 빈 점** 모양으로 가른다.
- **가운데 줄기의 점선을 긋지 않는다.** 꺾이지 않아 거꾸로 이으면 들어오는 줄기 · 광축과 겹친다. 점선은 넷이다.
- **수를 띄우지 않는다.** 초점 거리 글자 · 치수선(`dimension`)을 두지 않았다 — 주장은 초점이 **어느 쪽**에 생기느냐이고, 두 `F` 가 렌즈에서
  같은 거리라는 것은 같은 x 에 세운 그림에서 보인다. 수가 없으니 캡션 `vars` · state 글자(G133)도 필요 없다 — 상태는 비어 있다.
- 캡션은 지금 화면의 사실만 쓴다 — 식 · 법칙 진술(「볼록 렌즈는 빛을 모은다」 · 「허초점에서 나온 것처럼」)을 옮기지 않았다.
  허초점 캡션은 「실제 줄기는 그 점을 지나지 않는다」 — 화면에서 실선이 그 점에 닿지 않는 것이 보인다. 줄기 수는 캡션에 쓰지 않았다(상수).
- **조작기 없음.** 초점 거리를 끌게 하면 두 초점이 함께 움직일 뿐 주장이 늘지 않는다.
- 그리드 · 카메라 단추 · 범례 · 제목 없음. 잴 것이 거리가 아니다.
- 볼록 줄기는 초점을 지나 x = 4.8 까지 간다. 첫 촬영(끝 x = 3.8)에서 다섯 화살촉이 초점 바로 뒤에 뭉쳐 한 덩이로 보였다.
  오목 줄기는 x = 2.1 에서 끊는다 — 더 가면 바깥 줄기가 위 줄에 닿는다.
- `startAt: 4.0` — 도착한 순간 두 줄의 줄기가 다 지나가 있고 볼록 쪽 `F` 가 서 있다(실초점 멈춤 안). 쌓는 상태가 없어 `preroll` 은 쓰지 않는다.
- 물리량(초점 거리 · 줄기 수 · 간격)은 `stages[].constants`, 배치(축 높이 · 렌즈 반높이와 두께 · 줄 끝 · 이름표 띄움 · 경계)는 schema
  이름 있는 상수, 선 굵기 · 글자 크기 · 채움 짙기 · 표본 수는 scene 파일 머리의 이름 있는 상수다.

## (c) 어휘 부족

**주장 부족 없음** — 렌즈를 `region` 으로 그려 우회했다. 우회하지 않았다면 아래 새 부족이 `주장` 이다.

| 장부 | 이 조각에서 | 영향 |
| --- | --- | --- |
| G218 | `ray` 는 opacity 를 따르지 않아 빠져나감을 페이드로 못 한다 — 꼬리를 x 로 잘라 빛이 오른쪽으로 빠져나가게 했다. 허상 연장 점선은 `trajectory` 로 긋는다 | 근사 |
| G219 | `opticalElement` 렌즈 두께가 고정이고 `focalLength` 가 그림에 반영되지 않는다 — 렌즈를 `region` 다각형으로 직접 선언했다 | 근사 |
| G28 | 렌즈 면의 곡선 어휘가 없어 한 면을 18 마디로 표본한 다각형으로 긋는다 | 근사 |
| G143 | 렌즈 반높이 · 줄 끝 · 고정 경계가 스테이지 상수(줄기 수 · 간격 · 초점 거리)를 따라가지 않는다 — 줄기를 늘리면 렌즈 밖으로, 초점 거리를 늘리면 오목 초점이 줄기 출발점 밖으로 나갈 수 있다 | 근사 |
| G105 | 줄기 높이 목록을 선언할 수 없어 수 · 간격 두 상수에서 코드가 만든다 | 근사 |

새 부족 —

| 부족 | 이 조각에서 | 영향 |
| --- | --- | --- |
| plugin-optics `opticalElement` 의 `lens-concave` 가 **볼록 모양**(가운데가 두껍고 가장자리가 뾰족한 도형)으로 그려진다 — `renderOpticalElement` 의 두 이차 곡선이 제어점 부호만 바뀌어 `lens-convex` 와 같은 도형(더 얇은)을 만든다. G219 는 두께를 고를 수 없다는 것이고 이것은 모양이 뒤집힌 것이다 | 그대로 쓰면 오목 렌즈가 볼록 렌즈로 보여 「모양이 다른 두 렌즈」 가 무너진다. `region` 으로 우회 | 주장 |

렌즈 굴절은 `traceRay` 가 했고, 렌즈 윤곽 표본 · 줄기 자르기 · 축과 만나는 점 계산은 조각의 배치 계산이다.

## (d) 주장이 화면에서 서는가

`?t=` 촬영본을 라이트 · 다크 모두 직접 열어 확인했다 (2026-09-19, `tasks/piece-lab/_report/_scratch/converging-diverging-lens/shots/`).
첫 촬영에서 볼록 줄기 화살촉 뭉침 하나를 고쳤다(위 (b)). 아래는 고친 뒤 재촬영이다.

| t(초) | 단계 | 라이트 · 다크 |
| --- | --- | --- |
| 0.5 | hold-real | 위 다섯 줄기가 렌즈 뒤 축 위 채운 점 `F` 를 지나 엇갈려 퍼져 나간다. 아래 다섯 줄기는 벌어진다. 점선 없음. 캡션 실초점 문장 |
| 3.0 | trace-back | 아래 벌어진 줄기 넷의 점선이 렌즈 앞으로 반쯤 자라 축 쪽으로 모여 간다. 위 `F` 그대로 |
| 5.5 | hold-virtual | 네 점선이 오목 렌즈 앞 축 위 빈 점 `F` 에서 만난다. 위 `F` 는 렌즈 뒤, 아래 `F` 는 렌즈 앞 — 같은 x 의 두 렌즈에서 갈린다 |
| 10.0 | enter | 새 주기. 두 줄 모두 평행 줄기 다섯의 화살촉이 렌즈 왼쪽에 와 있다. 초점 · 점선 없음 |
| 11.0 | bend | 줄기 앞머리가 렌즈를 지나, 위는 축 쪽으로 좁혀 들고 아래는 축 바깥으로 벌어진다 |

- 주장의 동사(모인다 · 벌어진다 · 거꾸로 이은 점선이 모인다)는 10.0 → 11.0 → 0.5 → 3.0 → 5.5 를 이어 보면 선다.
- **다크** — 줄기 금빛, 렌즈 회청 테두리 · 어두운 채움, 채운 `F` 흰 점, 빈 `F` 흰 고리, 글자 흰색. 바탕과 모두 갈린다.
- **라이트** — 줄기 주황, 렌즈 회색 테두리 · 옅은 채움, 채운 `F` 짙은 점, 빈 `F` 짙은 고리. 글자 겹침 · 화면 밖으로 나감 없음.
- 빈 점 `F` 는 반지름이 작아(0.08 월드) 고리로 읽히는 크기가 빠듯하다. 점선이 모이는 꼭짓점이 함께 가리켜 주장에는 지장이 없다.
- 캡션 한 글자가 옅게 찍힌 촬영본이 있다(10.0 라이트의 「빛」). `law-of-reflection` 이 적은 것과 같은 글꼴 로딩 시점 문제로 보인다(미확인).
- 그림이 캔버스 가로의 약 절반을 쓴다. 두 줄을 쌓은 세로가 배율을 정한다 — 주장에 지장이 없어 두었다.
