# relativistic-momentum — 제작 기록

자유 구현 원본 없이 엔진 어휘 위에서 바로 지었다. 자유 렌더(`Bundle.renderers`)는 쓰지 않았다.

## (a) 답하는 질문과 동사

**질문** — 같은 힘으로 계속 밀면 물체는 언젠가 빛보다 빨라지는가?

**주장 한 문장** — 같은 힘으로 계속 밀면 운동량은 같은 시간마다 똑같이 쌓이지만, p = γmv 곡선은 느릴 때 고전 직선
p = mv 와 겹치다가 c 앞에서 위로 치솟아, 속도는 c 에 다가갈 뿐 넘지 못한다.

**동사** — *곡선이 c 앞에서 위로 치솟는다* (같은 운동량의 고전 점은 c 를 넘어 나가고, 실제 점은 c 앞에 머문다).

화면에서 일어나게 한 방법: 운동량-속도 곡선 판 하나. 가로축은 속도(0 ~ 1.3c), 세로축은 운동량. c 자리에 먹색 세로
점선이 서 있다. 먹색 곡선이 실제(`실제 p = γmv`), 회색 점선이 고전(`고전 p = mv`)이다.

- `slow`(0.6 초) — 한결같은 힘으로 미는 물체의 먹색 점이 원점에서 곡선을 오른다. 같은 운동량(같은 높이)의 「고전이라면」 점(속
  빈 회색)이 직선 위에 먹색 점과 붙어 있고 두 선도 겹친다. 캡션 「느릴 때는 곡선과 고전 직선이 겹친다」.
- `part`(1.6 초) — 두 점이 벌어져 회색 점선이 가로로 잇는다. 고전 점이 c 점선을 넘고, 단계 끝에 판 밖으로 나간다. 캡션 「같은
  운동량인데 두 점이 벌어진다 — 고전 점은 c 를 넘어 판 밖으로 간다」.
- `fast`(3.8 초) — 고전 점은 판 밖이고 잇는 선이 판 오른쪽 끝을 가리키는 화살표가 된다. 실제 점은 c 점선 앞에서 곡선을 타고
  가파르게 오른다.
- 내내 — 같은 시간 간격(0.5 초)마다 곡선 위에 강조색 자국 점이 남고, 두 축에 그 자리의 짧은 강조색 눈금이 찍힌다. **세로축
  눈금은 고르게**(같은 힘 → 같은 운동량), **가로축 눈금은 c 앞에서 촘촘하게**(속도는 점점 덜 는다) 쌓인다. 이 대비가
  「같은 힘을 계속 주어도 c 에 다가갈 뿐」 을 수 없이 보여 준다.
- `hold` — 밀기가 끝난 화면이 남는다. 자국 열둘이 c 점선 앞에서 거의 세로로 늘어서 있고, 실제 점은 c 에 닿지 않았다.
- `fade` — 자국 · 점이 흐려지고 다음 주기로 잇는다.

## (b) 화면 구성의 결정

- **이웃과 겹치지 않게** — `time-dilation` 은 지나가는 시계와 정지 시계 줄로 「바늘이 느리게 돈다」 를 보인다. 여기에는
  시계 · 레일 · γ 치수선이 없고 곡선 판 하나만 있다. 속도를 더해도 c 를 넘지 못하는 것은 `relativistic-velocity-addition`
  의 몫이라 배 · 탄환 · 빛을 두지 않았다. 여기서 c 를 못 넘는 까닭은 「더하기」 가 아니라 「같은 힘으로 계속 밀기」 다.
- **「같은 힘을 계속」 을 함께 보이기로 했다** — 곡선만 있으면 「치솟는다」 는 보이지만 그것이 왜 「c 를 못 넘는다」 인지는
  글이 말해야 한다. 한결같은 힘은 운동량을 시간에 비례해 쌓으므로(p = F·t) 점이 곡선을 오르는 **세로 빠르기가 한결같고**,
  같은 시간 간격의 자국이 세로축에는 고르게 · 가로축에는 c 앞에서 촘촘하게 남는다. 힘 화살표나 미는 물체의 그림은 두지
  않았다 — 세로가 비싸고, 판 하나에 자국이 그 일을 한다.
- **「고전이라면」 점** — 같은 운동량(같은 높이)에서 고전 직선 위의 속 빈 점. 느릴 때는 실제 점에 붙어 있다가 c 를 넘어 판
  밖으로 나간다. 판 밖으로 나간 뒤 판 끝에 세워 두지 않았다 — 그 자리는 거짓 값이다. 대신 잇는 점선이 판 끝을 가리키는
  화살표가 된다.
- **색** — 곡선 · 점 · c 는 먹(`ink`), 축 · 고전 직선 · 고전 점 · 안내선 · 속도 눈금은 회색(`muted`). 강조색은 「같은 시간마다
  찍은 자국」 한 뜻에만 쓴다(곡선 위 점 · 두 축의 짧은 눈금). 실제와 고전은 색이 아니라 선 모양(실선 · 점선)과 점 모양(채움 ·
  속 빔), 이름표로 가른다.
- **수는 선언값뿐** — 속도 눈금 `0.5c` · `0.8c` · `0.9c` 는 스테이지 상수를 `String` 으로 `'{v}c'` 문안에 끼운다. γ · 지금 속도 ·
  지금 운동량은 계산되지만 화면에 띄우지 않는다 — 묻는 것은 「몇 c 인가」 가 아니라 「넘는가」 이고, c 점선과 자국 간격이 그 답이다.
  세로축에는 눈금 수를 두지 않았다. 질량을 바꾸면 운동량 값이 바뀌는데 수를 달면 그 수가 질량 단위에 묶인다.
- **물리량은 스테이지 상수** — `mass` · `force` · `stampInterval` · `speedTick1..3`. 배치(축척 `perC` · `perP`, 축 끝 `vEnd` · `pTop`,
  곡선 이름표 자리)는 schema 의 이름 있는 상수, 선 굵기 · 글자 크기 · 띄움 · 짙기 · 곡선 표본 수는 scene 머리의 이름 있는 상수다.
- **곡선은 운동량을 고르게 나눠 짚는다** — 속도로 나누면 c 앞의 치솟는 구간이 표본 두셋으로 꺾인다. 세로축 끝(`pTop`)에서 판이
  곡선을 자른다 — 끝없이 치솟는 것을 그릴 수는 없다.
- **느려짐을 키우지 않았다** — 배율 없이 실제 식이다. 힘 0.6 · 6 초로 마지막 운동량이 3.6(질량 단위 × c), 속도는 약 0.96c 다.
- 미는 동안은 `slow` 시작부터 `fast` 끝까지(`slow` · `part` · `fast`)이고, 점의 자리는 `u − start('slow')` 의 함수다. 세 단계의 경계는
  캡션이 바뀌는 자리일 뿐 힘은 끊기지 않는다. 단계 길이는 캡션이 화면과 맞도록 잡았다 — `slow` 는 두 점이 붙어 있는 동안(두 점
  간격이 점 지름 안), `part` 는 고전 점이 판 밖으로 나갈 때(미기 시작 뒤 약 2.17 초)까지. 불투명도는 `at('fade')` 에서만 얻는다 — 단계 경계 상수가 코드에 없다.
- `startAt: 0.4` — 도착하면 점이 이미 원점을 떠나 오르는 중이다. 쌓는 상태가 없어 `preroll` 은 쓰지 않는다.
- **두지 않은 것** — 공식 p = γmv 의 유도 · γ 값 · 에너지 E = γmc² · 힘 화살표 · 미는 물체의 그림 · 가속기 · 속도 슬라이더 ·
  그리드 · 카메라 단추 · 제목 · 범례. 속도 슬라이더는 γ 를 계산해 띄워야 해서(유효숫자) 두지 않았고, 조작기 없이도 자동 진행으로
  주장이 끝난다.

## (c) 어휘 부족

**주장 부족 없음.** 근사한 곳은 모두 모양의 문제다.

| 장부 | 이 조각에서 | 영향 |
| --- | --- | --- |
| G47 | 곡선 판의 축을 `trajectory` 한 줄(ㄴ자) + 축 이름 `readout` 둘, 속도 눈금을 `lineSet` + `readout` 으로 손수 세웠다 | 근사 |
| G16 | `readout` 이 돌지 않아 세로축 이름을 축 위에 가로로 눕혔다 | 근사 |
| G24 | 캡션 자리가 프레이밍 여백으로 잡히지 않는다 — 경계 아래로 캡션 한 줄 자리를 더 잡았다 | 근사 |
| G105 | 스테이지 상수가 수 하나씩이라 속도 눈금 셋을 `speedTick1..3` 키로 흩었다. 눈금 개수(셋)는 코드의 `SPEED_TICKS` 길이에 남는다 | 근사 |
| G129 | 미는 동안(`slow` + `part` + `fast` = 6 초)이 자국 간격(0.5 초)의 정수배여야 마지막 자국이 미는 끝에 떨어진다 — 선언할 자리가 없어 schema 주석으로만 묶었다 | 근사 |
| G143 | `slow` · `part` 길이가 `force` · `mass` 에 묶여 있다(두 점이 붙어 있는 동안 · 고전 점이 판 밖으로 나가는 시각). 저작자가 `force` 만 바꾸면 경고 없이 캡션이 화면과 어긋난다 | 근사 |
| G09 | `fade` 에서 자국 · 점 · 안내선마다 불투명도를 하나씩 곱한다 | 근사 |

새 부족 없음. 곡선 표본 · 점 자리 · 판 밖으로 나간 고전 점의 처리는 조각의 물리 · 배치 계산이라 부족으로 올리지 않았다.

## (d) 주장이 화면에서 서는가

`pnpm -s piece:report --sims=http://localhost:5173/aperi21/ relativistic-momentum` 으로 라이트 · 다크를 모두 열어 봤다
(`tasks/piece-lab/_report/_scratch/relativistic-momentum/shots/`). 첫 촬영본이 aperi21 카탈로그의 「상대론적 운동량」 화면인 것을 확인했다.

- **t=0.1 (slow)** — 먹색 점이 0.3c 근처, 곡선과 고전 직선이 겹치고 속 빈 고전 점이 먹색 점에 붙어 있다. 두 축에 강조색
  자국 하나씩. 캡션 「느릴 때는 곡선과 고전 직선이 겹친다」 와 화면이 맞는다. 두 테마 모두 선다.
- **t=1.5 (part)** — 점이 0.75c 근처, 같은 높이의 고전 점이 c 점선을 넘어 오른쪽에 있고 회색 점선이 둘을 잇는다. 곡선이
  직선 위로 휘어 오른다. 캡션 「두 점이 벌어진다 — 고전 점은 c 를 넘어 판 밖으로 간다」. 두 테마 모두 선다.
- **t=3.6 (fast)** — 고전 점은 판 밖, 잇는 점선이 판 끝 화살표가 됐다. 실제 점은 0.9c 를 넘어 c 점선 앞에서 가파르게 오른다.
  세로축 자국 여덟은 고르고 가로축 자국은 0.9c 부근부터 촘촘하다. 선다.
- **t=6.4 (hold)** — 자국 열둘. 세로축 눈금은 끝까지 고르고, 가로축 눈금은 c 점선 바로 앞에 겹쳐 쌓였다. 실제 점은 c 에 닿지
  않았다. 캡션 「실제 속도는 c 에 다가갈 뿐 넘지 못한다」 와 화면이 맞는다. 선다.
- 다크에서 뒤집히는 것은 없다 — 먹색 곡선 · 점 · c 점선이 두 테마에서 바탕 반대쪽으로 오고, 강조색 자국이 두 테마 모두 또렷하다.
  글자가 화면 밖으로 나가거나 겹치는 곳은 없다.
- 처음 촬영에서 고친 것 — 두 번째 촬영 시각을 1.8 → 1.5 로 옮겼다. 1.8 에서는 고전 점이 이미 판 밖이라 「c 를 막 넘은」 순간이
  찍히지 않았다.
- rule-guard 사후 검증에서 고친 것 (S-piece 캡션) — 처음 시간표는 `slow` 2 초 · `fast` 4 초였고, `slow` 캡션 「느릴 때는 운동량이
  고전 직선을 따라 쌓인다」 가 떠 있는 동안 약 0.83 초부터 두 점이 벌어지고 단계 끝에는 고전 점이 c 를 넘어, 단계 후반 약 60 % 가
  캡션과 어긋났다. `slow` 를 두 점이 붙어 있는 0.6 초로 줄이고, 가운데에 「벌어진다」 캡션의 `part` 1.6 초를 더하고, `fast` 를
  3.8 초로 줄였다(미는 동안 6 초 · 주기 9.2 초는 그대로). 첫 `part` 문안 「고전대로라면 곧 c 를 넘는다」 는 재촬영 t=1.5 에서
  고전 점이 이미 c 를 넘어 있어 다시 어긋났고, 단계 내내 진행 중인 일 「c 를 넘어 판 밖으로 간다」 로 고쳤다. 첫 촬영 시각은
  0.6 → 0.1 로 옮겼다(0.6 은 이제 `part` 다). t=3.6 · 6.4 의 화면은 바뀌지 않았다.
- 판정에 걸리지 않는 흠 — 판이 세로로 차서 캔버스 가로에 여백이 남는다. 세로를 늘리면 글 흐름이 비싸져 기본 360 에 두었다.
- 관찰(미확인) — 캡션의 몇 글자(라이트 t=6.4 「뿐」, 다크 t=3.6 · 첫 촬영의 다크 t=1.8 「쌓」 「곡」 「솟」 등)가 옆 글자보다 옅게 찍혔다. 이웃 `time-dilation`
  NOTES 에 적힌 캡션 글자 옅어짐과 같은 현상으로 보이나 원인은 확인하지 않았다.
