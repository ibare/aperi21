# huygens-principle — 하위헌스 원리 (이관 기록)

원본: `tasks/piece-lab/huygens-principle/` (자유 구현). 주장·결정의 근거는 원본 `NOTES.md` 를 본다.

주장: 파면 위 점마다 나간 동그란 파가 촘촘히 겹치면 **곧은 파면이 되어 나아간다**.

## 쓴 어휘

- `scalarField` 두 장 — 왼쪽 들어오는 평면파(77 × 1, 세로로 같은 값이라 한 행을 늘림) ·
  오른쪽 점파원 합(204 × 107, 원본 3 칸 격자 그대로). 둘 다 순차형 `high: 'ink'`, 범위 −1 ~ 1,
  값은 원본의 제곱근 누름을 거친 **골 깊이**(−변위). `clip` 으로 원본 캔버스(840 × 320) 밖 한 칸을 자른다
- `trajectory` — 파면 자리 세로선 (`muted` · `subtle` · 굵기 1 · 불투명도 0.35)
- `particleSystem` — 점파원 1 → 33 개를 묶음 하나로 (`accent` · 반지름 4)
- `BundleSchema.timeline` — `n1`(8) · `n3`(3) · `n5`(3) · `n9`(3) · `n17`(4) · `n33`(8) 여섯 단계, 단계마다 캡션 키.
  점이 태어나는 시각은 scene 이 `timeline.start('n…')` 로 읽는다
- `BundleSchema.caption` — 장 아래 왼쪽 한 줄, `fade: 0`, `cases: [{ when: 'returning' }]`
- `BundleSchema.drawOrder: 'scene'` · `canvas` · `boundsHint`(고정 경계)

`startAt` 은 0 — 원본도 시계 0 에서 열리고, 그 순간 이미 가운데 점의 파가 화면을 덮고 있다.
`preroll` 은 없다 — 장 · 점이 모두 시각의 함수다. 상태에 남은 것은 캡션 하나를 고르기 위한 시계뿐이다(아래 G01).

첫 프레임 선언 수: 4 (장 2 · 선 1 · 점 떼 1).

## (a) 원본과 달라진 점과 이유

| 원본 | 여기 | 이유 |
|---|---|---|
| 색 띠 골(짙은 남색) · 0(회청) · 마루(밝은 색) | 마루 = 테마 바탕, 골 = 먹(`ink`), 0 = 둘을 선형광으로 반씩 섞은 색 | 한 역할의 명암으로 부호를 가르려면 순차형뿐이다. 골 · 마루는 짙기로 갈린다(G54 는 피함). 다만 선형광 섞기라 **0 이 원본보다 훨씬 옅다** — 점파가 약한 오른쪽 장 전체가 밝은 회색으로 떠서 무늬 대비가 원본보다 약하다 (G62) |
| 밝은 종이 위 단일 화면 | 카탈로그가 다크 테마면 바탕이 짙고 먹이 옅어 **마루 짙게 · 골 옅게** 로 뒤집힌다 | 순차형은 바탕 → 역할 색이다. 부호 순서만 뒤집히고 단조성은 유지되어 주장에는 영향이 없다. 대조 스크린샷은 모두 다크 테마였다 — 라이트 테마 화면은 찍어 보지 않았다(미확인) |
| 점파원 `#ff8a3d` 채움 + 짙은 테두리 1.5 px | `accent`(테마 황토) 채움, 테두리 없음 | C2 · `particleSystem` 에 둘레 선이 없다(새 부족). 옅어진 장 위에서 점이 원본보다 덜 도드라진다 |
| 파면 자리 선: 바탕색 35 % 알파 — 짙은 장 위의 옅은 선 | `muted` 35 % | 바탕(반전) 색 역할이 없다 (G07). 옅어진 오른쪽 장 위에서는 거의 보이지 않는다 |
| 점 반지름 4 px | 4 화면 px — 캔버스 배율을 따르지 않는다 | `particleSystem.sizes` 는 화면 px. 대조 화면(가로 약 752 px)에서 원본보다 약간 크게 보인다 (G25) |
| 캡션은 캔버스 밖 DOM | 캔버스 안 캡션 슬롯. 경계 아래 44 월드 띠를 비움 | G24 |
| 「점을 1개로 줄였다」 문구를 `k ≥ 1 && c·u < FAR` 로 고름 | `step` 이 시계를 세어 `returning` 을 만들고 캡션 `cases` 가 읽는다 | 조건이 **주기 번호**에 달려 첫 주기와 둘째 주기가 같은 단계에서 다른 말을 한다. 시간표 단계로 나눌 수 없고, `step` 은 `TimelineFrame` 을 받지 못한다 (G01) |
| 캡션 울퉁불퉁 / 곧게 를 `H/(n−1) < λ` 로 계산 | 단계마다 캡션 키로 적었다(n3 · n5 · n9 울퉁불퉁, n17 · n33 곧게) | 시간표 선언이다. 점 간격 비교는 `schema.ts` 주석에 근거로 남겼다. 저작자가 파장을 바꾸면 캡션이 따라오지 않는다 (G13) |

### 장 색 — 색 역할 판단

원본은 한 대상(물결 변위)에 한 색 띠, 골 짙게 · 마루 옅게였다. 고를 수 있던 것 —

- 발산형 같은 역할 양쪽(`interference` 의 선택) — 골 · 마루가 같은 짙기라 띠가 반 파장 간격이 된다 (G54). 이 조각은
  곧은 **물결**의 마루 · 골이 왼쪽 평면파와 이어지는 것도 보여야 해서 버렸다.
- 발산형 `low: 'ink'` · `high: 'secondary'` — 부호를 두 색으로 가른다. 「색으로 설명하지 않는다」 에 걸린다.
- 순차형 `high: 'ink'` (채택) — 한 역할의 짙기만으로 골 · 0 · 마루가 단조롭게 이어진다. 0 이 옅게 뜬다(G62).

강조색(`accent`)은 점파원 한 뜻에만 쓴다. 캡션의 `ink` 는 글자다.

## (b) 어휘 부족

### 장부에 있는 것

- **G01** — 「점을 1개로 줄였다」 캡션이 주기 번호에 달려 `step` 이 시계와 주기 길이를 따로 센다.
- **G07** — 짙은 장 위의 옅은 선에 쓸 바탕(반전) 색 역할이 없어 파면 자리 선을 `muted` 로 근사했다.
- **G13** — 캡션 울퉁불퉁 / 곧게 가 점 간격 · 파장에서 나오는데 단계 캡션이 그 계산을 받지 못해 손으로 적었다.
- **G24** — 캡션 자리가 프레이밍 여백으로 잡히지 않아 경계 아래에 빈 띠를 둔다.
- **G25** — 점파원 크기가 화면 px 고정이라 캔버스 배율을 따르지 않는다.
- **G51** — 첫 프레임 선언은 4 개로 적지만, 매 프레임 칸 21828 × 켜진 점(최대 33, 창 둘)을 scene 에서 합한다.
  실시간 프레임률은 확인하지 못했다(스크린샷은 가상 시간).
- **G62** — `scalarField` 섞기가 선형광 고정이라 순차형의 가운데(변위 0)가 원본 회청보다 훨씬 옅다. 약한 점파만 있는
  오른쪽 장이 밝게 떠 무늬 대비가 약하다. 원본의 세 점 색 띠(짙게 · 중간 · 옅게)를 옮길 사상이 없다.
- 원본 NOTES 가 바란 **점파원 합 장 계산기**(점마다 위치 · 위상 · 세기 · 켜짐 / 꺼짐 시각 → 인과 앞머리 · 꼬리까지 반영한
  합성 변위)는 어휘가 아니라 조각의 물리 계산이라 부족으로 세지 않았다 — `physics.ts` 에 둔다. 간섭 · 도플러가 같은 계산을
  다시 짜고 있으면 plugin 후보다.

### 새 부족

- **`particleSystem` 입자에 둘레 선(굵기 · 색)이 없다** — 영향 `근사`.
  원본 점파원은 주황 채움 + 짙은 테두리라 어떤 물결 무늬 위에서도 떨어져 보였다. 여기서는 테두리 없는 `accent` 점이라
  옅게 뜬 장 · 밝은 마루 위에서 경계가 흐려진다. 33 개라 낱개 `body`(G03 의 둘레 문제도 함께)로 풀지 않았다.
  G03 과 같은 계열이지만 G03 은 `body` 에 한정된 항목이다.
