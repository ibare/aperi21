# 부유체의 안정 — 이관 노트

원본: `tasks/piece-lab/stability-of-floating-body/` (손으로 짠 406줄, 자유 캔버스).
자유 렌더(`Bundle.renderers`) 없이 표준 어휘만으로 옮겼다.

## 쓴 어휘

| 원본 표시 | 어휘 |
|---|---|
| 물(위에서 아래로 짙어짐) | `scalarField` 순차형(`secondary`) — 값이 깊이 |
| 선체 단면 | `region` (`opaque`, `muted`) |
| 잠긴 단면 빗금 | `lineSet` — scene 이 사선을 잠긴 다각형으로 잘라 넘긴다 |
| 선체 윤곽 · 갑판 | `trajectory` (`closed` · 굵기 1.6 / 5) |
| 수압 분포 도형 | `region` 면마다 (배마다 최대 4) |
| 수압 화살 | `lineSet` — 축 + 꺾쇠 촉 |
| 부심 자취 | `trajectory` — 몸체 좌표로 쌓아 지금 자세로 돌려 놓음 |
| 중력 · 부력 작용선 | `trajectory` dashed |
| 짝힘 | `lineSet`(팔 막대 + 끝 눈금) · `sector`(채움 0, 테 2.2 px = 원호) · `region`(채운 촉) |
| 부심 · 무게중심 | `body` circle + `readout`(글자) |
| 수면 · 배 이름 | `trajectory` · `readout` |
| 흐려짐(주기 끝 0.3 초 · 다음 주기 첫 0.3 초) | `timeline` 세 단계 + 인스턴스 `opacity` |
| 캡션 | `caption` 슬롯 + `cases`(상태의 boolean 조합) |
| 무게중심 높이 | `slider` |

겹침이 그림이라 `drawOrder: 'scene'` 으로 원본 순서를 그대로 따랐다.
상태는 기울기 적분이라 `step` 이 쌓는다(고정 1/60 초 걸음, 걸음마다 4번 잘게). 원본에 미리
진행이 없어(t = 0 이 놓는 순간) `preroll` · `startAt` 은 두지 않았다.

## (a) 원본과 달라진 점과 이유

1. **캡션 · 조작기가 캔버스 안으로 들어왔다.** 원본은 290 px 캔버스 아래에 따로 두었다. 캔버스를
   440 px 로 잡고 물 아래 월드 0.98 m 를 바탕으로 비워 캡션 두 줄과 슬라이더를 담았다. 카메라 맞춤
   여백 때문에 그림 폭이 원본보다 약 8% 작다(900 px 촬영에서 약 780 px).
2. **뒤집힘 캡션을 더했다.** 원본 규칙은 균형각이 없는 높이(무게중심 0.80 m 이상 — 좁은 배가 완전히
   뒤집힘)에서도 20° 를 지나면 「부심이 무게중심 너머로 왔지만 기세로 더 기운다」 를 말해 화면과
   어긋났다. 90° 를 넘으면 「끝내 너머까지 가지 못해 뒤집혔다」, 균형각이 없으면 그 전까지 「못 미쳐
   점점 더 넘어간다」 를 유지한다. 기본값(0.70 m)의 문구 흐름은 원본과 같다(3.60 초 너머로 · 5.03 초
   흔들림 · 14 초 다시).
3. **색은 역할로.** 물 · 부력 쪽 파랑 = `secondary`, 무게 = `ink`, 선체 = `muted`, 짝힘 = `accent`
   하나. 다크 테마에서 선체가 짙은 판으로 보이고 물 위쪽이 바탕에 가깝다.
4. **무게중심 표지 속이 비친다.** 원본은 흰 원으로 속을 덮었다. 면에 쓸 바탕색 역할이 없어 테두리
   원 + 가운데 점으로 두었고, 부력 점선이 무게중심과 겹칠 때 고리 안으로 비친다(G72).
5. **원본의 화면 px 크기**(화살촉 · 끝 눈금 · 원호 반지름 · 점 반지름 · 사선 간격)를 원본 배율
   1 px = 0.01 m 로 월드에 옮겼다. 임베드 폭을 따라 함께 줄어든다(G25).
6. 실시간에서는 가변 dt 를 누적기로 고정 걸음에 맞춘다(G39). 주기 경계는 `step` 이 제 걸음 수로
   가르고 흐려짐은 시간표가 준다 — 둘은 같은 14 초를 센다(G01).

화면에 두지 않은 것은 원본 결정 그대로다 — 메타센터, 기울기 · 팔 길이 숫자, GZ 곡선.

### 새 부족

| 부족 | 영향 |
|---|---|
| **굽은 화살(원호 + 촉) 어휘가 없다.** 짝힘의 회전 방향을 `sector`(채움 0 · 테만) 원호와 `region` 채운 삼각형으로 조합하고, 촉 자리 · 접선 방향을 scene 이 계산한다. 방향이 뒤집힐 때 호 · 촉을 함께 뒤집는 일도 scene 몫이다 (원본 engineWish 「짝힘 표기」). 조합으로 원본과 같은 모양이 나온다 | 근사 |

조각의 물리 · 배치 계산(다각형 수면 절단 · 잠긴 넓이 도심 · 이분법 상하 맞춤 · 몸체 좌표 자취
회전 · 기울기별 복원 표)은 부족으로 올리지 않았다.

## (c) 근사로 주장이 약해졌는가

약해지지 않았다. 「부심이 기운 쪽으로 옮겨 간다 — 넓은 배는 무게선을 넘어 되세워지고, 좁은 배는 못
미쳐 넘어간다」 가 probeTimes 0 · 2 · 4 · 6 · 10 초 대조 스크린샷에서 원본과 같은 자세 · 같은 짝힘 방향 · 같은 캡션으로
일어난다(2 초 갑판 기울기를 두 화면에서 재어 넓은 배 약 6.9° · 좁은 배 약 15° 로 일치). 빛 채널은 쓰지 않았다(밝기가
주장인 곳이 없다).
