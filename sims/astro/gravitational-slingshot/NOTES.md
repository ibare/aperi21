# gravitational-slingshot — 제작 기록

자유 구현 원본 없이 엔진 어휘 위에서 바로 지었다.

## (a) 답하는 질문과 동사

**질문** — 행성 곁을 스쳐 지나기만 했는데 탐사선은 왜 빨라지는가? 중력은 들어올 때 당긴 만큼
나갈 때 도로 당기지 않는가?

**동사** — **빨라진다.** 같은 비행이 태양 틀에서만 점 간격을 벌리며, 더 긴 화살표로 떠난다.

같은 비행 하나를 같은 시계로 두 판에 나란히 그린다.

- **왼쪽 · 행성과 함께 보면** — 행성은 가만히 있고 탐사선은 쌍곡선을 그리며 행성 뒤를 돈다.
  같은 시간 간격으로 찍은 점의 간격이 들어올 때와 나갈 때 같고, 두 끝의 화살표 `u` · `u` 도 같은
  길이다. 방향만 120° 꺾였다. 「중력은 들어올 때 당긴 만큼 나갈 때 도로 당긴다」 가 여기서 선다.
- **오른쪽 · 태양에서 보면** — 행성이 공전 속도 `V` 로 오른쪽으로 달린다. 들어오는 점은 촘촘하고
  (`v₁` 짧음), 나가는 점은 넓게 벌어진다(`v₂` 가 `v₁` 의 두 배 넘음). 탐사선이 **눈앞에서 빨라진다.**
- **이어 붙인 삼각형** — 오른쪽 판 두 끝에서 `V` 를 먼저 놓고 그 끝에 점선 `u`(왼쪽 판의 화살표와
  같은 길이 · 같은 방향)를 이으면 `v` 의 머리에 닿는다. 같은 `V` 를 더했는데, 들어올 때의 `u` 는
  `V` 와 반대쪽을, 나갈 때의 `u` 는 같은 쪽을 본다 — 그래서 `v₂` 가 길다. 두 틀 사이의 다리가
  이 삼각형이다.
- 마지막 캡션이 늘어난 에너지는 행성의 공전에서 빌려 왔다고 말한다.

물리는 행성 틀의 쌍곡선 케플러 궤도(`e·sinh H − H = nτ`)를 시각마다 곧바로 풀고, 태양 틀은
행성의 등속 운동을 더한 것뿐이다(갈릴레이 변환). 상태가 없다.

이웃과 겹치지 않게 머문 자리 — 엔진으로 밀어 궤도를 옮기는 것(`orbital-transfer`)은 여기서
하지 않는다. 엔진은 한 번도 켜지지 않는다. 늘어난 빠르기는 전부 틀을 바꾼 데서 나온다.

## (b) 화면 구성의 결정

**둔 것**

| 무엇 | 왜 |
| --- | --- |
| 두 판 나란히 · 같은 시계 | 「같은 비행」 이라는 것이 주장의 전제다. 한 판에서 틀을 바꾸면 두 모습을 기억으로 견줘야 한다. 비행이 세로로 길어 가로로 나란히 두면 세로를 한 번만 쓴다 |
| 판 이름표 둘(「행성과 함께 보면」 · 「태양에서 보면」) | 판이 둘이면 어느 틀인지 말해야 한다. 제목이 아니라 판의 이름이다. 두 판의 빈 위 모서리(왼쪽 판은 왼쪽 위, 오른쪽 판은 오른쪽 위)에 넣어 줄을 따로 쓰지 않는다 |
| 같은 시간 간격 점(`trace`) | 동사 「빨라진다」 를 숫자 없이 보이는 장치다. 두 판이 **같은 순간에** 찍으므로 점 개수가 같고 간격만 다르다. 가장 가까운 순간 점이 벌어지는 것(행성 곁에서 빠른 것)도 두 판에 같이 보인다 |
| 들어올 때 · 나갈 때 화살표만 | 비행 중 탐사선에 화살표를 달면 행성 곁에서 길어졌다 줄어드는 것이 「들어올 때와 나갈 때가 같다」 를 흐린다. 들어오는 화살표는 머리가 출발 자리에, 나가는 화살표는 꼬리가 끝 자리에 붙어 길 바깥에 놓인다 — 점과 겹치지 않는다 |
| 나가는 화살표는 비행이 끝난 뒤 나타남 | 비행 중에는 점 간격이 말하게 두고, 끝난 뒤 길이로 한 번 더 확인한다 |
| 행성 속도 `V`(secondary) · 공전 길(점선) | 오른쪽 판에서 행성이 달리고 있다는 것이 틀의 차이 전부다. 태양은 화면 밖 멀리 있어 이 구간의 공전 길은 곧다 |
| 삼각형의 `V` 는 행성의 `V` 와 같은 색 · 같은 길이, `u` 는 왼쪽 판 `u` 와 같은 색 · 점선 | 같은 물리량은 같은 색이다. `u` 를 점선으로 둔 것은 그것이 이 판의 속도가 아니라 **옆 판에서 옮겨 온** 속도라서다 |
| 삼각형 세 변의 이름표를 삼각형 **바깥**에 고정 | `auto` 로 두면 `v₁` 의 이름이 삼각형 안에서 `u` 와 겹쳤다(첫 촬영) |
| 행성 뒤를 도는 배치 · 꺾임의 두 방향이 행성 진행 방향에 수직인 축을 두고 대칭 | 같은 꺾임 각에서 속도를 가장 크게 얻는 배치다. 행성 앞을 지나면 오히려 느려지는데, 그것은 이 조각의 주장이 아니다 |
| 조작기 없음 | 답은 한 주기 안에 끝난다. 꺾임 각 · 행성 속도를 끌게 하면 「얼마나 빨라지나」 라는 다른 질문이 되고, 나가는 화살표가 판 밖으로 나가 프레이밍이 무너진다 |

**두지 않은 것**

| 무엇 | 왜 |
| --- | --- |
| 속력 수치(`|v₁|` · `|v₂|` 칩) | 월드 단위계라 수에 단위가 없고, 비율을 코드로 계산해 띄우면 유효숫자 문제가 된다. 길이와 점 간격이 이미 말한다 |
| 행성이 느려지는 것 | 행성 질량이 탐사선의 수십억 배라 그 몫은 그림에 보일 크기가 아니다. 억지로 보이면 거짓말이 된다 — 캡션이 「너무 무거워 드러나지 않는다」 고 말하는 것으로 둔다 |
| 태양 · 굽은 공전 궤도 | 비행이 걸리는 짧은 시간에 공전 길은 곧다. 태양을 두면 판이 커져 세로가 먼저 찬다 |
| 에너지 막대 · 그래프 | 에너지는 캡션의 한 문장으로 충분하다. 막대를 두면 조각이 둘이 된다 |
| 행성 틀 판의 「태양 방향」 표시 | 왼쪽 판은 행성과 함께 움직이는 틀이라 태양 쪽이 흐른다. 이름표 하나로 틀을 말한다 |
| 강조색 | 견줄 것이 길이와 간격이라 한 가지 뜻을 따로 칠할 자리가 없다 |
| 그리드 | 견줄 것은 거리가 아니라 같은 시간 간격 점의 간격이다 |

## (c) 어휘 부족

| 장부 | 무엇이 없어서 | 영향 |
| --- | --- | --- |
| G10 | 판 단위 좌표계가 없다 — 두 판을 한 월드에 두려고 인스턴스마다 판 원점을 더한다(`at(origin, p)`). 행성 틀 → 태양 틀도 「원점 + 행성 이동」 을 scene 이 더한다 | 근사 |
| G108 | 화살표를 꼬리-머리로 잇는 묶음이 없다 — 삼각형의 `V` 끝에 `u` 를 잇는 자리와 들어오는 `v₁` 의 꼬리(머리가 출발 자리에 닿도록)를 scene 이 계산한다 | 근사 |

### 새 부족

없다. 쓴 것은 `body` · `trajectory`(길 · 공전 점선 · 판 경계) · `trace`(같은 시간 간격 점) ·
`vector`(`labelSide` · `lineStyle: 'dashed'` · `width`) · `readout`(판 이름표, `chip: false` ·
`align` · `weight`) 과 선언 `timeline` · `startAt` · `caption`(화면 아래 슬롯) · `drawOrder: 'scene'` ·
`canvas` · `boundsHint` 다.

`pnpm -s piece:report --sims=http://localhost:5173/aperi21/ gravitational-slingshot`, 시각 0.5 · 2.6 · 3.6 ·
7 · 11 · 15 를 라이트 · 다크로 열어 보았다.

| t | 라이트 | 다크 |
| --- | --- | --- |
| 0.5 | 선다 — 두 판에 점 다섯씩, 오른쪽 점이 더 촘촘하다. `u` 가 `v₁` 보다 길다 | 선다 — 먹색 점이 밝게 뒤집혀 읽힌다 |
| 2.6 | 선다 — 두 탐사선이 행성 뒤 같은 곡선 자리에 있고, 오른쪽 행성만 옮겨 가 있다 | 선다 |
| 3.6 | 선다 — 왼쪽 나가는 점 간격이 들어올 때와 같고, 오른쪽은 들어올 때보다 확연히 넓다 | 선다 |
| 7 | 선다 — 왼쪽 `u` · `u` 같은 길이, 오른쪽 `v₂` 가 `v₁` 의 두 배 넘게 길다 | 선다 |
| 11 | 선다 — 두 끝의 삼각형 `V` + 점선 `u` = `v`. 이름표가 삼각형 바깥에 겹치지 않고 놓인다 | 선다 — 파랑 `V` 와 빨강 `u` 가 다크에서도 갈린다 |
| 15 | 선다 — 캡션이 한 줄로 두 판 아래에 걸린다 | 선다 |

남은 약점 — 캔버스 폭이 넓으면(카탈로그 약 850 px) 세로가 먼저 차서 좌우에 여백이 남는다. 비행이
세로로 긴 모양이라 생긴 일이고, 세로를 더 주는 대신(440 px) 여백을 받아들였다.
