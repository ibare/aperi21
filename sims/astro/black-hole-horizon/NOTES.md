# black-hole-horizon — 사건 지평선

자유 구현 원본이 없다. 엔진 어휘로 곧바로 지었다. 자유 렌더(`Bundle.renderers`) 없음.

쓴 어휘: `body`(별 · 빛 펄스) · `trajectory`(지평선 점선 원 `closed` · `lineStyle: 'dashed'`, 펄스 꼬리 `fade: 'tail'`,
막대 길 · c 선) · `region`(탈출 속도 막대 `opaque`) · `readout`(반지름 글자 · 지평선 이름표 · 막대 이름 · c 이름),
선언 `timeline` · `startAt` · `caption`(월드 앵커) · `drawOrder: 'scene'` · `canvas`. 상태 없음, `step` 항등.

## (a) 답하는 질문과 동사

**질문** — 같은 질량을 점점 작게 짜부라뜨리면 표면에서 쏜 빛은 어떻게 되는가.

**주장** — 질량은 그대로 두고 반지름만 줄이면 표면의 탈출 속도 √(2GM/R) 가 커지다가, R = 2GM/c²
(태양 질량이면 약 3 km)에서 광속이 된다. 그 안으로 짜부라뜨린 별의 표면에서 바깥으로 쏜 빛은 지평선을
넘지 못하고 되돌아온다 — 그 반지름이 안과 밖을 가르는 지평선이다.

**동사** — *짜부라진다 → (막대가 c 에) 닿는다 → (빛이) 되돌아온다.*

화면에서 일어나는 방식 —

- 별은 왼쪽(먹색 원판), 빛은 강조색 점과 꼬리, 오른쪽 아래가 「표면의 탈출 속도」 막대와 c 선이다.
- `sun-*` — 화면 왼쪽을 채운 거대한 별(반지름 696000 km). 표면에서 쏜 빛이 오른쪽 끝으로 빠져나간다.
  멈춤마다 `-before`(펄스 전) · `-pulse`(빛이 표면을 떠나 화면 끝을 벗어날 때까지) · `-after`(펄스 뒤) 셋으로
  쪼개 시간표에 선언했다 — 캡션은 셋이 같은 키를 되풀이해 한 문장이다.
  막대는 보이지 않는다(광속의 0.2 %).
- `squeeze1` → `dwarf-*`(7000 km) → `squeeze2` → `neutron-*`(12 km) — 줄일 때마다 막대가 자라고, 멈출 때마다
  다시 쏜 빛이 빠져나간다. 12 km 에서 막대는 c 선의 절반쯤이다.
- `squeeze3` — 별이 더 줄며 그 **안쪽에** 점선 지평선 원이 떠오른다(질량이 그대로라 원의 크기는 처음부터
  그대로다). 표면이 원에 내려앉는 순간 막대 끝이 c 선에 닿는다.
- `horizon` — 표면 = 지평선. 원 위에 「사건 지평선 · 약 3 km」.
- `squeeze4` — 별이 지평선의 절반으로 더 줄어 원 안으로 들어간다. 막대는 c 선을 넘는다.
- `trapped-*` — `trapped-pulse` 동안 표면에서 사방(여덟 방향)으로 쏜 빛이 느려지다 **모두 지평선 원에서 멈추고** 떨어져 표면으로
  돌아온다. 앞의 세 번은 같은 빛이 화면 끝으로 나갔다 — 달라진 것은 반지름뿐이다.

물리는 닫힌 식이다 — 반지름은 멈춤 사이를 로그 등간격으로 줄이고(`TimelineFrame.at()` 의 합), 지평선 안의
빛은 반지름 방향 케플러 해(r = a(1 − cos E))를 이분법으로 푼다. 같은 시각은 언제나 같은 화면이다.

## (b) 화면 구성의 결정 — 두지 않은 것 포함

- **뉴턴식 문턱은 근사다.** 「탈출 속도가 광속이 되는 반지름」 으로 지평선을 정의하는 것은 18 세기 미첼 ·
  라플라스의 「어두운 별」 논증이다. 뉴턴식 √(2GM/R) = c 를 풀면 R = 2GM/c² 가 나오는데, 이것이 일반
  상대론의 슈바르츠실트 반지름과 **우연히 같은 값**일 뿐 같은 물리가 아니다. 뉴턴 그림에서 빛은 알갱이처럼
  느려지고, 올라갔다가 떨어진다. 일반 상대론에서 빛은 국소적으로 늘 c 로 움직이며, 지평선 안에서는 바깥으로
  쏜 빛도 반지름이 **줄어드는** 쪽으로만 간다 — 「올라갔다 떨어진다」 는 모양 자체가 없다. 막대가 c 를 넘는
  것도 뉴턴식의 값이다. 이 조각은 글 한 문단(탈출 속도 → 지평선)에 붙는 그림이라 그 논증의 언어를 따르고,
  캡션은 「지평선을 넘지 못한다」 까지만 말한다.
- **마지막 반지름을 지평선의 절반(`insideFactor` 0.5)으로 둔 이유.** 뉴턴 그림에서 반지름 R(< Rs)의 표면에서
  광속으로 쏜 빛이 가장 높이 오르는 곳은 R/(1 − R/Rs) 다. R 이 Rs 에 가까우면 이 값이 지평선보다 멀어져, 빛이
  원 밖으로 나갔다가 돌아오는 그림이 된다 — 「지평선이 안과 밖을 가른다」 와 어긋나고 일반 상대론과도 틀린다.
  R = Rs/2 이면 정확히 지평선에서 돌아선다. 이 값보다 크게 바꾸면 그림이 위 어긋남을 보인다.
- **반지름을 눌러 그린다.** 696000 km 와 1.5 km 를 한 화면에 선형으로 담을 수 없다. 지평선의 두 배
  (`linearUpTo`)까지는 그대로 비례하게, 그 밖은 한 자리수마다 `worldPerDecade`(0.2 월드)만 커지게 그린다.
  그래서 태양 → 7000 km(100 배)가 화면에서는 조금 줄어드는 것으로 보인다. 크기는 **반지름 글자**가 말한다.
  **지평선 원은 별이 선형 구간에 들어온 뒤에만 나타난다** — 눌러 그린 곳에서 원을 그리면 「지평선이 태양
  반지름의 3 분의 1」 처럼 비율이 거짓말을 한다(실제는 23 만 분의 1).
- **막대는 선형이다.** 누르지 않는다. 태양 크기에서 막대가 보이지 않는 것이 주장의 절반(「거의 0 이다가」)이라
  그대로 둔다.
- **빛이 빠져나가는 샷의 화면 시간은 따로 줄인다.** 빛은 펄스 단계(`sun-pulse` 등) 동안 표면에서
  화면 끝 너머까지 고르게 간다. 떠나는 때와 끝나는 때는 시간표의 단계 경계다 — 코드는 `tl.at()` 만 읽는다. 느려지는 모양(12 km 에서 약간)은 그리지 않는다 — 그 샷의 주장은 「나간다」 뿐이다.
  지평선 안의 샷은 물리 시각에 비례해(케플러 방정식) 꼭대기에서 느려지는 모양이 그대로다.
- **지평선 안에서는 사방으로 쏜다.** 한 방향만 쏘면 「그쪽이 우연히 막혔다」 로 읽힐 수 있다. 여덟 방향이 같은
  원에서 멈춘다. 방향을 반 칸 돌려(`TRAPPED_RAY_PHASE`) 꼭대기의 지평선 이름표를 가리지 않게 했다(두 번째 촬영 20.7 에서 겹침).
  빠져나가는 샷은 오른쪽 하나다 — 사방으로 쏘면 캡션 · 막대 위로 빛이 지나간다.
- **지평선 반지름의 수는 선언값(`horizonLabelKm` 3)을 쓴다.** 2GM/c² 를 계산하면 2.95… 인데 화면에 계산값을
  줄여 적지 않는다(S-piece 유효숫자). 탈출 속도의 수(618 km/s 등)도 띄우지 않는다 — 막대와 c 선의 거리가
  말하고, 수를 띄우면 독자가 막대 대신 수를 읽는다. 마지막 반지름(1.5 km)도 적지 않는다 — 계산값이다.
- **질량을 글자로 두지 않았다.** 「질량은 그대로」 는 캡션(`caption.squeeze`)이 말하고, 지평선 원이 처음부터 같은
  크기라는 것이 그림으로 받친다.
- **색.** 별 먹색, 빛 강조색(이 조각에서 강조색의 뜻은 「빛」 하나), 지평선 원 · 이름표 primary 점선, 막대 secondary,
  막대 길 muted, c 선 먹색. 빠져나가는 빛과 되돌아오는 빛을 다른 색으로 칠하지 않는다 — 움직임이 말한다.
- **이웃을 되풀이하지 않는다.** 곧장 위로 쏘는 레인 · 속도 문턱(`escape-velocity`), −GM/r 우물과 에너지 선
  (`gravitational-potential-energy-general`)은 두지 않았다. 여기서 바뀌는 것은 쏘는 속도가 아니라 반지름이다.
- **조작기 없음.** 반지름 슬라이더는 선형 구간과 눌러 그린 구간을 한 손잡이로 오가야 해, c 에 닿는 순간을
  짚기 어렵다. 다섯 멈춤의 자동 진행이 한다.
- `startAt: 1.0` — 도착한 순간 거대한 별 표면에서 빛이 이미 떠나 있다. 쌓는 상태가 없어 `preroll` 은 쓰지 않는다.
- `drawOrder: 'scene'` — 별 위에 지평선 원, 그 위에 빛.
- 그리드 · 카메라 단추 · 제목 · 범례 없음(기본값). 눌러 그린 구간이 있어 격자로 거리를 잴 수 없다.
- 물리량(G · M · c · 멈춤 반지름 셋 · `insideFactor` · 이름표 반지름)과 표현 배율(`horizonWorld` · `linearUpTo` ·
  `worldPerDecade` · `barLength`)은 모두 `stages[].constants` 에 있고 `readConstants` 가 기본값과
  함께 읽는다. 막대 · 캡션 자리와 `SCENE_BOUNDS` 는 배치 상수다.

## (c) 어휘 부족

**주장 부족 없음.** 근사한 곳은 선언의 관계 문제다.

| 장부 | 이 조각에서 | 영향 |
| --- | --- | --- |
| G105 | 멈춤 반지름 셋을 목록으로 선언할 수 없어 `radius1Km`~`radius3Km` 로 흩고, 멈춤 단계 id(`STOP_PHASES`) · 줄이기 단계 id(`SQUEEZE_PHASES`)와 짝짓는 것이 코드에 있다 | 근사 |
| G13 | 단계에 값을 실을 수 없다 — 「이 멈춤의 반지름」 을 단계가 들지 못해 위 짝짓기가 필요하다 | 근사 |
| G24 | 캡션 자리가 프레이밍 여백으로 잡히지 않아 `SCENE_BOUNDS.maxY` 와 `CAPTION_AT` 을 손으로 맞췄다 | 근사 |

새 부족: 없음. 반지름의 눌러 그리기(선형 + 로그), 지평선 안 반지름 방향 케플러 해, 여덟 방향 배치는 조각의
물리 · 배치 계산이다.

## (d) 주장이 화면에서 서는가

| t(초) | 단계 | 라이트 · 다크 |
| --- | --- | --- |
| 0.5 | sun-pulse | 거대한 별이 왼쪽을 채우고(위아래 · 왼쪽으로 넘침), 「반지름 696000 km」 곁에서 빛 펄스가 꼬리를 끌며 오른쪽으로 나간다. 막대는 시작점의 가는 금뿐 |
| 9.7 | neutron-pulse | 별이 작아졌다(「반지름 12 km」). 막대가 c 선의 절반쯤. 빛은 여전히 나간다 |
| 14.9 | horizon | 표면에 점선 지평선 원이 겹쳤고 「사건 지평선 · 약 3 km」 가 선다. 막대 끝이 c 선에 정확히 닿았다 |

| 21.9 | trapped-pulse | 여덟 펄스가 원 안쪽으로 떨어지는 중 — 꼬리가 원 쪽에서 끌려온다 |

- 펄스 창을 시간표 단계(전 · 펄스 · 뒤)로 옮긴 뒤 같은 다섯 시각을 다시 찍었다 — 단계 길이를 창 비율 × 원래 길이로 잡아
  경계 시각이 그대로라 다섯 장 모두 위 표와 같다.
- 촬영 목록 밖에서 12.6(`squeeze3`)도 찍어 보았다 — 별 안쪽에 점선 원이 떠오르고 막대가 c 선에 다가간다.
  라이트에서 먹색 원판 위의 붉은 점선이 조금 어둡지만 읽힌다.
- **다크** — 별이 밝은 미색 원판(`ink` 가 뒤집힌다)이고 빛은 금빛, 지평선 원은 밝은 빨강 점선으로 갈린다.
  뒤집혀 뜻이 바뀐 것 없음(별이 밝은 것은 별이라 어색하지 않다).
- **라이트** — 별 먹색, 빛 황토, 원 빨강 점선, 막대 파랑. 글자 겹침 · 화면 밖으로 나감 없음.
- 촬영하며 두 가지를 고쳤다 — 그림 전체가 작아(지평선 반지름 약 50 px, 되돌아오는 빛이 25 px 움직임) 경계를
  좁히고 로그 압축을 줄였고, 곧장 위로 쏜 펄스가 지평선 이름표를 가려 방향을 반 칸 돌렸다.
