# tidal-force — 이관 NOTES

원본: `tasks/piece-lab/tidal-force/` (자유 구현). 자유 렌더(`Bundle.renderers`) 없이 표준 어휘로만 옮겼다.

주장: 천체로 함께 떨어지는 먼지 구름은 가까운 쪽이 더 세게, 먼 쪽이 더 약하게 끌려, 구름 가운데에서
보면 **양쪽으로 늘어난다.**

## 쓴 어휘

| 원본 묶음 | 어휘 |
|---|---|
| 천체의 중력장 (방사형 그라데이션) | `scalarField` 순차형 하나 — 캔버스 전체 215 × 75 칸(4 px)에 세기를 적는다 |
| 천체 | `body` circle (`glow: false`, `outline: 'none'`) |
| 확대 구역 꺾쇠 | `trajectory` 꺾은선 넷 |
| 먼지 구름 · 확대한 먼지 | `particleSystem` 둘 (같은 상태, 좌표만 다름). 왼쪽은 `shape: 'square'` |
| 양 끝 먼지 · 벗어난 거리 | `body` circle + `trajectory` (강조색은 이 뜻에만) |
| 확대 화면 바탕 | `region` `opaque` + `fillOpacity: 0` |
| 조석 잔차장 흐름 무늬 | `lineSet` 하나 — 획 하나가 선 하나, 짙기는 선별 `opacities` |
| 고르게 끌렸다면 있었을 자리 | `trajectory` closed dashed |
| 확대 화면 테두리 · 이름 | `trajectory` closed + `readout` |
| 두 판 경계 | 인스턴스마다 `clip` |
| 한 바퀴 (보통 → 0.3 배 → 멈춘 채 흐려짐 → 초기화) | `timeline` 세 단계 (`slow.timeScale: 0.3`) · `drawOrder: 'scene'` |
| 잰 값으로 고르는 캡션 | `caption.cases` (`when: 'stretched'`) |

한 프레임 선언 수는 **19** 다 (2026-09-17 묶음 그리기 전 215 — 원판 56 · 흐름 획 142 안팎이 빠졌다).

상태는 누적이다 — 입자 170개를 `step` 이 1/60 초 이하 걸음으로 실제 적분한다. 매 주기 시작마다
원본 `PREROLL` 1 초만큼 미리 떨어뜨리는 것은 `resetCloud` 가 하고(`stage.constants.headStart`),
주기마다 되풀이되므로 `schema.preroll` · `startAt` 이 아니다(둘 다 0). 원본도 시계를 앞당기지 않고
`reset()` 안에서 물리만 1 초 흘렸다.

### 색 판단

음영(`scalarField`)은 역할 하나(`secondary`)의 **순차형**이다 — 값이 중력의 세기를 명암으로 보일 뿐
대상을 색으로 가르지 않는다. 흐름 무늬도 같은 대상(중력)이라 같은 역할이다. 먼지는 두 판 모두 한 색
(`ink`)이고 역할별로 가르지 않는다. 강조색(`accent`)은 「천체를 잇는 직선 위 양 끝 먼지」 한 뜻뿐이다.

## (a) 원본과 달라진 점

- **색** — 테마 역할로 옮겼다. 먼지 `ink` medium, 천체 `muted` strong, 틀·꺾쇠 `muted` subtle,
  점선 원·이름 `muted` medium, 강조 `accent`(테마의 갈색 — 원본 주황빨강보다 흐리다).
  흐름 무늬는 `secondary` `subtle` — 원본의 옅은 푸른 회색(`#7f95ad`)에 짙기가 가장 가까운 조합이다.
  `strong` 은 흐름 무늬가 먼지와 강조색을 눌러 버렸다 (G08).
- **음영의 짙기와 색조** — `scalarField` 는 바탕 → `secondary` 를 **선형광에서** 섞고 강조 단계를 받지
  않는다. 원본은 옅은 색을 알파 `0.42 × 세기` 로 화면값에서 겹쳤다. 기본 밝은 테마에서 바탕 대비 밝기를
  맞춰 보면 섞는 비율이 세기의 0.40~0.45 배라, 값은 원본과 같은 세기(1/r², 정지점 15 선형 보간)를 두고
  범위 끝을 `1 / 0.42` 로 잡았다. 짙기의 떨어짐은 원본과 같고, 크림색 바탕에 파랑이 섞여 천체 곁이
  원본보다 **약간 보랏빛**이다. 원판 56장일 때 천체 곁에 남던 동심 이음매는 사라졌다.
- **캡션 자리** — 원본은 캔버스 아래 HTML 문단, 여기서는 캡션 슬롯(캔버스 왼쪽 아래)이다. 캔버스
  높이를 380 으로 잡아 두 줄 자리를 남겼다.
- **배율** — 임베드 폭에서 원본 860 px 이 1 배보다 작게(대조 화면에서 약 0.9 배) 그려진다. 화면 px 로 고정된 것(먼지 점 크기 ·
  선 굵기 · 이름 글자 13 px)은 따라 줄지 않아 원본보다 조금 도드라진다 (G25).
- **왼쪽 먼지 점** — 원본과 같은 2 × 2 px 사각형이다 (`shape: 'square'`, 반변 1).
- **흐름 무늬 짙기 단계** — 원본은 획마다 알파가 연속이다. `lineSet` 은 선별 불투명도를 8 단계로 묶어
  단계마다 경로 하나로 긋는다 — 1/8 간격으로 반올림되고 1/16 아래 획은 그리지 않는다. 획이 나타났다
  사라지는 흐름이 약간 계단져 보일 수 있으나 대조 화면에서 무늬의 모양 · 세기 분포는 같다 (새 부족 N5).
- **점선 무늬** — 원본 4/4 px, 엔진 고정 6/5 px (G05).
- **적분 걸음** — 원본은 실시간에서도 고정 1/60 걸음을 누적한다. 여기서는 엔진이 주는 dt 를 1/60
  이하로 쪼갠다. 검사 시각 이동(`?t=`)에서는 걸음이 원본과 같아 대조 화면의 입자 배치가 일치한다.
- **흐름 무늬 위상** — 원본은 화면 시각으로 돈다(느린 단계에서도 보통 빠르기). 조각 시계는 느린
  단계에서 느리게 흐르므로 `screenClock` 이 단계별 `timeScale` 로 나눠 화면 시각을 되돌린다 (G42).

대조 (`tasks/piece-lab/_report/_scratch/tidal-force/shots/`, 2026-09-17 묶음 그리기 뒤 다시 찍음) —
t = 0 · 3 · 4.6 · 6 네 시각 모두 입자 배치 · 늘어난 길이 · 양 끝 벗어난 거리 · 흐름 무늬 · 음영 ·
캡션 전환이 원본과 같은 모양이다.

## (b) 어휘 부족

### 장부에 있는 것

- **G01** — `step` 이 시간표를 받지 못한다. 흐려지는 단계에서 적분을 멈추고 주기가 넘어갈 때 구름을
  되돌리려고, `step` 이 `schema.timeline.phases` 를 직접 읽어 주기 길이와 멈춤 시각을 다시 계산하고
  자기 시계(`state.clock`)를 센다.
- **G05** — 점선 원의 대시 길이 · 간격을 선언할 수 없다.
- **G08** — 원본의 옅은 푸른 회색(장)에 맞는 색 역할이 없어 `secondary` `subtle` 로 눈대중했다.
  음영은 `scalarField` 가 강조 단계를 받지 않아 값의 범위로 짙기를 맞췄다.
- **G09** — 흐려지는 단계에서 움직이는 것 전부를 한꺼번에 흐리는 묶음 불투명도가 없어 인스턴스마다
  `opacity` 를 곱한다. 흐름 무늬가 `lineSet` 하나가 되어 곱하는 곳은 14 군데로 줄었다.
- **G10** — 판 단위 좌표계가 없다. 같은 입자 상태를 정지틀(0.95 배)과 함께 떨어지는 틀(중심을 빼고
  1.4 배)로 그리는 두 보기 변환을 scene 이 인스턴스마다 좌표로 옮기고, 판 경계는 인스턴스마다 `clip`,
  판 바탕은 `region` `opaque` + `fillOpacity: 0` 으로 깐다.
- **G25** — 화면 px 크기(점 · 굵기 · 글자)가 배율을 따르지 않는다.
- **G31 그라데이션 채움** — 이 조각에서는 **해결됨 (2026-09-17 묶음 그리기)**. 방사형 그라데이션을
  `scalarField` 격자로 칠한다 — 원판 56장 누적 알파(옛 N1)를 지웠다. 선형광 섞기로 색조가 조금 다른 것은
  위 (a) 「음영의 짙기와 색조」.
- **G41 벡터장을 흐르는 획** — **해결됨 (2026-09-17 묶음 그리기)**. 획마다 `trace` 인스턴스(최대 약 156개,
  옛 N2)를 `lineSet` 하나로 묶었다. 「방향 = 흐르는 쪽, 세기 = 길이 · 짙기, 위상 = 시각」 규약은 여전히
  조각이 격자 칸마다 계산한다 — 어휘가 준 것은 선언 · 그리기를 묶는 것이지 장 그리기 규약이 아니다.
- **G42 화면 시각** — 영향 `근사`(옛 N3). `TimelineFrame` 에 재생 속도를 적용하기 전의 화면 시각이 없다.
  느린 단계에서도 보통 빠르기로 흘러야 하는 장식적 움직임(흐름 무늬 위상)을 위해 조각이 단계별
  `timeScale` 로 역산한다.
- **G43 `particleSystem` 점 모양** — **해결됨 (2026-09-17 묶음 그리기)** (옛 N4). `shape: 'square'`.
- **G51 인스턴스 수 성능** — 이 조각의 한 프레임 선언은 215 → 19 개가 됐다.

### 새 부족

- **N5 선별 · 입자별 불투명도의 단계 묶음** — 영향 `근사`. `lineSet` · `particleSystem` 의 `opacities`
  는 8 단계로 반올림되고 1/16 아래는 그리지 않는다. 원본 흐름 획은 알파 `(0.1 + 0.75s) × sin(π·위상)`
  으로 연속으로 나타났다 사라진다 — 획 하나의 짙기가 단계를 건너뛰며 바뀐다. 정지 화면에서는 구별되지
  않고, 움직일 때 가장 옅은 끝(나타나기 직전 · 사라지기 직전)이 조금 일찍 끊긴다.

조각의 물리(입자 170개 반암시적 오일러 적분 · 시드 난수 · 늘어남 판정)는 부족으로 올리지 않았다.

### 근사가 주장을 약하게 했는가

약해지지 않았다. 동사(양쪽으로 늘어난다)는 실제 적분된 입자와 점선 원 · 강조색 변위로 일어나고,
남은 근사는 음영 색조와 흐름 획 짙기의 단계에만 걸려 있어 화면에서 원본과 같은 모양으로 읽힌다.
