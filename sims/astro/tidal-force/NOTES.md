# tidal-force — 이관 NOTES

원본: `tasks/piece-lab/tidal-force/` (자유 구현). 자유 렌더(`Bundle.renderers`) 없이 표준 어휘로만 옮겼다.

주장: 천체로 함께 떨어지는 먼지 구름은 가까운 쪽이 더 세게, 먼 쪽이 더 약하게 끌려, 구름 가운데에서
보면 **양쪽으로 늘어난다.**

## 쓴 어휘

| 원본 묶음 | 어휘 |
|---|---|
| 천체의 중력장 (방사형 그라데이션) | `region` 동심 원판 56장 — 누적 알파 근사 (새 부족 N1) |
| 천체 | `body` circle (`glow: false`, `outline: 'none'`) |
| 확대 구역 꺾쇠 | `trajectory` 꺾은선 넷 |
| 먼지 구름 · 확대한 먼지 | `particleSystem` 둘 (같은 상태, 좌표만 다름) |
| 양 끝 먼지 · 벗어난 거리 | `body` circle + `trajectory` (강조색은 이 뜻에만) |
| 확대 화면 바탕 | `region` `opaque` + `fillOpacity: 0` |
| 조석 잔차장 흐름 무늬 | `trace` `tick` — 획마다 인스턴스 하나 (새 부족 N2) |
| 고르게 끌렸다면 있었을 자리 | `trajectory` closed dashed |
| 확대 화면 테두리 · 이름 | `trajectory` closed + `readout` |
| 두 판 경계 | 인스턴스마다 `clip` |
| 한 바퀴 (보통 → 0.3 배 → 멈춘 채 흐려짐 → 초기화) | `timeline` 세 단계 (`slow.timeScale: 0.3`) · `drawOrder: 'scene'` |
| 잰 값으로 고르는 캡션 | `caption.cases` (`when: 'stretched'`) |

상태는 누적이다 — 입자 170개를 `step` 이 1/60 초 이하 걸음으로 실제 적분한다. 매 주기 시작마다
원본 `PREROLL` 1 초만큼 미리 떨어뜨리는 것은 `resetCloud` 가 하고(`stage.constants.headStart`),
주기마다 되풀이되므로 `schema.preroll` · `startAt` 이 아니다(둘 다 0). 원본도 시계를 앞당기지 않고
`reset()` 안에서 물리만 1 초 흘렸다.

## (a) 원본과 달라진 점

- **색** — 테마 역할로 옮겼다. 먼지 `ink` medium, 천체 `muted` strong, 틀·꺾쇠 `muted` subtle,
  점선 원·이름 `muted` medium, 강조 `accent`(테마의 갈색 — 원본 주황빨강보다 흐리다).
  중력장 음영과 흐름 무늬는 같은 대상(중력)이라 같은 `secondary` `subtle` 이다. 원본의 옅은 푸른
  회색(`#7f95ad`)에 짙기가 가장 가까운 조합이고, 원본보다 약간 옅고 약간 더 푸르다. `strong` 은
  흐름 무늬가 먼지와 강조색을 눌러 버려 버렸다 (G08).
- **캡션 자리** — 원본은 캔버스 아래 HTML 문단, 여기서는 캡션 슬롯(캔버스 왼쪽 아래)이다. 캔버스
  높이를 380 으로 잡아 두 줄 자리를 남겼다.
- **배율** — 임베드 폭에서 원본 860 px 이 약 0.83 배로 그려진다. 화면 px 로 고정된 것(먼지 점 크기 ·
  선 굵기 · 이름 글자 13 px)은 따라 줄지 않아 원본보다 조금 도드라진다 (G25).
- **왼쪽 먼지 점** — 원본 2 × 2 px 사각형을 넓이가 같은 반지름 1.13 px 원으로 (새 부족 N4).
- **점선 무늬** — 원본 4/4 px, 엔진 고정 6/5 px (G05).
- **적분 걸음** — 원본은 실시간에서도 고정 1/60 걸음을 누적한다. 여기서는 엔진이 주는 dt 를 1/60
  이하로 쪼갠다. 검사 시각 이동(`?t=`)에서는 걸음이 원본과 같아 대조 화면의 입자 배치가 일치한다.
- **흐름 무늬 위상** — 원본은 화면 시각으로 돈다(느린 단계에서도 보통 빠르기). 조각 시계는 느린
  단계에서 느리게 흐르므로 `screenClock` 이 단계별 `timeScale` 로 나눠 화면 시각을 되돌린다 (새 부족 N3).

대조 (`tasks/piece-lab/_report/_scratch/tidal-force/shots/`) — t = 0 · 3 · 4.6 · 6 네 시각 모두 입자
배치 · 늘어난 길이 · 양 끝 벗어난 거리 · 캡션 전환이 원본과 같은 모양이다. `ⓘ 비교 한계` 없음.

## (b) 어휘 부족

### 장부에 있는 것

- **G01** — `step` 이 시간표를 받지 못한다. 흐려지는 단계에서 적분을 멈추고 주기가 넘어갈 때 구름을
  되돌리려고, `step` 이 `schema.timeline.phases` 를 직접 읽어 주기 길이와 멈춤 시각을 다시 계산하고
  자기 시계(`state.clock`)를 센다.
- **G05** — 점선 원의 대시 길이 · 간격을 선언할 수 없다.
- **G08** — 원본의 옅은 푸른 회색(장)에 맞는 색 역할이 없어 `secondary` `subtle` 로 눈대중했다.
- **G09** — 흐려지는 단계에서 움직이는 것 전부를 한꺼번에 흐리는 묶음 불투명도가 없어 인스턴스마다
  `opacity` 를 곱한다(흐름 무늬 획 150여 개 포함).
- **G10** — 판 단위 좌표계가 없다. 같은 입자 상태를 정지틀(0.95 배)과 함께 떨어지는 틀(중심을 빼고
  1.4 배)로 그리는 두 보기 변환을 scene 이 인스턴스마다 좌표로 옮기고, 판 경계는 인스턴스마다 `clip`,
  판 바탕은 `region` `opaque` + `fillOpacity: 0` 으로 깐다.
- **G25** — 화면 px 크기(점 · 굵기 · 글자)가 배율을 따르지 않는다.

### 새 부족

- **N1 연속 음영 (스칼라장 짙기 · 방사형 그라데이션)** — 영향 `근사`.
  천체 중력장 1/r² 를 짙기로 까는 어휘가 없다. 원본 그라데이션(정지점 15, 선형 보간)의 알파를
  목표로, 같은 색 원판 56장을 바깥부터 겹치고 원판마다 알파를 1 − Π(1 − aⱼ) 에서 거꾸로 풀었다.
  화면에서 짙기의 떨어짐은 같게 나오나, 원판 가장자리 안티에일리어싱 이음매가 천체 곁에 아주 옅은
  동심 줄로 남는다. 인스턴스 56개가 하나의 장을 흉내 낸다.
- **N2 벡터장을 흐르는 획으로 그리기** — 영향 `근사`.
  「방향 = 획이 흐르는 쪽, 세기 = 획 길이 · 짙기, 위상 = 시각」 규약을 조각이 격자 칸마다 계산해
  `trace` `tick` 으로 펼친다. `trace` 는 `strength` 하나가 길이와 짙기를 함께 묶어(그리고 알파 하한
  0.05) 원본의 「길이 4 + 12s, 짙기 0.1 + 0.75s」를 한 인스턴스에 담을 수 없어 **획마다 인스턴스**를
  나눴다(최대 약 156개). 모양은 원본과 같다 — 이 조각에서 표현의 대부분이 어휘가 아니라 scene 코드에 있다.
- **N3 화면 시각** — 영향 `근사`. `TimelineFrame` 에 재생 속도를 적용하기 전의 화면 시각이 없다.
  느린 단계에서도 보통 빠르기로 흘러야 하는 장식적 움직임(흐름 무늬 위상)을 위해 조각이 단계별
  `timeScale` 로 역산한다.
- **N4 `particleSystem` 점 모양** — 영향 `근사`. 사각 점을 고를 수 없어 넓이가 같은 원으로 바꿨다.

조각의 물리(입자 170개 반암시적 오일러 적분 · 시드 난수 · 늘어남 판정)는 부족으로 올리지 않았다.

### 근사가 주장을 약하게 했는가

약해지지 않았다. 동사(양쪽으로 늘어난다)는 실제 적분된 입자와 점선 원 · 강조색 변위로 일어나고,
근사는 장의 음영과 흐름 무늬의 **그리는 방식**에만 걸려 있어 화면에서 원본과 같은 모양으로 읽힌다.
