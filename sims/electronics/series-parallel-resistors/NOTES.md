# series-parallel-resistors — 저항의 직렬과 병렬

엔진 위에서 바로 만든 조각이다. 자유 구현 원본이 없다. 자유 렌더 0.

## (a) 답하는 질문과 동사

**질문** — 같은 전지에 같은 저항 둘을 어떻게 잇느냐가 전지가 내주는 전류를 바꾸는가.

**주장** — 같은 두 저항을 한 줄로 이으면 전지가 내주는 전류가 어느 하나보다 줄고, 나란히
이으면 어느 하나보다 는다.

**동사** — 같은 동안 전지를 지난 전하 기둥이 **하나만 일 때의 높이에 못 미치고, 그 높이를 넘는다.**

화면에서 일어나는 방식 —

1. `flow` — 같은 `6 V` 전지와 같은 `3Ω` 저항 둘로 만든 회로 셋이 나란히 선다. 하나만 이은 것,
   한 줄로 이은 것, 두 가지로 나란히 이은 것. 다섯 저항 기호에 모두 `3Ω`, 세 전지에 모두 `6 V` 가
   붙어 있어 **달라진 것이 연결뿐**임이 글자가 아니라 배선으로 보인다. 전자(`e⁻`)가 세 회로를
   돌고, 알갱이 간격은 모든 도선에서 같으며 빠르기가 전류에 비례한다 — 꼬리 길이가 빠르기다.
2. `count` — 아래 도선의 문이 짙어지고, 같은 동안 전지를 지난 전하가 회로마다 아래 기둥으로
   쌓인다. 병렬 기둥이 가장 빨리, 직렬 기둥이 가장 느리게 자란다. **여기가 동사가 일어나는
   자리다** — 세 기둥의 자라는 속도가 곧 세 전류다.
3. `hold` — 기둥이 멈춘다. 하나만 두 칸 · 직렬 한 칸 · 병렬 네 칸. 하나만 기둥의 꼭대기를 지나는
   강조색 점선이 셋을 가로지르고, 직렬은 그 아래, 병렬은 그 위에 있다. 기둥마다 `2 A` · `1 A` ·
   `4 A` 가 붙는다 — 계산값이 아니라 선언한 스테이지 상수다.
4. `fade` — 기둥 · 기준선 · 값이 흐려지고, 전자는 계속 돌며 다음 세기를 기다린다.

기둥 높이도 알갱이 자리도 조각 시계의 닫힌 식이다 — 쌓는 상태가 없고(`step` 은 항등),
같은 시각은 언제나 같은 화면이다. 한 칸의 잣대는 코드에 없다. `columnHeight` 가
`duration('count')` 를 읽어 **`unitCurrent` 가 세는 단계 내내 흐르면 딱 한 칸**이 되게 한다
(S-piece 「시간표는 선언이다」 · 원칙 2). 선언에서 `count` 를 2.4 → 3.2 으로 늘이면 세 기둥이
함께 더 느리게 자랄 뿐 끝 높이의 비는 그대로다(확인 후 되돌림).

## (b) 화면 구성의 결정 — 두지 않은 것 포함

| 결정 | 이유 |
| --- | --- |
| 배치 셋을 **한 화면에 나란히** | 주장이 「어느 하나보다」 라는 견줌이다. 스테이지 탭으로 갈라 두면(구세대 `dc-circuit` 이 그랬다) 독자가 앞 화면을 기억해 견줘야 하고, 견줌이 화면이 아니라 머릿속에서 일어난다 |
| 전지 · 저항 값을 셋 다 똑같이 보임 | 「같은 전지 · 같은 저항」 이 전제다. 값을 한 번만 쓰면 독자가 세 회로가 같은 부품인지 확인할 길이 없다. 다섯 개의 `3Ω` 이 그 확인이다 |
| 전류를 **기둥 높이**로 | 전류 = 단위 시간에 지나는 전하. 같은 동안 센 전하를 쌓으면 비가 높이가 된다. 알갱이 빠르기만으로는 **멈춘 화면**에서 4 : 2 : 1 이 읽히지 않는다 — 꼬리 길이는 알갱이 간격을 넘을 수 없어 비가 눌린다 |
| 기둥을 **칸으로** 쌓고 칸 사이에 틈 | 높이를 눈대중하는 대신 셀 수 있다 — 한 칸 · 두 칸 · 네 칸. 눈금선을 기둥 위에 긋는 것보다 낫다(칠 위의 선은 역할색이 겹쳐 흐려진다) |
| 세 기둥이 **같은 바닥**에서 출발 | 길이를 견주려면 출발점이 같아야 한다. 회로마다 기둥을 그 회로 안에 두면 바닥이 셋으로 갈린다 |
| **강조색은 「하나만 일 때의 높이」 한 뜻에만** | 주장의 기준선이다. 기둥 · 전자는 primary(기둥은 문을 지난 전자 그 자체다), 도선 · 전지 · 저항 · 마디는 먹색, 문 · 바닥 · 이름표는 muted. 직렬 · 병렬을 색으로 가르지 않는다 — 가르는 것은 배선 모양과 이름이다 (S-piece) |
| 기준선은 `hold` 부터 | 세는 동안에는 기준선이 함께 자라 「기준」 이 되지 못한다. 다 센 뒤에 서야 넘고 못 미치는 것이 한눈에 읽힌다 |
| 알갱이 간격은 세 회로에서 같고 **빠르기**가 전류 | 같은 재료 = 같은 운반자 밀도. 촘촘함을 회로마다 바꾸면 밀도 차이인지 흐름 차이인지 갈리지 않는다. 병렬 두 가지는 본선의 절반 빠르기다 — 물리가 그렇고, 그것을 캡션으로 말하지는 않는다(마디 법칙은 `kirchhoffs-current-law` 의 몫) |
| 꼬리 길이 = 빠르기 × `trailSeconds`, 가장 빠른 꼬리가 알갱이 간격을 넘지 않게 | 2차 촬영에서 병렬 본선의 꼬리가 이어져 **빨간 도선**처럼 보였다(ohms-law 가 같은 자리를 밟았다). 간격을 0.46 → 0.7 로 넓히고 꼬리를 0.18 초로 줄여 끊었다 |
| 문(세는 자리)은 **아래 도선**에 세로 막대 | 1차 촬영에서 전지 위 왼쪽 기둥에 가로 막대로 두었더니 **전지 판이 하나 더 있는 것**으로 읽혀 회로가 2 셀 전지처럼 보였다. 아래 도선의 세로 막대는 전지 기호와 섞이지 않는다 |
| 저항은 `circuitElement`, 전지는 `lineSet` 두 판 | 저항 지그재그는 기호가 제 리드선까지 그려 도선에 이어진다. 전지는 리드선과 기호 사이가 비어 회로가 끊겨 보인다(G178) — 이웃 넷이 같은 이유로 손수 그었다 |
| 저항을 **가로 변에만** | `circuitElement` 값 글자가 소자 가운데에서 화면 아래 14 px 고정이라(G199) 세로 소자에서는 지그재그 위에 겹친다. 그래서 병렬의 두 가지도 가로로 눕혔다 |
| `e⁻` 표식 한 번, 화살표와 **따로** | 도선 속을 흐르는 것이 무엇인지 밝힌다(전자는 관례 전류와 반대로 간다). 1차 촬영에서 화살표 이름으로 달았더니 아래 도선 위에 얹혀 잘려, 화살표 아래 `readout` 으로 내렸다 |
| 두지 않은 것 | **합성 저항(1.5Ω · 6Ω)** — 계산값이고, 주장은 기둥 높이가 세야 한다. **전류계** — `scale` dial 이 값 글자를 `toFixed` 로 늘 쓰고(G144) 이 조각의 동사는 쌓임이다. **전압 나눠짐(직렬 각 3 V)** — `kirchhoffs-voltage-law` · `potential-divider` 의 몫. **가지 전류 값(2 A)** — `kirchhoffs-current-law` 의 몫이라 가지에는 수를 두지 않고 빠르기로만 남겼다. **전압을 바꾸는 조작** — `ohms-law` 의 몫. **저항 기호의 길이 · 굵기** — `resistance-and-geometry` 의 몫이라 다섯 기호를 똑같이 두었다. **조작기 · 그리드 · 카메라 단추** — 세 배치가 한 화면에 있어 누를 것이 없고, 잴 것은 거리가 아니라 칸 수다 |
| 캔버스 세로 404 px | 1차 촬영(356)에서 **세로가 먼저 찼다** — 가로 800 px 중 685 px 만 쓰여 그림이 작았다. 세로를 48 px 늘리니 가로를 다 쓴다. 세로는 비싸지만, 남는 가로를 못 쓰는 세로는 더 비싸다 |
| `startAt: 3.2` | 도착한 순간 이미 세는 중이다 — 세 기둥이 서로 다른 빠르기로 자라는 자리에서 연다. 0 이면 빈 기둥 자리가 먼저 보인다. 쌓는 상태가 없어 `preroll` 은 쓰지 않는다 |
| `drawOrder: 'scene'` | 도선은 저항 기호 아래, 꼬리는 도선 위, 알갱이는 꼬리 위, 기둥 칸은 바닥선 위여야 한다. 층 순서로는 `particleSystem` 이 `lineSet` 아래로 밀린다 |

## (c) 어휘 부족

**주장 부족 없음.** 근사한 곳은 모두 모양의 문제이고, 장부에 이미 있는 항목이다.

| 장부 id | 이 조각에서 | 영향 |
| --- | --- | --- |
| G90 | 코어에 회로 기호가 없다 — 전지를 `lineSet` 두 판(긴 판 + · 짧은 판 −)으로 긋는다 | 근사 |
| G178 | `circuitElement` battery 는 리드선과 기호 사이가 비어 회로가 끊겨 보인다 — 쓰지 않았다 | 근사 |
| G199 | `circuitElement` 값 글자가 소자 가운데에서 화면 아래 14 px 고정이다 — 저항을 가로 변에만 둘 수 있어 병렬 두 가지를 세로로 세우지 못했고, 위 가지의 `3Ω` 이 두 가지 사이에 놓인다 | 근사 |
| G186 | `circuitElement` 크기가 월드 길이 2 로 고정이다 — 저항 기호 길이가 세 회로의 가로 폭을 정해, 직렬 회로만 다른 둘보다 2 월드 넓다 | 근사 |
| G89 | 경로를 따라 흐르는 점 묶음이 없다 — 가닥마다 scene 이 호길이로 알갱이 자리를 계산해 `particleSystem` 에 넘긴다 | 근사 |
| G181 | `particleSystem` 꼬리가 곧은 선이라 도선 모서리에서 회로 밖으로 삐졌다(2차 촬영에서 실제로 보였다) — 알갱이마다 호길이 구간을 잘라 `lineSet` 으로 길을 따라 긋는다 | 근사 |
| G84 | 월드에 놓이는 막대 묶음이 없다 — 기둥의 칸마다 `region` 사각형을 손으로 배치한다(`graph` bar 는 화면 카드이고 막대마다 `toFixed(1)` 을 쓴다) | 근사 |
| G105 | 회로 셋(왼쪽 기둥 x · 가로 폭 · 저항 자리)의 목록을 스테이지 상수로 선언할 수 없다 — `schema.ts` 의 `CELL_X` · `CELL_W` 코드 표. 배치마다의 물리량은 `currentSingle` · `currentSeries` · `currentParallel` · `currentBranch` 로 흩었다 | 근사 |
| G143 | 상수 사이 관계를 선언할 자리가 없다 — `currentSingle = voltage/resistance` · `currentSeries = voltage/2resistance` · `currentParallel = 2voltage/resistance` · `currentBranch = currentParallel/2` 가 선언에 네 번 따로 적힌다. 저작자가 `resistance` 만 바꾸면 경고 없이 기둥이 회로와 어긋난다 | 근사 |
| G24 | 캡션 슬롯이 프레이밍 여백으로 잡히지 않아 `SCENE_BOUNDS.minY` 에 캡션 띠를 손으로 더했다 | 근사 |
| G10 | 판(회로 · 기둥) 단위 좌표계가 없다 — 같은 그림을 세 번 놓는 것이라 회로마다 `x0` 을 모든 인스턴스에 손으로 더한다 | 근사 |

새 부족은 나오지 않았다. 남은 것들(전류 → 빠르기 배율, 호길이 격자, 저항 몸통 구간 비우기,
칸 나누기)은 조각의 물리 · 배치 계산이라 부족이 아니다.

## (d) 주장이 화면에서 서는가

`pnpm -s piece:report --sims=http://localhost:5173/aperi21/` 로 찍은 라이트 · 다크 촬영본을
probeTimes 마다 직접 열어 확인했다 (2026-09-23).

| t(초) | 라이트 · 다크 |
| --- | --- |
| 0.3 | 세 회로가 나란하고 문이 짙다. 기둥이 자라는 중 — 병렬이 이미 두 칸 언저리, 하나만은 한 칸, 직렬은 반 칸. 자라는 속도 차이가 보인다 |
| 1.6 | 세기가 거의 끝났다. 하나만 두 칸 · 직렬 한 칸 · 병렬 네 칸이 거의 다 찼고, 병렬 기둥이 하나만 기둥보다 눈에 띄게 높다 |
| 3.0 | 기둥이 멈추고 강조색 점선 기준선이 셋을 가로지른다. 직렬은 선 아래, 병렬은 선 위. `2 A` · `1 A` · `4 A` 칩이 붙는다. 캡션과 화면이 같은 말을 한다 |
| 4.6 | 같은 견줌이 그대로. 다섯 `3Ω` 과 세 `6 V` 가 모두 보여 달라진 것이 연결뿐임이 읽힌다 |
| 7.0 | 다음 주기. 기둥이 비고 전자만 돈다 — 병렬 본선의 알갱이 꼬리가 가장 길고 직렬이 가장 짧다 |

- **다크** — 도선 · 전지 · 저항이 밝은 선(`ink` 가 뒤집힌다), 기둥과 전자는 붉은 primary, 기준선은
  금빛. 기둥 칸 사이 틈이 어두운 선으로 남아 칸이 여전히 세어진다. 글자 겹침 · 화면 밖으로 나감 없음.
- **라이트** — 칸 사이 틈이 바탕색으로 남는다. `6 V` 칩이 전지 판에 닿아 있어 띄움을 0.56 → 0.72 월드로 늘렸다.
- **고친 것 셋** — (1) 문이 전지 판처럼 읽혀 아래 도선으로 옮겼다 (2) `e⁻` 이름이 도선 위에 얹혀 잘려
  `readout` 으로 내렸다 (3) 병렬 본선의 꼬리가 이어져 빨간 도선처럼 보여 간격을 넓히고 꼬리를 줄였다.
- **약한 곳** — `flow` 단계(주기의 2.6/9.2)에는 기둥이 비어 화면 아래가 빈다. 멈춘 화면에서 세 전류를
  가르는 것은 꼬리 길이뿐이라, 이 단계만 보면 주장이 약하다. 도착 시각(`startAt` 3.2)을 세는 중으로
  잡아 독자가 자라는 기둥을 먼저 보게 했다.
