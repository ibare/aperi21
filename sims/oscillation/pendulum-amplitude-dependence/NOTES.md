# 진자의 등시성 — sim 노트

원본: `tasks/piece-lab/pendulum-amplitude-dependence/` (자유 구현). 원본의 결정과 근거는 그쪽 `NOTES.md`.
이 파일은 sim 으로 옮긴 뒤 **달라진 것**과 **어휘 부족**을 적는다.

## 쓴 어휘

| 원본의 묶음 | 어휘 |
|---|---|
| 최하점 기준선 | `trajectory` (`lineStyle: 'dashed'` · `width` · `opacity`) |
| 속도 잔상 | `trajectory` (`fade: 'tail'` · `opacity`) |
| 진자 다발 — 실 다섯 | `constraint` (`subtype: 'string'`, `to` 에 추의 id) |
| 진자 다발 — 추 다섯 · 피벗 | `body` (`circle` · `glow: false`) |
| 바닥 통과 섬광 | `trace` (`shape: 'ring'` · `spreadTo` · `life`) |
| 박자 기록띠 | `trace` (`shape: 'tick'` · `size` · `width`) |

## 원본과 달라진 것

1. **잔상의 굵기가 한 값이다.** 원본은 최신 구간일수록 굵어지고(1→6.5 px) 짙어진다(0→0.30).
   농도는 `fade: 'tail'` × `opacity: 0.3` 으로 그대로 나오지만 `trajectory.width` 는 선 하나에
   하나뿐이라 중간값 4 px 로 고정했다. 속력을 읽는 두 눈금(길이 · 굵기) 중 굵기가 빠지고
   길이와 농도만 남았다.

2. **캡션에서 수가 빠졌다.** 원본은 "진폭이 20.0°에서 4.0°까지 …", "… 0.06초 뒤처졌다" 처럼
   값을 문장에 끼웠다. `CaptionSlotDef` 에는 `vars` 가 없어(`Readout` 에는 있다) 값을 넣을 수
   없다. 진폭 다섯은 이름표가 화면에서 이미 말하고 있어 문장에서 뺐고, 지연의 크기는 띠의
   세로줄이 기우는 정도가 말한다.

3. **슬라이더 값이 `20.00 °` 로 찍힌다.** 원본은 1° 눈금에 `20°` 였다. 조각은 잡고 있는 동안
   값을 정수로 스냅하지만(`physics.step`), 조작기가 값을 찍는 형식은 선언이 정하지 못한다.

4. **점선 무늬가 다르다.** 원본은 `setLineDash([3, 4])`, 어휘는 `[6, 5]` 고정이다.

5. **추에 1 px 윤곽선이 생겼다.** `body` 렌더러가 원을 채운 뒤 `theme.line` 으로 한 번 두른다.
   원본은 채움만 했다. 후광은 `glow: false` 로 껐다.

6. **색이 테마 토큰이다.** 원본의 `#fbfaf8` · `#22252b` · `#e8590c` 대신 배경 · `ink` · `accent`
   로 말한다 (C2). 실의 농도는 맞췄다 — `constraint` 렌더러가 0.55 를 곱하므로 `opacity: 0.55`
   를 주면 원본의 0.30 이 된다. 굵기(1 px)와 그 계수 자체는 렌더러 상수다.

7. **`startAt` 은 쓰지 않았다.** 이 조각의 "도착한 순간 이미 진행 중" 은 전부 `preroll` 이다 —
   띠 · 잔상 · 통과 시각이 누적 상태라 시계만 앞당기면 화면이 빈다. 원본의 512 스텝이
   `preroll: 512/60` 으로 그대로 옮겨졌다.

8. **잔상을 프레임 수가 아니라 시간으로 자른다.** 원본은 최근 13 프레임을 들었다. 러너의 dt 는
   실시간이라 흔들리므로, 같은 13 프레임이 조각마다 다른 시간이 된다. 잔상 길이가 곧 속력이라는
   읽기를 지키려면 시간이어야 해서 `TRAIL_SPAN = 12/60` 초로 잡았다. 고정 걸음(프리롤 · 검사
   시각 이동)에서는 원본과 정확히 같은 13 점이다.

## 확인한 것

카탈로그에 이 조각의 주제가 없어 **대조 스크린샷을 만들지 못했다**(아래 「막힌 것」). 대신 러너와
같은 순서(`preroll` 512 스텝 → 검사 시각까지 1/60 걸음)로 상태를 굴려 `scene` 선언을 직접 읽고,
원본 `NOTES.md` 가 적어 둔 수와 대 봤다.

| 잰 것 | 결과 | 원본 |
|---|---|---|
| 프리롤 뒤 조각 시계 | 8.533 초 | 512 × 1/60 = 8.533 초 |
| 지연 t=0 | 0.0554 초 | "t=0 에 이미 0.055초" |
| 지연 t=7.2 | 0.1145 초 | "t=7.2 에 0.115초" |
| 추 다섯의 최대 거리 t=0 · 1 · 7.2 | 13 · 16 · 12 px | 추 지름이 13 px 다 — 포개진다 |
| 추 다섯의 최대 거리 t=0.5 | 56 px | "가장 큰 것은 75px 밖, 가장 작은 것은 15px 밖" |
| 띠의 최신 세로줄 폭 t=4 · 7.2 | 0.085 · 0.115 초 | 그때의 지연과 같다 — 기우는 정도가 곧 누적 위상차 |
| 캡션 (다섯 시각 모두) | `caption.same` | 전환은 t≈11.2 초, "t=7.2 캡션은 아직 '같은 순간'을 말한다" |
| 진폭 이름표 | 20.0 · 16.0 · 12.0 · 8.0 · 4.0 | 같다 |

지연 두 값이 원본이 적어 둔 수와 자릿수까지 같으므로, 적분기(velocity Verlet) · 소진폭 근사를
쓰지 않은 것 · 영점 교차 보간 · 프리롤 길이가 모두 그대로 옮겨졌다.

### 막힌 것 — 대조 스크린샷

`apps/catalog` 의 카탈로그 데이터에 **id 가 `pendulum-amplitude-dependence` 인 주제가 없다.**
`scripts/piece-report.mts` 의 `simIdOf` 는 조각 id 와 같은 id 의 주제에서 `simId` 를 찾으므로
`--sims` 를 줘도 sims 쪽 화면을 한 장도 찍지 못한다(원본 쪽 5장만 나온다). `catalog:gen` 과
`catalog.json` 편집은 이 작업의 금지 목록이라 손대지 않았다.

가장 가까운 주제는 `pendulum-amplitude-dependence`("진폭과 주기 — 큰 진폭에서 깨지는 등시성")
이고 아직 `simId` 가 없다. 로더(`aperi21:pendulum-amplitude-dependence`)와 능력 목록은 이미 있으므로,
주제에 `simId` 만 붙으면 그대로 열린다.

## 어휘 부족

1. **굵기가 변하는 궤적.** `trajectory` 는 선 하나에 굵기 하나다. 속도를 굵기로 읽히게 하는
   잔상은 이 조각만의 요구가 아니다 — 원본 `engine-fit.json` 도 같은 자리를 「수정 필요」로 적었다.

2. **캡션에 값을 끼우는 자리.** `CaptionSlotDef` 에 `vars` 가 없다. `Readout` 에는 있으므로 같은
   모양이면 된다. 없으면 "지금 화면에서 실제로 벌어지는 일" 을 말하는 캡션이 수를 말하지 못한다.

3. **`trace` 의 `tick` 크기 단위가 선언과 구현에서 어긋난다.** 주석은 `size` 를 화면 px 라 적었고
   `dot` · `ring` 은 실제로 px 인데, `tick` 만 월드로 읽는다(`pos + dir × half` 를 `toScreen` 한다).
   이 조각은 10 px 짜리 획을 월드 `10/208` 로 줘서 맞췄다 — 배율이 달라지면 획 길이가 따라 변한다.
   둘 중 하나로 정해야 한다.

4. **슬라이더의 눈금과 자릿수.** `ControllerKind` 의 `slider` 에 `step` 도 자릿수도 없다. 정수
   눈금은 조각이 `physics` 에서 스냅해 흉내 냈지만, 화면에 찍히는 `20.00` 은 고치지 못한다.
   유효숫자를 조각이 정한다는 규범(S-piece)이 조작기에는 아직 닿지 않는다.

5. **점선 무늬.** `lineStyle` 은 이름만 고르고 간격은 렌더러 상수다.

6. **`body` 의 윤곽선을 끌 수 없다.** `glow` 는 껐지만 채운 뒤의 `stroke` 는 늘 그린다.
